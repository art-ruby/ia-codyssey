# AI Strategist 경계 — 무엇을 AI 에게 맡기고 무엇을 맡기지 않는가

2026-09-03

이 문서의 목적은 «AI 비서를 어떻게 만들까» 가 아니라 **«AI 가 손대면 안 되는 곳을
먼저 못 박는 것»** 이다. 순서가 반대면 시스템이 그럴듯한 거짓말을 하게 된다.

---

## 0. 전제

Radar 는 이미 «숫자가 나온다는 이유로 결과를 믿지 않는다» 를 설계 원칙으로 삼고 있다
(REPORT.md §4, prd §10). LLM 을 붙이는 순간 이 원칙이 가장 먼저 깨진다.
**LLM 은 언제나 답을 만들어 낸다. 모른다고 말하는 것이 기본값이 아니다.**

그래서 다음 한 줄이 이 문서 전체의 요약이다.

> **숫자는 코드가 만들고, 문장은 AI 가 만들고, 결론은 사람이 낸다.**

---

## 1. 분류 기준

| 구분 | 뜻 | 판정 방법 |
|---|---|---|
| **A. Deterministic Code** | Python/pandas 로 계산 | 같은 입력 → 항상 같은 출력이어야 하는가? |
| **B. Rule Engine** | 명시적 임계값·조건문 | 사람이 규칙을 읽고 «왜 그렇게 나왔는지» 설명할 수 있어야 하는가? |
| **C. LLM** | 언어 해석·비교·설명·각도 | 정답이 하나가 아니고, 틀려도 되돌릴 수 있는가? |
| **D. Human** | 사람 최종 판단 | 틀리면 되돌릴 수 없거나, 남에게 손해를 끼치는가? |
| **E. Hybrid** | 위의 조합 | |

## 2. 기능별 분류

### 2.1 절대 A (코드) — LLM 이 손대면 안 되는 것

| 기능 | 근거 |
|---|---|
| ADViews · Age Bucket 백분위 | 모집단 통계다. LLM 이 «대충 상위권» 이라고 말하면 그 순간 검증이 불가능해진다 |
| Video Score · Channel Score | 가중치가 문서로 고정돼 있다(W_AGE_ADJUSTED 0.6 등). 재계산 금지 |
| Subscriber View Ratio · 분모 하한 1,000 | 규칙이 데이터로 뒷받침돼 있다 (config.py 주석의 실측) |
| 참여율(매크) 방어 1.5/1k | 위와 같음 |
| Daily View Gain · MIN_GAIN_HOURS=6 | 나눗셈 함정 방어. 판단이 아니라 산수 |
| API quota 계산 | 틀리면 하루가 날아간다 |
| 검색어별 성과 순위·공급량 | 집계 |
| 게시 후 성과 수집(24h/72h/7d) | 관측이다. 해석과 반드시 분리 |
| 중복 소재 «후보» 찾기 (video_id·seed·키워드 일치) | 1차는 문자열·id 대조로 충분하고 그 편이 재현 가능하다 |

> **규칙:** AI Strategist 에게 넘기는 모든 숫자는 **이미 계산된 값**이어야 한다.
> Strategist 는 숫자를 «읽는» 역할이지 «내는» 역할이 아니다.

### 2.2 B (규칙 엔진) — 먼저 규칙, LLM 은 그 다음

| 기능 | 규칙 예 | 왜 규칙인가 |
|---|---|---|
| **1차 MAKE/WATCH/SKIP 선별** | Video Score ≥ 임계 & 구독대비 ≥ 5배 & 매크 아님 & 나이 ≤ N일 → 후보 | 대부분은 규칙만으로 걸러진다. LLM 을 777건에 돌릴 이유가 없다 |
| Channel Fit 대상 선정 | Video Score 상위 20 (`CHANNEL_FIT_TOP_N`) | 이미 그렇게 되어 있다 |
| 데이터 부족 판정 | 스냅샷 < 2회 → Gain «못 잼», 버킷 n < 20 → method=median_ratio | 이미 그렇게 되어 있다. **이 상태에서는 LLM 이 «상승 중» 이라고 말하지 못하게 막아야 한다** |
| Fact Check Required 플래그 | 대본/브리프에 금액·연금·세금·상속·보험·부동산 제도 낱말 → 무조건 true | 정규식으로 충분하고, 그래야 놓치지 않는다 |
| 크로스오버 후보 | 두 채널 모두 channel_relevance=HIGH | 이미 `is_crossover` |
| 성과 판정 등급 | 우리 채널 중앙값 대비 배수 구간 | 사례가 30건 쌓이기 전에는 통계가 아니라 규칙 |

### 2.3 C (LLM) — 언어를 다루는 일만

| 기능 | 입력 | 출력 | 지금 상태 |
|---|---|---|---|
| 제목 한국어 번역 | 일본어 제목 | 한국어 한 줄 | ✅ `translate.translate_titles` |
| **Channel Fit 판정** | 채널 프로필 + 영상 메타 + 자막 요약 | HIGH/MED/LOW 7항목 + 근거 문장 + angle | ✅ `channel_fit.judge` — **점수를 만들지 않는 설계가 옳다** |
| **댓글 → 시청자 목소리** | 좋아요 상위 30개 댓글 | concerns/questions/fears/objections/phrases/gaps | ✅ `comments.analyze` |
| **Angle 설계** | 브리프 + 채널 프로필 | «이 채널이라면 이렇게 잡는다» | ✅ 부분 |
| **오늘의 브리핑** | 이미 계산된 상위 후보 표 | «오늘 무엇을 보아야 하는가» 3~5줄 | **NEW** |
| **왜 이 소재인가 / 반대 근거** | Evidence 목록 | 찬성 2~3줄 + **반대 2~3줄** | **NEW** |
| **예측 vs 실제 해설** | 예측값과 실측값 | «왜 빗나갔는가» 가설 | **NEW(4차)** |
| 자연어 질의 | 질문 + 조회된 데이터 | 답변 + 근거 링크 | **NEW** |
| 대본·제목·썸네일 문구 집필 | 브리프 | 일본어 원고 | ✅ AutoMaker |

### 2.4 D (사람) — AI 에게 절대 맡기지 않는 것

| 기능 | 왜 |
|---|---|
| **최종 MAKE 결정** | AI 는 추천만 한다. 승인은 사람이 누른다 |
| **세무·연금·법률·의료·상속 사실 확정** | 시청자가 50~69세이고 다루는 것이 자기 돈과 집이다. 틀린 제도 설명은 조회수 문제가 아니라 **사람에게 손해를 끼친다** (automaker-contract.md 가 이미 그렇게 적고 있다) |
| **업로드** | 되돌릴 수 없다. 자동 업로드는 만들지 않는다 |
| **최종 대본 승인** | |
| 채널 정체성 변경 | profile_version 이 올라가면 과거 판정이 전부 무효가 된다 |
| 검색어 추가·제거 | 이미 «프로그램은 후보만 낸다» 원칙 (prd F-4) |
| API 키·비용 한도 변경 | |
| 두 채널에 같은 구성을 올릴지 | 계약서 §68 금지 사항 |

### 2.5 E (Hybrid) — 조합

| 기능 | 구성 |
|---|---|
| MAKE/WATCH/SKIP | **B**(규칙 선별) → **C**(근거·반대 근거·confidence) → **D**(승인) |
| Production Brief | **A**(숫자) + **C**(각도·해석) + **B**(fact-check 플래그) + **D**(확정) |
| 중복 소재 방지 | **A**(id·키워드 일치 후보) → **C**(«실질적으로 같은 이야기인가» 판단) → **D** |
| 성과 리뷰 | **A**(실측) + **B**(등급) + **C**(가설) + **D**(무엇을 이어갈지) |

## 3. Hallucination 방지 구조

### 3.1 원칙 8개 → 구현 방법

| # | 원칙 | 구현 |
|---|---|---|
| 1 | 숫자는 원본 또는 결정적 분석에서만 온다 | LLM 프롬프트에 **이미 포맷된 숫자 문자열**만 넣는다. 원자료(raw CSV)를 통째로 주지 않는다 |
| 2 | AI 가 숫자의 출처를 확인할 수 있어야 한다 | 모든 수치에 `source` 표기: `videos.csv#video_id` / `video_snapshots.csv@2026-09-02` / `analysis.build()` |
| 3 | 답변에 Evidence 를 연결한다 | `AIRecommendation.evidence_refs[]` — 근거가 없는 문장은 화면에서 «근거 없음» 배지 |
| 4 | 정보가 없으면 «데이터 없음» | 프롬프트에 결측을 **`(측정 안 됨)`** 으로 명시해 넣는다. `0` 으로 채우지 않는다 — Radar 가 이미 CSV 단에서 하고 있는 것을 프롬프트 단까지 연장 |
| 5 | LOW confidence 를 허용 | confidence 는 필수 필드. `LOW` 가 나와도 화면이 그대로 보여준다. **LOW 를 숨기면 시스템이 늘 자신 있어 보인다** |
| 6 | Fact Check Required 상태 지원 | 규칙 엔진이 플래그를 세우고, **플래그가 서 있는 한 «업로드 준비 완료» 상태로 못 넘어간다** |
| 7 | 고위험 정보는 트렌드 신호와 사실 확인을 분리 | Radar 는 «이 주제에 수요가 있다» 만 말한다. «제도가 이렇다» 는 말하지 않는다. 두 문장을 화면에서 시각적으로도 분리 |
| 8 | 원본 영상에 없는 사실을 만들지 않는다 | 자막 digest 는 인용 블록으로 명확히 구분하고, LLM 출력에 «원본 인용» 필드를 따로 두어 digest 안 문자열과 대조 가능하게 한다 |

### 3.2 구조적 방어 3가지

**① 숫자 통로를 하나로 좁힌다**

```
analysis.build()  →  freeze()  →  DecisionSnapshot(JSON)  →  프롬프트
                                        ↑
                     여기에 없는 숫자는 프롬프트에 들어갈 수 없다
```

프롬프트 조립 함수는 `DecisionSnapshot` 외의 인자를 받지 않게 만든다.
이 한 가지가 대부분의 숫자 환각을 구조적으로 막는다.

**② 출력 스키마를 강제하고, 핵심 필드가 비면 저장하지 않는다**

`channel_fit.judge()` 가 이미 이렇게 하고 있다 —
`channel_relevance` 가 비면 «빈 판정을 캐시하면 다시 물어보지도 않게 된다» 며
저장을 거부한다. **이 패턴을 Strategist 전체에 적용한다.**

**③ «모른다» 를 값으로 만든다**

```json
{ "decision": "WATCH", "confidence": "LOW",
  "why_low": ["스냅샷 1회 — 증가량 측정 불가", "구독자 비공개 — 구독대비 계산 불가"] }
```

`why_low` 가 비어 있는 LOW 는 허용하지 않는다. **«왜 모르는지» 를 못 대면
그것은 모르는 것이 아니라 안 본 것이다.**

## 4. AI 비서가 하지 말아야 할 것 (가설 검증 결과)

원 지시서의 A~I 후보를 실제 코드에 비추어 다시 분류했다.

| 후보 | 판정 | 이유 |
|---|---|---|
| A. Radar 결과 해석 | **채택** | 지금 사람이 표를 읽는 데 쓰는 시간이 가장 크다 |
| B. MAKE/WATCH/SKIP | **채택 (Hybrid)** | 가장 큰 공백. 단 규칙이 1차, LLM 이 2차 |
| C. Confidence | **채택** | 단 «반대 근거» 필드를 필수로 |
| D. Channel Fit 해석 | **이미 있음 → 이동만** | 새로 만들지 말 것 |
| E. Angle 설계 | **이미 있음(부분) → 강화** | |
| F. 중복 콘텐츠 방지 | **구조만 채택, 기능은 보류** | 제작 이력이 **0건**이다. 지금 만들면 항상 «없음» 만 답하는 기능이 된다 |
| G. Production Brief 보강 | **채택** | 단 **새 LLM 호출을 추가하지 말 것** — `production_brief.py` 는 «조립만 한다» 는 원칙을 지키고 있다 |
| H. 제작 후 성과 평가 | **보류(4차)** | 성과 데이터가 0이다. 데이터 없이 만들면 빈 화면이다 |
| I. 자연어 질의 | **채택(제한적)** | **ChatGPT 형 자유 채팅창으로 만들지 말 것.** 미리 정의된 질문 6~8개 + 자유 입력. 자유 채팅은 근거 연결이 끊기고 환각이 가장 쉽게 들어온다 |

**즉, 9개 중 새로 만들 것은 사실상 3개(A·B·C)이고, 2개(D·E)는 이동이며,
3개(F·H·I 확장)는 데이터가 쌓이기 전에는 만들면 안 된다.**

## 5. AI 비서가 필요 없는 곳

솔직하게 말한다.

- **수집·스냅샷·점수 계산** — AI 를 붙일 자리가 없다. 붙이면 나빠지기만 한다.
- **검색어 후보 제안** — 이미 `translate.suggest_search_terms` 가 있고, 사람이 승인한다.
  여기에 «AI 비서» 를 덧붙이는 것은 껍데기만 하나 더 만드는 일이다.
- **제작 단계 전반(TTS·이미지·렌더)** — 이미 자동이고 판단이 필요 없다.
- **위키 학습** — 성과 데이터 없이 «좋은 패턴» 을 학습한다는 말은 성립하지 않는다.
  지금 위키는 **외부 자료를 요약해 저장하는 기능**일 뿐이며, 그것을 «학습» 이라
  부르면 스스로를 속이게 된다.
