# 06_model_comparison_plan_v1.md

## 1. 문서 목적
이 문서는 **AI 테크 뉴스 블로그 자동화 프로젝트에서 사용할 생성형 AI 모델 비교 실험 기준 문서**이다.  
동일한 입력과 프롬프트 조건에서 여러 모델의 결과를 비교하여, 실제 운영에 적합한 모델 또는 조합 전략을 결정하는 것을 목표로 한다.

이 문서의 목적은 다음과 같다.

- GPT / Claude / Gemini 등 후보 모델의 출력 품질을 비교한다.
- 뉴스 정리, 블로그 본문 생성, HTML 변환 등 단계별 적합성을 평가한다.
- 단순 인상 평가가 아니라 재현 가능한 비교 기준을 만든다.
- 최종적으로 운영용 모델 선택 또는 단계별 혼합 전략 수립에 활용한다.

## 2. 비교 대상 범위

현재 비교 대상은 아래와 같다.

### 2.1 기본 비교 대상
- OpenAI GPT 계열
- Anthropic Claude 계열
- Google Gemini 계열

### 2.2 비교 단위
비교는 아래 두 수준으로 수행한다.

1. **모델 단위 비교**
   - 같은 작업을 서로 다른 모델에 수행
2. **단계 단위 비교**
   - 뉴스 정리에는 어떤 모델이 강한지
   - 본문 생성에는 어떤 모델이 강한지
   - HTML 변환에는 어떤 모델이 안정적인지 평가

### 2.3 제외 범위
현재 버전에서는 아래 항목은 우선 제외한다.

- 이미지 생성 모델 비교
- 음성/영상 생성 모델 비교
- 외부 검색 성능 자체 비교
- API 응답 속도의 정밀 벤치마크

## 3. 비교 목표

모델 비교의 핵심 질문은 다음과 같다.

1. 어떤 모델이 **가장 읽기 쉬운 블로그 초안**을 만드는가?
2. 어떤 모델이 **입력 사실을 가장 안정적으로 유지**하는가?
3. 어떤 모델이 **구조화된 출력(JSON/HTML)** 을 가장 잘 지키는가?
4. 어떤 모델이 **비교형 콘텐츠**를 가장 자연스럽게 정리하는가?
5. 운영 기준에서 어떤 모델이 **비용 대비 효율**이 좋은가?

---

## 4. 비교 원칙

### 4.1 동일 입력 원칙
같은 실험에서는 모든 모델에 동일한 입력 데이터와 동일한 프롬프트를 사용한다.

### 4.2 동일 출력 요구 원칙
출력 형식(JSON, Markdown, HTML 등)은 모델마다 다르게 요청하지 않는다.

### 4.3 단계별 비교 원칙
전체 결과만 보지 않고, 작업 단위별로 나누어 비교한다.

### 4.4 정성 + 정량 병행 원칙
문장 품질은 정성 평가하고, 형식 준수나 길이 제한 등은 정량 평가한다.

### 4.5 운영 적합성 원칙
단순히 “잘 쓴다”보다 실제 자동화 파이프라인에서 안정적으로 쓸 수 있는지를 중요하게 본다.

## 5. 비교 시나리오

모델 비교는 아래 3가지 시나리오로 진행한다.

### 5.1 시나리오 A: 뉴스 정리 성능 비교
목적:
- 기사 후보를 구조화하고 핵심을 정리하는 능력 평가

대상 단계:
- 뉴스 수집 정리
- 뉴스 정규화
- 핵심 뉴스 선별

### 5.2 시나리오 B: 블로그 작성 성능 비교
목적:
- 같은 입력으로 더 읽기 쉽고 설득력 있는 블로그 본문을 만드는지 평가

대상 단계:
- 제목 생성
- 메타 설명 생성
- 3줄 요약 생성
- 본문 생성
- 비교 표 생성

### 5.3 시나리오 C: 출력 포맷 안정성 비교
목적:
- 구조화 출력과 HTML 변환 안정성을 평가

대상 단계:
- JSON 출력
- Markdown 출력
- HTML 출력

## 6. 비교 평가 항목

각 모델은 아래 평가 항목으로 점검한다.

### 6.1 사실성
- 입력 기사에 없는 내용을 임의로 추가하지 않는가
- 기사 핵심을 왜곡하지 않는가
- 비교 문장이 근거 없이 확장되지 않는가

### 6.2 관련성
- 검색 주제와 직접 관련된 내용만 유지하는가
- 불필요한 배경 설명이 과도하지 않은가

### 6.3 구조성
- 요청한 문서 구조를 잘 지키는가
- 도입/본론/결론이 분명한가
- 비교 축이 일관적인가

### 6.4 가독성
- 일반 독자와 직장인이 쉽게 읽을 수 있는가
- 문장이 과하게 길거나 복잡하지 않은가
- 단락 흐름이 자연스러운가

### 6.5 해설력
- 단순 요약을 넘어서 “왜 중요한가”를 설명하는가
- 비교 포인트가 이해 가능한 언어로 제시되는가

### 6.6 형식 준수
- JSON, Markdown, HTML 등 지정 형식을 잘 지키는가
- 불필요한 설명 문장을 덧붙이지 않는가
- 코드블록, 태그, 표 구조가 깨지지 않는가

### 6.7 안정성
- 같은 프롬프트에서 결과 편차가 과도하지 않은가
- 재실행 시 최소한의 일관성이 있는가

### 6.8 운영 효율성
- 응답 길이가 과도하지 않은가
- 후처리 부담이 적은가
- 비용 대비 품질이 적절한가

## 7. 평가 방식

평가는 **정량 평가 + 정성 코멘트**를 함께 사용한다.

### 7.1 정량 평가
각 항목을 1~5점으로 평가한다.

| 점수 | 의미 |
|------|------|
| 1점 | 매우 부족 |
| 2점 | 부족 |
| 3점 | 보통 |
| 4점 | 우수 |
| 5점 | 매우 우수 |

### 7.2 정성 평가
각 결과에 대해 아래 내용을 함께 기록한다.

- 잘한 점
- 부족한 점
- 수정 필요 포인트
- 운영 투입 가능 여부

## 9. 실험 입력 데이터 설계

모델 비교는 입력 데이터 품질에 크게 영향을 받으므로, 테스트용 입력 세트를 별도로 관리한다.

### 9.1 입력 세트 구성 원칙
1. 같은 날짜 기준의 뉴스 묶음을 사용한다.
2. OpenAI와 Google이 모두 포함된 주제를 우선 사용한다.
3. 비교 가능한 사건 묶음을 만든다.
4. 입력 규모는 너무 크지도 작지도 않게 유지한다.

### 9.2 권장 테스트 세트 수
- 최소 3세트
- 권장 5세트 이상

### 9.3 테스트 세트 예시
- 세트 A: OpenAI 신제품 발표 vs Google 대응 전략
- 세트 B: 모델 성능 경쟁 관련 뉴스
- 세트 C: 기업 협업/투자/생태계 확장 뉴스
- 세트 D: 검색·에이전트·멀티모달 기능 경쟁 뉴스
- 세트 E: AI 서비스 상용화 및 기업 도입 사례

## 14. 승자 선정 방식

모델 비교는 “무조건 1등 모델 1개”를 뽑는 방식보다, 단계별 최적 모델을 찾는 방식을 우선한다.

### 14.1 단일 모델 운영 시
아래 조건을 가장 고르게 만족하는 모델을 선택한다.

- 본문 품질
- 형식 준수
- 운영 안정성
- 비용 효율

### 14.2 혼합 운영 시
예시:
- 뉴스 정리: Claude
- 본문 생성: GPT
- HTML 변환: GPT 또는 Gemini

이처럼 단계별 강점을 조합할 수 있다.

### 14.3 동점 처리
동점일 경우 아래 우선순위로 판단한다.

1. 사실성
2. 형식 준수
3. 가독성
4. 운영 효율성

## 15. 주의사항

### 15.1 한 번의 결과로 결론 내리지 않는다
단일 테스트 결과는 우연일 수 있으므로 최소 3회 이상 반복한다.

### 15.2 문체 취향과 품질을 구분한다
“내 취향에 맞는 문체”와 “운영에 적합한 품질”은 다를 수 있다.

### 15.3 길다고 좋은 것이 아니다
응답이 길어도 핵심성이 떨어지면 높은 평가를 주지 않는다.

### 15.4 HTML은 화려함보다 안정성이 중요하다
복잡한 구조보다 티스토리에서 깨지지 않는 결과를 우선한다.

### 15.5 비용을 무시하지 않는다
품질이 약간 높더라도 비용 차이가 크면 운영 선택은 달라질 수 있다.

## 16. 현재 프로젝트에 권장하는 1차 비교 범위

현재 단계에서는 모든 것을 한꺼번에 비교하기보다 아래 4개 작업부터 시작하는 것을 권장한다.

1. 뉴스 정규화
2. 핵심 뉴스 선별
3. 블로그 본문 생성
4. HTML 변환

이 4개만 비교해도 실제 운영 모델 선택에 필요한 핵심 판단이 가능하다.

## 17. 후속 확장 포인트

향후 아래 항목으로 비교 체계를 확장할 수 있다.

### 17.1 자동 점수화
- 형식 준수 자동 검사
- 길이 제한 자동 검사
