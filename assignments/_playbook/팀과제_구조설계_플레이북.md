> 2026-08-19 작성 · 출처: 팀미션 2-1 [Project A] `ai-brand-generator` 구조 분석
> 대상: 다음 과제(코디세이 올인원 과정) 착수 시 참고

---

## 0. 전략 — 왜 이 역할을 노려야 하는가

**구조 설계는 코딩 실력과 별개의 축이다.**

지난 과제에서 구조를 설계한 사람의 능력은 두 가지로 나뉜다.

| 능력 | 필요 조건 | 내가 지금 할 수 있나 |
|---|---|---|
| 2,000줄 코드 구현 | 높은 프로그래밍 숙련도 | ❌ 아직 아님 |
| 역할·파일·일정 분할 설계 | 판단력 + 체크리스트 | ✅ **가능** |

두 번째는 **착수 24시간 안에, 코드 한 줄 없이** 할 수 있다.
그리고 팀에서 아무도 안 하는 일이라, 먼저 하는 사람이 가져간다.

**목표: 다음 과제에서 "구조 설계·조율" 역할을 선점한다.**

---

## 1. D-Day 체크리스트 (착수 24시간 안)

과제 발표 직후, 아래 순서로 진행한다. 코딩 능력 불필요.

- [ ] **1) 결과물 목록 뽑기** — 과제 명세에서 "제출해야 하는 것" 전부 나열
- [ ] **2) 파일 소유권 표 그리기** — §2 템플릿 사용 (⭐가장 중요)
- [ ] **3) 빈 템플릿 파일 만들어 올리기** — §3 템플릿 사용 (⭐가장 효과 큼)
- [ ] **4) 의존 체인 그리기** — §4 템플릿 사용
- [ ] **5) 커밋 컨벤션 합의** — §5
- [ ] **6) 팀 채널에 공유** — "이렇게 나누면 어떨까요?" 로 제안

6번까지 하면 사실상 구조 설계자 역할이 확정된다.

## 2. ⭐ 파일 소유권 표 (핵심 기법 1)

### 원칙
> **"누가 무슨 *일*을 하나"가 아니라 "누가 어떤 *파일*을 소유하나"로 나눈다.**
> 파일 집합이 서로 겹치지 않으면 머지 충돌이 구조적으로 불가능하다.

지난 과제 실제 사례 — 3명 사이에 겹치는 파일이 **0개**였고, PR 5건 전부 충돌 없이 머지됐다.

### 복붙 템플릿

```markdown
## 파일 소유권

| 담당 | 소유 파일 | 절대 안 건드림 |
|---|---|---|
| (이름) | `docs/PLAN.md` | 그 외 전부 |
| (이름) | `src/style.css`, `src/index.html` | 그 외 전부 |
| (이름) | `TEST_LOG.md`, `DEPLOY_LOG.md` | 그 외 전부 |
| (이름) | `src/main.py` 등 코어 로직 | 위 3명 파일 |

원칙: 위 표에 없는 파일을 건드려야 하면 반드시 팀 채널에 먼저 공유
```

### 검증 방법
표를 다 그린 뒤 스스로 물어본다:
> **"두 사람이 같은 파일 이름을 적은 칸이 있나?"**
> 있으면 → 쪼개거나, 한 명에게 몰아주거나, 순서를 나눈다.

## 3. ⭐ 템플릿 선제공 (핵심 기법 2)

### 원칙
> **산출물을 요구할 때 양식을 먼저 준다.**
> "테스트 결과 정리해줘"보다 "이 표 채워줘"가 완료율·형식 통일 모두 압도적이다.

이건 **실력이 필요 없으면서 팀 기여도가 가장 크게 드러나는 작업**이다.
빈 칸이 있는 마크다운 파일을 만들어 올리는 게 전부다.

### 복붙 템플릿 — 테스트 로그

```markdown
# TEST_LOG.md — 테스트 기록
작성: (이름)

## 정상 케이스 1 — (입력 조건)
- 실행 명령: `...`
- 결과:
  - [ ] (기대 항목 1)
  - [ ] (기대 항목 2)
- 소요 시간: ___초
- 특이사항:

## 예외 케이스 1 — (조건)
- 방법:
- 기대 동작:
- 실제 결과:
- 판정: ✅ / ❌
```

### 복붙 템플릿 — 배포 로그

```markdown
# DEPLOY_LOG.md — 배포 기록
작성: (이름)

## 1. 배포 설정
- 플랫폼:
- Root Directory:
- 환경변수: `KEY = ****` (대시보드에서만 입력, 코드에 절대 넣지 않음)
- 배포 URL(Production):
- 배포 상태: [ ] 성공 / [ ] 실패

## 2. 헬스체크
- 요청: `GET /api/health`
- 응답:
```

## 3. 정상 케이스
- 입력:
- 결과: [ ] 항목1 [ ] 항목2
- 응답 시간: ___초

## 4. 예외 케이스
| 케이스 | 방법 | 기대 동작 | 실제 결과 |
|---|---|---|---|
| 필수값 누락 | | | |
| 반복 요청 | | | |

## 5. 트러블슈팅
- (문제 → 원인 → 해결)
```

> 💡 **팁**: `## 5. 트러블슈팅` 칸을 반드시 넣을 것.
> 최종 보고서의 트러블슈팅 섹션이 여기서 그대로 나온다.

---

## 4. 의존 체인 (핵심 기법 3)

### 원칙
> 의존 관계를 **선형 체인**으로 만든다. 각자 확인할 조건이 1개로 줄어든다.
> 순환·양방향 대기가 생기면 조율 비용이 기하급수적으로 는다.

### 복붙 템플릿

```markdown
## 작업 순서 및 차단 조건

A(스캐폴드) ──→ B(화면) ──→ C(테스트·배포) ──→ D(보고서)
   D-0          D+1         D+2              D+3

| 단계 | 담당 | 시작 조건 | 산출물 |
|---|---|---|---|
| A | | 없음(바로 시작) | |
| B | | A의 PR 머지 후 | |
| C | | B의 PR 머지 후 | |
| D | | C 완료 후 | |
```

각 담당자에게는 **"당신 앞사람이 끝났는지만 확인하면 됩니다"** 라고 전달한다.

---

## 5. 커밋 컨벤션 (합의만 하면 끝)

```
[이름] type: 내용

type: feat / fix / docs / test / style / refactor
예) [강하연] test: 정상·예외 케이스 테스트 결과 기록
```

**효과**: `git log` 만으로 누가 뭘 했는지 즉시 보인다 → 평가 자료가 자동 축적된다.

---

## 6. 평가에서 드러나게 만드는 법

지난 과제에서 확인된 것 — 평가 근거는 결국 **GitHub에 남은 흔적**이다.

| 무엇을 | 어디서 확인되나 |
|---|---|
| 팀원별 기여도 | `/graphs/contributors` |
| 브랜치·머지 흐름 | `/network` |
| 커밋 히스토리 | `/commits/main` |
| PR 생성·머지 실적 | `/pulls?q=is%3Apr` |

### 실천 사항
- [ ] 작업은 **반드시 브랜치 → PR → Merge** 로 (직접 push 금지)
- [ ] PR은 **최소 2개 이상** 만든다 (1개는 "했다"지만 2개는 "일하는 방식"이 된다)
- [ ] 커밋을 한 번에 몰아치지 말고 **작업 단위로 쪼갠다** (그래프에 분포가 보임)
- [ ] 중요 화면은 **그 자리에서 캡처** (나중에 재현하려면 시간 2배)

## 7. 내가 먼저 메워야 할 기술 공백

지난 과제에서 실제로 막혔던 지점. 다음 과제 전에 손에 익혀둘 것.

### 7-1. Git 경로 감각 ⚠️ 가장 많이 막힘
```bash
pwd                      # 항상 현재 위치부터 확인
```
- 저장소 루트에 있으면 → `git add Base/TEST_LOG.md`
- `Base/` 안에 있으면  → `git add TEST_LOG.md`
- **경로는 "지금 내가 서 있는 곳" 기준이다**

### 7-2. 가상환경(venv)
```bash
cd <프로젝트 폴더>
.\venv\Scripts\Activate.ps1     # 프롬프트에 (venv) 붙는지 확인
```
- `(venv)` 없으면 패키지를 못 찾는다
- 폴더마다 venv가 따로다. **엉뚱한 venv를 켜면 안 켠 것과 같다**

### 7-3. `.env` 파일
```bash
notepad .env            # 파일 탐색기에서 안 보이면 터미널로 직접 연다
type .env               # 저장 확인은 반드시 이걸로
```
- 편집 후 **Ctrl+S** → 탭의 흰 점(●)이 사라졌는지 확인
- `.gitignore`에 걸려 있어 **git에 안 보이는 게 정상**이다

### 7-4. 터미널 명령 vs 프로그램 입력 구분
```bash
python main.py          # ← 이건 터미널 명령
brief.json              # ← 이건 프로그램이 물어볼 때 답하는 값
```
프로그램이 질문을 띄운 뒤에 입력하는 값을 터미널에 바로 치면 에러가 난다.

## 8. 한 장 요약

```
착수 24시간 안에:
  1. 파일 소유권 표     → 겹치는 파일 0개로
  2. 빈 템플릿 파일     → 팀원은 칸만 채우게
  3. 의존 체인          → 각자 앞사람만 확인
  4. 커밋 컨벤션        → 기여도 자동 기록

작업 중:
  5. 브랜치 → PR → Merge (직접 push 금지, PR 2개 이상)
  6. 중요 화면은 그 자리에서 캡처

착수 전 내 숙제:
  7. pwd / venv / .env / 터미널 입력 구분 손에 익히기
```

> **핵심 한 줄**
> 구조 설계는 코딩 실력이 아니라 **먼저 그려서 공유하는 실행력**이다.
