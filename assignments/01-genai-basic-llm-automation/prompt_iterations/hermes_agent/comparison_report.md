# Hermes Agent 프롬프트 v1 → v2 개선 비교

## 1. 비교 목적

같은 Claude Sonnet 5와 같은 Hermes Agent 기사를 사용해 일반적인 직접 생성 방식과 단계적 검토·자체 검수 방식의 차이를 확인한다.

## 2. 비교 조건

| 항목 | v1 | v2 |
|---|---|---|
| 모델 | Claude Sonnet 5 | Claude Sonnet 5 |
| 입력 기사 | 동일 | 동일 |
| 프롬프트 | Claude 전용 v5 | 공통 v6 Final |
| 생성 방식 | 바로 콘텐츠 생성 | 사실 구분 → 불확실성 → 구조 → HTML → 자체 검수 |
| 결과 파일 | `article.md`, `index.html` | `package.md`, `blog.html` |

정확한 실행 시각과 응답 생성 시간은 기록되지 않아 비교에서 제외했다.

## 3. 결과 비교

| 비교 항목 | v1 | v2 | 판정 |
|---|---|---|---|
| 사실 확인 섹션 | 없음 | 있음 | 개선 |
| GitHub 스타 처리 | 72,000개를 현재 사실처럼 사용 | 최신 확인 필요로 분리 | 개선 |
| MIT·$5 VPS 처리 | 확정 서술 | 최신 확인 필요로 분리 | 개선 |
| 마이그레이션 명령 | 본문에서 다루지 않음 | 공식 확인 필요 표시 | 개선 |
| HTML 스타일 | `<style>`과 외부 폰트 | 인라인 CSS | 개선 |
| SEO meta | 없음 | 있음 | 개선 |
| 출력 파일 표준화 | 불일치 | `package.md`, `blog.html` | 개선 |
| 이미지 연계 | 실패·메모리·비교 | 같은 흐름을 명시적으로 연결 | 유지·개선 |
| 과장 표현 | “전멸”, 성공 단정 | 일부 남아 있음 | 부분 개선 |

## 4. 실제 근거

### v1

- `index.html`: “현재 공개된 내용 기준 GitHub 스타 72,000개를 넘겼습니다.”
- `index.html`: “무료 오픈소스(MIT 라이선스)이고 $5 VPS에서도 운영할 수 있습니다.”

문제:

- 기사에 포함된 변동 가능 수치를 별도 검증 표시 없이 본문 사실로 사용했다.
- Hermes 자체 비용과 LLM API·서버 비용의 조건을 충분히 분리하지 않았다.

### v2

- `package.md`: GitHub 스타, MIT 라이선스, 무료 운영, `$5 VPS`, 컨텍스트 요구사항을 확인 필요 항목으로 분리했다.
- `blog.html`: 스타 수, 라이선스, 요금, 시스템 요구사항과 마이그레이션 명령은 최신 공식 확인이 필요하다고 안내했다.

개선:

- 원문 주장을 삭제하지 않으면서 확정 사실처럼 보이지 않게 했다.
- HTML 게시 형식과 자동 평가 구조도 동시에 안정화했다.

## 5. 점수 비교

| 평가 축 | v1 | v2 |
|---|---:|---:|
| 사실성 | 2.5 | 4.0 |
| 형식 준수 | 3.0 | 4.5 |
| 콘텐츠 구조 | 4.0 | 4.0 |
| 가독성 | 4.5 | 4.0 |
| HTML 완성도 | 3.5 | 4.5 |
| 이미지·영상 연계 | 3.5 | 4.0 |
| 운영 편의성 | 2.5 | 4.0 |

v2는 사실성, 형식 준수, HTML 이식성, 운영 편의성에서 분명한 개선이 있었다. 가독성 점수는 v1이 조금 높지만 v2에서도 게시 가능한 수준을 유지했다.

## 6. 개선 결론

v2를 최종 채택한다.

근거:

1. 변동 가능 사실을 별도 확인 항목으로 분리한다.
2. 자동 파싱과 HTML 검증이 가능하다.
3. 모델별 결과를 같은 구조로 저장하고 비교할 수 있다.
4. 인라인 CSS로 블로그 플랫폼 이식성이 높다.

남은 보완:

- “전멸”, “성공 사례” 같은 표현을 더 중립적으로 제한
- 공식 확인이 끝난 항목과 미확인 항목을 자동으로 구분하는 입력 구조 추가
