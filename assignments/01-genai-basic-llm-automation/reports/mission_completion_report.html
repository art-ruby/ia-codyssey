1. 미션 개요

본 미션의 목적은 Hermes Agent 관련 원문과 벤치마크를 기반으로 한국어 AI 뉴스 블로그 콘텐츠 패키지를 생성하고, ChatGPT·Claude·Gemini의 결과를 동일한 기준으로 비교 평가하는 것이다.

평가 범위에는 콘텐츠 기획, 게시용 HTML, 이미지 및 영상 프롬프트, 사실 검증, 형식 준수, 프롬프트 개선 효과와 대화형 수정 과정이 포함된다.

평가표는 사실 정확성·환각 억제에 가장 높은 25% 가중치를 부여하고, 기사 충실도·형식 준수·콘텐츠 구조를 각각 15%로 평가했다. 따라서 최종 순위는 단순한 문장 품질보다 검증 가능성과 실무 사용성을 함께 반영한 결과다.

4. 주요 성과

  • 세 모델에 동일한 입력과 출력 규칙을 적용해 비교 가능성을 확보했다.
  • 마크다운, 게시용 HTML, 이미지 3종, Sora 2 프롬프트, SEO 요소를 하나의 평가 단위로 구성했다.
  • GitHub 스타 수, 설치 시간, 라이선스, VPS 비용 등 변동되거나 불확실한 정보에 대한 환각 검증 체계를 추가했다.
  • v2 프롬프트에 사실 추출, 불확실성 표시, 구조 설계, HTML 생성, 자체 검수 순서를 도입했다.
  • 대화형 수정 로그를 통해 독자층, 제목, 과장 표현, 비교표, 수치, HTML, 이미지 위치가 어떻게 개선됐는지 추적할 수 있게 했다.

5. 후속 권장사항

현재 제출을 막지는 않지만 다음 실행에서 보강할 항목
  1. 향후 재실행부터 정확한 시작·종료 시각과 응답 생성 시간을 측정한다.
  2. 모델별 결과 파일명을 package.md와 blog.html로 완전히 통일한다.
  3. 자동 검증 명령과 실행 로그를 별도 파일로 보존한다.

실행 메타데이터 보강

실행 날짜는 기록되어 있으나 정확한 시각과 응답 생성 시간은 측정되지 않았다. 재현성을 높이려면 모델명·버전, 요금제, 웹 검색 사용 여부, 실행 시각, 응답 시간, 온도나 추론 수준 등 사용 가능한 설정을 모델별로 동일한 형식으로 남겨야 한다.

자동 검증 증빙 보강

계획서에는 자동 검증이 완료됐다고 기록되어 있지만, 현재 파일 목록만으로는 검증 스크립트나 실행 결과 로그를 직접 확인하기 어렵다. 필수 섹션, 이미지 개수, HTML 마크다운 혼입, SEO 메타, 인라인 CSS 등을 검사한 명령과 결과를 별도 파일로 보존하는 것이 적절하다.

파일명과 구조 정규화

모델별 결과 파일명이 ChatGPT는 blog.html, Claude는 article.md와 index.html, Gemini는 index.md와 index.html로 다르다. 후속 자동 평가를 위해 공통 파일명 규약을 적용하거나 매핑 manifest를 두는 편이 안전하다.

6. 권장 마무리 순서

  1. 계획서 상태와 실제 파일 현황을 동기화한다.
  2. 최종 제출용 보고서 3종을 기존 평가표와 증빙을 인용해 작성한다.
  3. 누락된 증빙과 실행 메타데이터를 단일 형식으로 통합한다.
  4. 링크, 파일 존재 여부, HTML 유효성, 이미지 참조를 최종 점검한다.

7. 최종 판정

현재 단계는 “미션 완료, 후속 재현성 보강 권장”으로 판정한다. 세 모델 비교, 프롬프트 설계, 개선 실험, 환각 검증, 11턴 대화, 최종 보고서와 부속 증빙이 모두 존재한다. 정확한 실행 시각과 생성 시간은 미측정으로 투명하게 기록했으며 완료를 막는 누락 자료는 없다.
