# 09_output_examples_v1.md

## 1. 문서 목적

이 문서는 **AI 테크 뉴스 블로그 자동화 프로젝트에서 기대하는 출력물의 형태와 품질 수준을 예시 중심으로 정리한 기준 문서**이다.

목적은 다음과 같다.

- 좋은 출력물의 기준을 구체적으로 보여준다.
- 나쁜 출력물의 전형적인 문제를 식별할 수 있게 한다.
- 프롬프트 설계, 모델 비교, 수동 검수 시 판단 기준으로 활용한다.
- 요구사항 문서와 리스크 문서를 예시 차원에서 연결한다.
- “어떤 결과가 게시 가능한가”를 빠르게 판단할 수 있게 한다.

---

## 2. 적용 범위

이 문서는 아래 산출물 예시에 적용된다.

- 뉴스 요약 초안
- 비교형 블로그 본문
- OpenAI vs Google 비교표
- 제목/서브제목 예시
- 요약 박스 예시
- HTML 출력 예시
- 잘못된 출력 예시
- 수정 전/수정 후 예시

다만 이 문서는 전체 생성 규칙을 설명하는 문서가 아니라,  
**실제 출력 예시를 통해 품질 감각을 통일하는 문서**이다.

---

## 3. 문서 활용 방식

이 문서는 아래와 같이 활용한다.

1. 프롬프트 설계 시 목표 출력 형태를 확인한다.
2. 모델 비교 시 어떤 결과가 더 기준에 맞는지 평가한다.
3. 생성 후 검수 시 예시와 비교하여 품질을 판단한다.
4. 반복 실패가 발생하면 “나쁜 예시” 유형으로 추가한다.
5. 좋은 결과가 나오면 “권장 예시”로 축적한다.

---

## 4. 출력 예시의 분류 기준

예시는 크게 아래 4종으로 나눈다.

### 4.1 좋은 예시(Good Example)
구조, 정확성, 가독성, 비교 품질이 모두 기준에 부합하는 결과

### 4.2 보완 가능 예시(Acceptable Example)
게시는 가능하지만 문장 다듬기나 일부 수동 수정이 필요한 결과

### 4.3 나쁜 예시(Bad Example)
구조 문제, 환각, 비교 왜곡, HTML 깨짐 등으로 재작업이 필요한 결과

### 4.4 수정 예시(Before / After Example)
문제가 있던 결과를 어떻게 개선했는지 보여주는 예시

---

## 5. 좋은 출력의 공통 조건

좋은 출력은 단순히 문장이 자연스러운 것만으로 충분하지 않다.  
아래 조건을 함께 만족해야 한다.

### 5.1 구조 조건
- 제목이 명확하다.
- 도입부가 주제를 짧게 정리한다.
- 핵심 뉴스 요약이 있다.
- 비교 표 또는 비교 섹션이 있다.
- 시사점 또는 결론이 있다.
- 전체 흐름이 자연스럽다.

### 5.2 내용 조건
- 입력 기사에 없는 사실을 함부로 추가하지 않는다.
- 비교는 근거 기반이다.
- 특정 기업에 편향되지 않는다.
- 과장 표현이 적다.
- 최신성과 관련성이 유지된다.

### 5.3 형식 조건
- 문단 길이가 과도하게 길지 않다.
- 소제목이 읽기 쉽게 배치된다.
- HTML 구조가 안정적이다.
- 티스토리 붙여넣기에 무리가 없다.

---

## 6. 나쁜 출력의 공통 신호

다음과 같은 특징이 보이면 품질이 낮은 결과일 가능성이 크다.

- 제목은 강한데 본문 근거가 약함
- 기사 요약이 아니라 일반론 반복
- 비교표 항목이 들쭉날쭉함
- 입력 기사에 없는 해석을 단정적으로 서술
- 결론이 과장되거나 예언형 표현으로 끝남
- HTML 앞뒤에 설명 문장이 섞임
- 표/박스/리스트 구조가 깨짐

---

## 7. 예시 작성 원칙

이 문서의 예시는 실제 운영에 맞게 아래 기준으로 작성한다.

1. 지나치게 길지 않게 핵심만 보여준다.
2. 좋은 예시는 “왜 좋은지”를 같이 설명한다.
3. 나쁜 예시는 “왜 문제인지”를 분명히 적는다.
4. 수정 예시는 개선 포인트가 보이게 구성한다.
5. 예시의 주제는 AI 뉴스 자동화 프로젝트 성격에 맞춘다.

## 8. 제목 예시

### 8.1 좋은 제목 예시
- OpenAI와 Google AI 경쟁, 이번 주에 달라진 핵심 포인트
- AI 시장 주도권 경쟁: OpenAI와 Google의 최근 전략 비교
- 이번 주 AI 뉴스 정리: OpenAI와 Google은 어디에 집중했나

### 왜 좋은가
- 주제가 분명하다.
- 비교 관점이 드러난다.
- 과도한 자극 표현이 적다.
- 뉴스 기반 글이라는 인상이 있다.

### 8.2 보완 가능 제목 예시
- OpenAI와 Google, 누가 더 앞서가고 있을까

### 보완 포인트
- 너무 포괄적이다.
- “무엇을 기준으로 앞서는가”가 드러나지 않는다.
- 기사 기반 비교라는 느낌이 약하다.

### 8.3 나쁜 제목 예시
- 충격! OpenAI가 구글을 완전히 끝장냈다
- AI 패권 전쟁의 승자는 이미 정해졌다

### 왜 문제인가
- 과장 표현이 심하다.
- 기사 근거보다 자극성이 앞선다.
- 프로젝트 문체 기준과 맞지 않는다.

## 9. 도입부 예시

### 9.1 좋은 도입부 예시
```text
이번 주 AI 뉴스에서는 OpenAI와 Google이 각각 다른 방향에서 경쟁 구도를 강화하는 모습이 드러났다. OpenAI는 제품 활용성과 생태계 확장 측면에서 움직였고, Google은 검색·모델 통합과 플랫폼 전략을 중심으로 존재감을 키웠다. 이번 글에서는 주요 기사들을 바탕으로 두 기업의 최근 흐름을 비교해본다.
```

### 왜 좋은가
- 이번 글의 범위를 명확히 제시한다.
- 기업별 비교 관점을 미리 알려준다.
- 과장 없이 본문 연결성이 좋다.

### 9.2 나쁜 도입부 예시
```text
AI 산업은 지금 역사상 가장 거대한 전쟁을 벌이고 있다. 전 세계 모든 기업이 긴장하고 있고, 승자는 곧 모든 시장을 차지하게 될 것이다.
```

### 왜 문제인가
- 일반론만 있고 입력 기사 연결이 없다.
- 과장 표현이 많다.
- 글의 신뢰도를 떨어뜨린다.

## 10. 핵심 뉴스 요약 예시

### 10.1 좋은 예시
```text
- OpenAI 관련 뉴스는 제품 기능 확장과 활용 사례 중심으로 주목을 받았다.
- Google 관련 뉴스는 검색 통합, 모델 적용 범위 확대, 생태계 연결 전략이 강조되었다.
- 공통적으로 두 기업 모두 단일 모델 경쟁보다 서비스 접점 확대에 집중하는 흐름이 확인됐다.
```

### 왜 좋은가
- 기사 세트를 요약하는 역할이 분명하다.
- 기업별 특징과 공통점이 함께 보인다.
- 해석이 과도하지 않다.

### 10.2 나쁜 예시
```text
- OpenAI는 혁신적이다.
- Google도 열심히 한다.
- 둘 다 앞으로 잘할 것 같다.
```

### 왜 문제인가
- 정보량이 거의 없다.
- 기사 기반 요약이 아니다.
- 비교 분석의 출발점이 되기 어렵다.

---

## 11. 비교 분석 문단 예시

### 11.1 좋은 예시
```text
이번 기사 흐름만 놓고 보면 OpenAI는 사용자 체감 기능과 활용 장면을 넓히는 방향이 더 두드러졌고, Google은 기존 플랫폼과 AI 기능을 결합하는 방식이 더 강하게 나타났다. 이는 두 기업 모두 경쟁하고 있지만, 단기적으로는 ‘독립형 AI 사용 경험’과 ‘기존 서비스 내 AI 통합’이라는 서로 다른 강점을 드러내고 있음을 보여준다.
```

### 왜 좋은가
- 입력 기사 기반 해석처럼 읽힌다.
- 비교 축이 명확하다.
- 우열 단정이 아니라 차이 설명 중심이다.

### 11.2 보완 가능 예시
```text
OpenAI는 제품 중심이고 Google은 플랫폼 중심으로 보인다.
```

### 보완 포인트
- 너무 짧다.
- 근거 연결이 약하다.
- “왜 그렇게 보이는지”가 부족하다.

### 11.3 나쁜 예시
```text
OpenAI는 이미 AI 시장의 절대 강자이며 Google은 사실상 뒤처졌다.
```

### 왜 문제인가
- 기사 수준을 넘어선 단정이다.
- 비교 근거가 없다.
- 프로젝트의 중립성 기준에 맞지 않는다.

## 12. 비교 표 예시

### 12.1 좋은 예시
| 비교 항목 | OpenAI | Google |
|-----------|--------|--------|
| 최근 기사에서 두드러진 포인트 | 제품 활용성 확대 | 플랫폼 통합 강화 |
| 강하게 드러난 접점 | 사용자 경험 | 검색·서비스 생태계 |
| 기사 기반 인상 | 독립 서비스 확장 | 기존 서비스 연동 |

### 왜 좋은가
- 비교 축이 일정하다.
- 기사 기반 표현으로 정리되어 있다.
- 과장 없이 읽기 쉽다.

### 12.2 나쁜 예시
| 비교 항목 | OpenAI | Google |
|-----------|--------|--------|
| 기술력 | 최고 | 보통 |
| 미래 | 승리 | 불리 |
| 시장 장악력 | 압도적 | 밀림 |

### 왜 문제인가
- 주관적이고 근거가 없다.
- 비교 축이 모호하다.
- 평가형 단어가 강해 신뢰도가 낮다.

## 13. 결론 문단 예시

### 13.1 좋은 예시
```text
정리하면 이번 주 흐름에서는 OpenAI와 Google이 같은 AI 경쟁 구도 안에 있으면서도 서로 다른 실행 방식을 보여줬다. OpenAI는 사용자 체감 기능과 독립형 서비스 경험을 넓히는 쪽이 두드러졌고, Google은 기존 플랫폼에 AI를 결합하는 전략이 더 선명했다. 앞으로도 두 기업의 차이는 단순 성능 비교보다 실제 서비스 접점에서 더 분명하게 드러날 가능성이 크다.
```

### 왜 좋은가
- 앞선 본문 내용을 잘 요약한다.
- 과장되지 않는다.
- 다음 관찰 포인트까지 자연스럽게 제시한다.

### 13.2 나쁜 예시
```text
결국 이 전쟁의 승자는 OpenAI다. Google은 이제 따라가기 어려울 것이다.
```

### 왜 문제인가
- 근거 없는 결론이다.
- 뉴스 요약 글의 범위를 벗어난다.
- 과장과 단정이 심하다.

## 14. 요약 박스 예시

### 14.1 좋은 예시
```text
[Summary Box]
- OpenAI: product usability and direct user experience
- Google: platform integration and ecosystem leverage
- Key takeaway: different execution styles within the same AI race
```

### 설명
- 영어 라벨 예시로 두면 HTML/시각화 확장 시 활용하기 쉽다.
- 짧고 핵심만 담아 가독성이 높다.

### 한글 의미
- product usability and direct user experience: 제품 활용성과 직접적인 사용자 경험
- platform integration and ecosystem leverage: 플랫폼 통합과 생태계 활용
- different execution styles within the same AI race: 같은 AI 경쟁 안에서도 서로 다른 실행 방식

### 14.2 나쁜 예시
```text
[Summary Box]
- OpenAI is amazing
- Google is dangerous
- The war is getting crazy
```

### 왜 문제인가
- 감정적 표현이 많다.
- 정보성이 약하다.
- 블로그 기준 문체와 맞지 않는다.

## 17. 수정 전 / 수정 후 예시

### 17.1 수정 전
```text
OpenAI는 이미 시장을 장악했고 Google은 크게 뒤처졌다. 이번 기사들은 그 사실을 다시 증명한다.
```

### 문제점
- 과장 표현
- 입력 기사 범위를 넘는 단정
- 비교가 아니라 판정처럼 읽힘

### 17.2 수정 후
```text
이번 기사 흐름만 보면 OpenAI는 사용자 체감 기능 측면에서 존재감을 보였고, Google은 기존 플랫폼과의 통합 전략이 더 선명하게 나타났다. 다만 이번 글은 특정 시점의 기사 세트를 바탕으로 한 비교라는 점에서, 장기 우열 판단보다는 실행 방향의 차이에 주목할 필요가 있다.
```

### 왜 개선되었는가
- 단정 대신 근거 기반 비교가 되었다.
- 글의 범위를 스스로 제한해 신뢰도를 높였다.
- 중립성이 강화되었다.

### 20.1 추가해야 하는 예시
- 매우 좋은 결과
- 자주 반복되는 실패 결과

- HTML 오류 대표 사례

### 20.2 삭제 또는 교체 가능한 예시

- 너무 추상적인 예시
- 기준이 바뀌어 더 이상 대표성이 없는 예시
- 현재 프롬프트/파이프라인 구조와 맞지 않는 예시

### 20.3 운영 원칙

2. 나쁜 예시는 “재발 방지용 학습 자료”로 관리한다.
3. 수정 전/수정 후 예시는 프롬프트 개선의 근거로 활용한다.
4. 예시 추가 시 관련 프롬프트 버전 또는 로그 문서와 연결한다.

## 22. 실무에서 자주 보는 실패 패턴 예시

운영 중 자주 나올 수 있는 실패 패턴을 예시 차원에서 정리한다.

### 22.1 일반론 과다
```text
AI industry is changing rapidly, and many companies are investing heavily in innovation.
```

### 문제
- 기사 세트 기반 요약이 아니다.
- 누구에게나 적용되는 일반론이다.
- 블로그 초안으로서 정보 밀도가 낮다.

### 22.2 비교 축 붕괴
```text
OpenAI는 제품이 강하다.
Google은 크다.
OpenAI는 빠르다.
Google은 똑똑하다.
```

### 문제
- 같은 기준으로 비교하지 않는다.
- 표나 비교 문단으로 확장하기 어렵다.
- 독자가 무엇을 읽어야 하는지 불명확하다.

### 22.3 근거 없는 미래 예측
```text
앞으로 1년 안에 Google의 AI 전략은 완전히 실패할 가능성이 높다.
```

### 문제
- 기사 기반 정보가 아니라 추정이다.
- 단정적 예측은 신뢰도를 떨어뜨린다.
- 프로젝트 문체 원칙과 맞지 않는다.

### 22.4 HTML 외 텍스트 혼입
```html
Sure, here is the HTML version you requested.

<h1>...</h1>
```

### 문제
- HTML 순수 출력 원칙 위반
- 붙여넣기 자동화 흐름 방해
- 후처리 부담 증가

## 23. 좋은 예시를 프롬프트 개선에 반영하는 방법

좋은 예시는 단순 참고 자료가 아니라, 프롬프트 품질 개선의 기준점이 된다.

### 23.1 반영 방법
- 좋은 제목 예시를 제목 생성 프롬프트에 포함
- 좋은 도입부 구조를 시스템 지시문으로 반영
- 좋은 비교표 축을 출력 형식 예시로 포함
- 좋은 결론의 톤을 금지 표현 규칙과 함께 명시

### 23.2 예시 반영 원칙
1. 예시는 복붙용이 아니라 패턴 학습용으로 사용한다.
2. 예시가 너무 구체적이면 결과가 획일화될 수 있으므로 주의한다.
3. 좋은 예시는 2~3개 정도만 엄선해 넣는 것이 좋다.
4. 나쁜 예시는 “금지 예시”로 활용할 수 있다.

## 24. 모델 비교 시 예시 문서 활용법

같은 입력으로 여러 모델 결과를 비교할 때,  
이 문서의 예시를 기준점으로 사용하면 평가가 훨씬 일관된다.

### 24.1 활용 방법
- 제목이 좋은 예시와 유사한지 확인
- 도입부가 기사 기반 비교를 하고 있는지 확인
- 비교표가 좋은 축을 유지하는지 확인
- 결론이 나쁜 예시처럼 과장되지 않았는지 확인
- HTML이 잘못된 예시 패턴을 반복하는지 확인

### 24.2 평가 메모 예시
```text
- 제목: Good Example에 가까움
- 도입부: 기사 기반은 있으나 비교 관점이 약함
- 비교표: 축 일관성 양호
- 결론: Acceptable Example 수준
- HTML: 구조 안정적
```

## 25. 수동 검수 시 활용 체크리스트

출력 결과를 검수할 때 아래 질문으로 빠르게 확인할 수 있다.

### 내용 검수
- 이 문장은 입력 기사에서 근거를 찾을 수 있는가?
- 비교가 우열 판정보다 차이 설명 중심인가?
- 과장 표현이 들어가 있지 않은가?
- 일반론이 과도하게 많지 않은가?

### 구조 검수
- 제목, 도입, 요약, 비교, 결론이 모두 있는가?
- 문단 순서가 자연스러운가?
- 비교표 축이 일정한가?

### 형식 검수
- HTML 외 설명 문장이 섞이지 않았는가?
- 태그 구조가 안정적인가?
- 붙여넣기 후 레이아웃 문제가 없는가?

## 26. 운영 기준으로서의 핵심 해석

이 문서의 핵심은 “좋은 문장”을 고르는 것이 아니라  
**“게시 가능한 품질의 출력 패턴”을 식별하는 것**이다.

즉, 아래 기준이 중요하다.

- 읽기 좋은가?
- 기사 기반인가?
- 비교가 명확한가?
- 과장되지 않는가?
- HTML이 안정적인가?
- 반복 가능한 품질인가?

이 기준을 만족하는 결과가 곧 이 프로젝트에서의 좋은 출력이다.
