# 01_requirements_spec_v1.md

## 1. 문서 목적
이 문서는 **AI 테크 뉴스 블로그 자동화 프로젝트의 요구사항 명세서**이다.  
입력, 출력, 품질 기준, 제약 조건, 검증 기준을 정의하여 이후 프롬프트 설계, 파이프라인 설계, HTML 템플릿 설계의 기준으로 사용한다.

---

## 2. 프로젝트 개요

### 2.1 프로젝트명
AI 테크 뉴스 블로그 자동화 프로젝트

### 2.2 목표
검색어 1개를 입력하면 최신 AI 뉴스 기반의 블로그 포스트를 자동 생성한다.

### 2.3 최종 산출물
- 티스토리 게시용 HTML 블로그 본문
- 제목 5개
- 메타 설명
- 3줄 요약
- 비교 표
- HTML 강조 문장
- 해시태그 10개
- 이미지 프롬프트 5개
- 영상 프롬프트 1개

### 2.4 타겟 독자
- 최신 AI/IT 뉴스를 빠르게 이해하고 싶은 일반 독자
- 직장인
- 실무자
- 콘텐츠 소비자

### 2.5 작성 목적
블로그 게시용 콘텐츠 자동 생성

### 2.6 출력 플랫폼
티스토리

---

## 3. 기본 주제
- **기본 주제**: OpenAI와 Google의 최신 생성형AI 경쟁 구도
- **작성 톤**: 분석형 + 뉴스 브리핑형
- **목적**: 최신 AI 뉴스의 핵심을 빠르게 전달하고, 실무적 의미까지 해설하는 블로그 콘텐츠 제작

---

## 4. 핵심 요구사항 요약
본 프로젝트는 다음 조건을 만족해야 한다.

1. 검색어 1개만으로 콘텐츠 생성 흐름을 시작할 수 있어야 한다.
2. 최신 뉴스 기반으로 내용을 구성해야 한다.
3. 단순 요약이 아니라 의미 해설과 비교가 포함되어야 한다.
4. 결과물은 티스토리에 바로 붙여넣기 쉬운 HTML 형태여야 한다.
5. 출력 순서는 고정되어야 한다.
6. 벤치마킹 기반의 높은 가독성을 가져야 한다.
7. 이후 GPT / Claude / Gemini 비교가 가능하도록 입력/출력 구조가 통일되어야 한다.

## 5. 입력 요구사항

### 5.1 기본 입력
사용자는 최소 1개의 검색어를 입력한다.

예:
- `GPT 최신 업데이트`
- `OpenAI와 Google 생성형AI 경쟁`
- `Gemini 2.5 vs ChatGPT`
- `AI 에이전트 최신 동향`

### 5.2 입력 필드
기본 입력 필드는 아래와 같다.

| 항목 | 필수 여부 | 설명 |
|------|-----------|------|
| 검색어 | 필수 | 최신 뉴스 탐색의 기준 키워드 |
| 주제 | 선택 | 블로그에서 집중할 세부 관점 |
| 작성 목적 | 선택 | 블로그 게시 / 비교 분석 / 요약 정리 등 |
| 타겟 독자 | 선택 | 일반 독자 / 직장인 / 실무자 등 |
| 작성 톤 | 선택 | 분석형 / 브리핑형 / 인사이트형 등 |
| 출력 플랫폼 | 선택 | 티스토리 / 워드프레스 / 노션 등 |

### 5.3 기본값
선택 입력이 없을 경우 아래 기본값을 사용한다.

- **주제**: OpenAI와 Google의 최신 생성형AI 경쟁 구도
- **작성 목적**: 블로그 게시
- **타겟 독자**: 최신 AI 뉴스를 빠르게 이해하고 싶은 직장인과 일반 독자
- **작성 톤**: 분석형 + 뉴스 브리핑형
- **출력 플랫폼**: 티스토리

## 6. 출력 요구사항

출력은 반드시 아래 순서를 따른다.

1. 제목 5개
2. 메타 설명
3. 3줄 요약
4. 블로그 본문
5. 비교 표
6. HTML 강조 문장
7. 해시태그
8. 이미지 프롬프트
9. 영상 프롬프트

---

## 7. 상세 출력 명세

### 7.1 제목 5개
- 서로 다른 스타일로 5개 제안한다.
- 클릭 유도형, 분석형, 질문형, 비교형 등으로 다양화한다.
- 과장 없이 사실 기반으로 작성한다.
- 가능하면 핵심 키워드를 자연스럽게 포함한다.

예시 스타일:
- 뉴스 브리핑형
- 질문형
- 비교형
- 실무 인사이트형
- 이슈 정리형

---

### 7.2 메타 설명
- 검색 결과 노출을 고려한 짧은 소개문
- 핵심 키워드를 자연스럽게 반영
- 과장된 문구 지양
- 1~2문장 분량 권장

---

### 7.3 3줄 요약
- 전체 글의 핵심만 빠르게 파악할 수 있어야 한다.
- 독자가 본문을 읽기 전에 흐름을 이해할 수 있어야 한다.
- 각 줄은 짧고 명확하게 작성한다.

---

### 7.4 블로그 본문
본문은 아래 구조를 기본으로 한다.

1. 도입
2. 핵심 뉴스 요약
3. OpenAI 동향
4. Google 동향
5. 경쟁 구도 비교
6. 실무적 의미
7. 결론

#### 본문 작성 규칙
- 문단은 짧게 유지한다.
- 2~3문장 단위로 끊는다.
- 단순 나열이 아니라 해설을 포함한다.
- “왜 중요한가”와 “실무적으로 어떤 의미인가”를 함께 설명한다.
- 필요 시 소제목(h2, h3) 구조를 사용한다.
- 불확실한 내용은 명확히 표시한다.

---

### 7.5 비교 표
- 비교 가능한 내용은 반드시 표로 정리한다.
- 표는 본문과 충돌하지 않아야 한다.
- 비교 기준은 명확해야 한다.

예시 비교 항목:
- 최근 발표/업데이트 방향
- 제품 전략
- 생태계 확장성
- 사용자 접점
- 기업용 활용성
- 실무 영향도

---

### 7.6 HTML 강조 문장
- 블로그 내 강조 박스 또는 하이라이트 문장으로 사용할 수 있어야 한다.
- 짧고 임팩트 있게 작성한다.
- 사실 기반으로 작성한다.
- 최소 2~3개 제공 가능하도록 설계한다.

예:
- `<div class="highlight-box">이번 경쟁의 핵심은 모델 성능 자체보다 생태계 확장 속도에 있다.</div>`

---

### 7.7 해시태그
- 총 10개 작성한다.
- 범용 키워드 + 세부 키워드를 혼합한다.
- 검색성과 주제 적합성을 함께 고려한다.

예:
- `#AI`
- `#생성형AI`
- `#OpenAI`
- `#GoogleAI`
- `#AI뉴스`

---

### 7.8 이미지 프롬프트
- 총 5개 작성한다.
- **썸네일용**과 **본문 삽입용**을 구분한다.
- 기술 블로그에 어울리는 현대적이고 전문적인 스타일을 반영한다.
- 파란색/보라색 계열 중심의 톤을 선호한다.

#### 구분 방식
- 썸네일용: 1개 이상
- 본문용: 4개 이상

#### 포함 요소
- 장면 설명
- 구도
- 분위기
- 색감
- 사용 목적

---

### 7.9 영상 프롬프트
- 1개 작성한다.
- 쇼츠 / 릴스형 짧은 영상 제작에 적합해야 한다.
- 빠르게 핵심을 전달할 수 있는 구성이어야 한다.
- 15초~60초 내외의 짧은 콘텐츠 흐름을 가정한다.

포함 요소:
- 영상 콘셉트
- 장면 흐름
- 핵심 자막 방향
- 추천 톤앤매너

---

## 8. HTML 출력 요구사항

### 8.1 목적
최종 결과는 티스토리에 붙여넣기 쉬운 HTML 형태를 지원해야 한다.

### 8.2 HTML 구조 요구
- 제목: `h1`
- 주요 섹션: `h2`
- 하위 섹션: `h3`
- 요약 박스, 강조 박스, 비교 표 포함 가능
- 문단 간 여백 확보
- 가독성 높은 구조 유지

### 8.3 스타일 가이드
- 강조색: `#FF6B6B`
- 배경색: `#E8F5F0`
- 박스색: `#E3F2FD`
- 테두리: `#4A90E2`

### 8.4 HTML 작성 원칙
- 불필요한 복잡성을 줄인다.
- 외부 스크립트 의존성을 최소화한다.
- 티스토리 에디터에 붙여넣기 쉬운 구조를 우선한다.
- 인라인 스타일 또는 재사용 가능한 CSS 블록을 고려한다.

---

## 9. 콘텐츠 품질 기준

### 9.1 사실성
- 입력 기반 정보를 우선 반영한다.
- 입력에 없는 사실은 임의로 추가하지 않는다.
- 수치, 날짜, 가격, 성능은 검증 없이는 작성하지 않는다.
- 루머는 사실처럼 쓰지 않는다.

### 9.2 해설력
- 단순 뉴스 요약에서 끝나지 않아야 한다.
- 왜 중요한지 설명해야 한다.
- 실무자 관점에서 어떤 변화가 있는지 해설해야 한다.

### 9.3 가독성
- 짧은 문단 사용
- 불필요한 장문 지양
- 핵심 문장 강조
- 표, 박스, 이미지 삽입 포인트 고려

### 9.4 재사용성
- 결과물이 다른 주제에도 적용 가능한 구조여야 한다.
- 제목/본문/표/프롬프트가 분리 가능해야 한다.
- 후속 자동화에서 그대로 활용할 수 있어야 한다.

---

## 10. 작성 원칙 반영 기준

본 문서는 아래 프로젝트 작성 원칙을 요구사항 수준에서 반영한다.

1. 입력 정보를 최우선으로 반영한다.
2. 입력에 없는 사실은 임의로 추가하지 않는다.
3. 불확실한 내용은 확인 필요로 표시한다.
4. 뉴스 요약에 그치지 않고 중요성과 실무적 의미를 설명한다.
5. 전문적이되 어렵지 않게 쓴다.
6. 문단은 짧고 가독성이 높아야 한다.
7. 출력은 구조화되어야 한다.
8. 제목은 서로 다른 스타일로 제안한다.
9. 비교 가능 시 표를 포함한다.
10. 해시태그는 범용+세부 키워드를 혼합한다.
11. 이미지 프롬프트는 썸네일용/본문용을 구분한다.
12. 영상 프롬프트는 짧은 영상 제작에 적합해야 한다.

---

## 11. 금지 사항 반영 기준

아래 사항은 출력 생성 시 금지한다.

- 입력에 없는 수치, 날짜, 가격, 성능을 추정해서 쓰는 행위
- 확인되지 않은 루머를 사실처럼 쓰는 행위
- 과장된 표현을 근거 없이 사용하는 행위
- 표와 JSON 내용이 본문과 충돌하게 작성하는 행위

## 12. 최신 뉴스 기준

### 12.1 현재 상태
최신 뉴스의 기준 기간은 아직 최종 확정 전이다.

### 12.2 임시 기본안
초기 기본값은 아래와 같이 설정한다.

- **기본 기준**: 최근 7일 이내 뉴스 우선
- 보조 옵션:
  - 최근 24시간
  - 최근 30일

### 12.3 주의사항
LLM 단독 생성만으로 최신성을 보장할 수 없으므로, 실제 뉴스 수집 단계와 출처 확인 단계가 필요하다.

## 13. 뉴스 출처 요구사항

### 13.1 원칙

- 출처 없는 내용은 단정적으로 쓰지 않는다.

### 13.2 우선 검토 대상 예시
- OpenAI 공식 블로그
- Google 공식 블로그
- Google DeepMind 관련 공식 채널
- Anthropic 공식 채널
- Microsoft 공식 블로그
- TechCrunch AI
- The Verge AI
- Reuters Tech
- VentureBeat AI

### 13.3 후속 과제
출처 우선순위와 필수/보조 출처 목록은 별도 문서에서 확정한다.

## 17. 실패 기준

아래 중 하나라도 발생하면 결과 품질이 미달한 것으로 본다.

- 입력에 없는 사실을 단정적으로 추가함
- 제목 5개가 서로 지나치게 유사함
- 본문이 단순 기사 나열 수준에 그침
- 실무적 의미 설명이 없음
- 비교 표가 부실하거나 본문과 충돌함
- HTML 구조가 티스토리 활용에 부적합함
- 해시태그가 지나치게 일반적이거나 주제 적합성이 낮음
- 이미지/영상 프롬프트가 사용 목적에 맞지 않음
