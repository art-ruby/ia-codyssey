# IA Codyssey 미션 실행 계획

## 1. 핵심 판단

현재 세 개의 모델별 프롬프트는 동일하지 않다.

- ChatGPT v3: 규칙이 가장 상세하지만 출력 구조가 구버전이다.
- Gemini v4: 대표 이미지 3개와 완결형 HTML 구조가 강화되었다.
- Claude v5: 자동 파싱 구분자가 추가되었고 Claude Project 사용에 최적화되었다.

이 상태로 결과를 직접 비교하면 모델 성능과 프롬프트 차이가 섞인다. 따라서 비교 실험을 다음 두 종류로 분리한다.

1. 공정 비교: 동일한 공통 프롬프트를 세 모델에 입력
2. 실무 비교: 모델별 최적화 프롬프트 v3·v4·v5 사용

최종 보고서에는 두 실험의 입력, 결과, 점수를 분리해서 기록한다.

## 2. 확정된 업무 과업

> Hermes Agent 관련 원문과 벤치마크를 바탕으로 한국어 AI 뉴스 블로그 콘텐츠 패키지를 자동 생성한다.

### 입력 자료

- Hermes Agent GPTERS 글
- Nick Spisak X 원문 링크
- Hermes Agent와 OpenClaw 비교 내용
- 네이버 블로그 형식 벤치마크
- AI 도구 소개 콘텐츠 구성 벤치마크

### 출력 자료

- 마크다운 기획·메타 문서
- 게시 가능한 완결형 HTML
- 제목과 썸네일 문구
- 대표 이미지 프롬프트 3개와 각각의 alt 텍스트
- Sora 2 영상 프롬프트, 내레이션, 자막
- SEO 설명과 해시태그

## 3. 실험 입력 확정

하나의 고정 입력 패키지를 사용한다.

```text
evaluation/test_inputs/hermes_agent/
├── article_source.md
├── source_manifest.md
├── expected_facts.md
└── test_case.md
```

`expected_facts.md`에는 다음 검증 기준을 기록한다.

- 개발 주체
- 라이선스
- 지원 환경
- 설치 명령
- 메모리 및 스킬 기능
- 메시징 지원 범위
- OpenClaw 비교 주장
- 확인되지 않은 숫자와 표현

## 4. 비교용 공통 프롬프트

세 모델에 완전히 동일하게 넣을 프롬프트를 사용한다.

```text
prompts/comparison/prompt_ai_news_content_package_common_v6_final.md
```

공통 프롬프트에서 다음 항목을 고정한다.

- 입력 기사
- 형식 벤치마크
- 콘텐츠 벤치마크
- 출력 항목과 순서
- HTML 구조와 길이
- 사실 검증 규칙
- 출력 구분자

## 5. 모델별 결과 저장

```text
evaluation/model_outputs/hermes_agent/

│   │   ├── package.md

    ├── chatgpt/
    ├── gemini/
    └── claude/
```

각 모델 실행 시 다음 정보를 기록한다.

- 정확한 모델명
- 요금제
- 웹·앱·API 구분
- 실행 날짜
- 주요 설정
- 사용 프롬프트
- 응답 생성 시간
- 무료 버전의 제한사항

## 6. 자동·수동 검증

### 자동 검증

- 필수 섹션 존재 여부
- 대표 이미지 프롬프트 3개 여부
- `[이미지1]`, `[이미지2]`, `[이미지3]` 위치
- HTML 문서 시작·종료 태그
- HTML 내부 마크다운 문법 혼입 여부
- 해시태그 10개 이상
- Sora 2 필수 문구
- 출력 시작·끝 구분자

### 수동 검증

- 사실성
- 기사 충실도
- 한국어 자연스러움
- 콘텐츠 전개력
- 형식 벤치마크 반영
- HTML 완성도
- 비교의 균형성
- 실무 수정량

## 7. 비교 평가표

| 평가 축 | 가중치 |
|---|---:|
| 사실 정확성·환각 억제 | 25% |
| 입력 기사 충실도 | 15% |
| 형식 준수 | 15% |
| 콘텐츠 구조 | 15% |
| 한국어 가독성 | 10% |
| HTML 완성도 | 10% |
| 이미지·영상 프롬프트 연계 | 5% |
| 운영·파싱 편의성 | 5% |

각 항목은 1~5점으로 평가하고 반드시 결과물의 실제 문장이나 구조를 근거로 기록한다.

## 8. 추가 미션 과제

### Few-shot 예시 3개

최종 시스템 프롬프트 설계 문서에는 다음 예시를 포함한다.

1. 충분한 기사 입력
2. 사실과 해석이 섞인 기사
3. 정보가 부족해 확인 질문이 필요한 기사

### v1 → v2 개선 비교

- v1: 기사에서 블로그를 바로 생성
- v2: 사실 추출 → 불확실성 표시 → 구조 설계 → HTML 생성 → 자체 검수

수정 전후 결과와 개선 근거를 함께 기록한다.

### 환각 검증 질문

최소 다음 질문을 검증한다.

1. 공식 라이선스는 무엇인가?
2. 현재 GitHub 스타 수는 얼마인가?
3. 공식 지원 운영체제는 무엇인가?
4. 설치 명령은 현재도 유효한가?
5. OpenClaw 마이그레이션 명령이 실제 존재하는가?
6. `Gemma 4 26B`라는 모델명이 정확한가?
7. `$5 VPS 운영 가능`의 공식 근거가 있는가?

각 질문에 기대 정답 또는 판정 기준, 출처, Pass/Fail을 기록한다.

### 10턴 이상 대화 로그

최종 선정 모델로 다음 흐름을 포함한 반복 대화를 수행한다.

1. 기사 입력
2. 핵심 주제 확인
3. 독자층 변경
4. 제목 수정
5. 과장 표현 제거
6. 비교표 보완
7. 출처 없는 수치 삭제
8. HTML 형식 변경
9. 이미지 위치 조정
10. 최종 패키지 재생성
11. 앞서 확정한 조건 유지 여부 확인

## 10. 실행 순서

1. Hermes 입력 원문과 검증 기준 확정
2. 공통 비교 프롬프트 작성
3. ChatGPT·Gemini·Claude에서 동일 조건 실행
4. 원본 응답과 HTML을 모델별 저장
5. 자동 형식 검사
6. 사실 검증과 평가표 작성
7. 최적 모델 선정
8. 선정 모델로 10턴 이상 대화 수행
9. v1→v2 개선 이력 작성
10. 최종 보고서 3개 완성
