# 04_generation_pipeline_v1.md

## 1. 문서 목적
이 문서는 **AI 테크 뉴스 블로그 자동화 프로젝트의 생성 파이프라인 설계 문서**이다.  
입력된 검색어를 바탕으로 최신 뉴스 기반 블로그 결과물을 생성하기까지의 전체 흐름을 단계별로 정의한다.

이 문서의 목적은 다음과 같다.

- 전체 작업 흐름을 표준화한다.
- 프롬프트를 단계별로 분리 설계할 수 있게 한다.
- GPT / Claude / Gemini 비교 시 동일한 파이프라인을 적용할 수 있게 한다.
- 향후 Codex 또는 자동화 스크립트가 구현할 수 있는 구조를 만든다.

---

## 2. 파이프라인 한 줄 설명
**검색어 입력 → 뉴스 수집 → 뉴스 정리 → 핵심 선별 → 블로그 구조 생성 → HTML 변환 → 결과 검수**의 흐름으로 콘텐츠를 생성한다.

---

## 3. 파이프라인 설계 원칙

### 3.1 단계 분리 원칙
하나의 긴 프롬프트로 모든 작업을 처리하지 않고, 기능별로 단계를 분리한다.

### 3.2 검증 가능성 원칙
각 단계는 입력과 출력이 명확해야 하며, 중간 산출물을 검토할 수 있어야 한다.

### 3.3 재사용성 원칙
특정 키워드에만 종속되지 않고, 다른 AI/IT 주제에도 확장 가능해야 한다.

### 3.4 비교 가능성 원칙
모델 비교를 위해 단계별 입력 조건과 출력 구조를 최대한 고정한다.

### 3.5 사실성 우선 원칙
최신 뉴스와 사실 기반 정보가 핵심이며, 추정이나 환각 생성은 최소화해야 한다.

---

## 4. 전체 파이프라인 개요

전체 흐름은 아래 7단계로 구성한다.

1. 입력 정의
2. 뉴스 수집
3. 뉴스 정리 및 정규화
4. 핵심 뉴스 선별 및 해설 포인트 도출
5. 블로그 콘텐츠 생성
6. HTML 렌더링
7. 검수 및 저장

---

## 5. 단계별 파이프라인 상세

## 5.1 1단계: 입력 정의

### 목적
사용자의 검색어와 선택 옵션을 받아 작업의 기준을 설정한다.

### 입력
- 검색어 1개 이상
- 선택 옵션:
  - 주제
  - 작성 목적
  - 타겟 독자
  - 작성 톤
  - 출력 플랫폼

### 기본값
선택 옵션이 없으면 아래 기본값을 사용한다.

- **주제**: OpenAI와 Google의 최신 생성형AI 경쟁 구도
- **작성 목적**: 블로그 게시
- **타겟 독자**: 최신 AI 뉴스를 빠르게 이해하고 싶은 직장인과 일반 독자
- **작성 톤**: 분석형 + 뉴스 브리핑형
- **출력 플랫폼**: 티스토리

### 출력
구조화된 입력 객체 또는 입력 요약 문서

예시:
```json
{
  "keyword": "OpenAI Google generative AI competition",
  "topic": "OpenAI와 Google의 최신 생성형AI 경쟁 구도",
  "purpose": "블로그 게시",
  "audience": "직장인과 일반 독자",
  "tone": "분석형 + 뉴스 브리핑형",
  "platform": "티스토리"
}
```

### 체크포인트
- 검색어가 너무 넓지 않은가
- 검색어가 최신 뉴스 탐색에 적합한가
- 타겟 독자와 톤이 충돌하지 않는가

---

## 5.2 2단계: 뉴스 수집

### 목적
입력된 검색어와 관련된 최신 뉴스 후보를 수집한다.

### 역할
이 단계는 “무엇이 최근 핵심 이슈인가”를 모으는 단계이다.

### 입력
- 검색어
- 최신 뉴스 기준 기간
- 우선 출처 목록

### 기본 기준
- 최근 7일 이내 뉴스 우선
- 필요 시 최근 24시간 / 최근 30일 옵션 사용 가능

### 수집 대상 예시
- 공식 블로그
- 공식 제품 발표
- 주요 기술 매체 기사
- 기업 발표문
- 인터뷰 또는 보도자료

### 기대 출력
뉴스 후보 목록

예시 구조:
```json
[
  {
    "title": "기사 제목",
    "source": "출처명",
    "date": "YYYY-MM-DD",
    "url": "기사 링크",
    "summary": "핵심 내용 2~3문장",
    "relevance": "검색어와의 관련성 설명"
  }
]
```

### 체크포인트
- 출처가 명확한가
- 날짜가 최신 기준에 부합하는가
- 검색어와 직접 관련이 있는가
- 중복 기사만 과도하게 수집되지 않았는가

### 실패 위험
- 오래된 뉴스 포함
- 루머성 기사 포함
- 제목만 다르고 사실상 같은 기사 중복 포함

---

## 5.3 3단계: 뉴스 정리 및 정규화

### 목적
수집된 뉴스 후보를 동일 형식으로 정리하여 후속 분석이 가능하게 만든다.

### 역할
원자료를 모델이 다루기 쉬운 중간 데이터로 바꾸는 단계이다.

### 처리 내용
- 제목 정리
- 날짜 형식 통일
- 출처명 통일
- 중복 기사 제거
- 핵심 문장 요약
- 주제별 묶기

### 입력
- 뉴스 후보 목록

### 출력
정리된 뉴스 데이터셋

예시 구조:
```json
{
  "keyword": "OpenAI Google generative AI competition",
  "collected_at": "YYYY-MM-DD",
  "news_items": [
    {
      "id": "news_001",
      "company": "OpenAI",
      "title": "기사 제목",
      "source": "출처명",
      "date": "YYYY-MM-DD",
      "url": "기사 링크",
      "normalized_summary": "정규화된 핵심 요약",
      "topic_tag": ["model", "enterprise", "product"]
    }
  ]
}
```

### 체크포인트
- 형식이 통일되었는가
- OpenAI / Google / 기타 경쟁사 구분이 가능한가
- 기사별 핵심 포인트가 한눈에 보이는가

### 실패 위험
- 정리 형식이 들쭉날쭉함
- 기사 핵심이 아닌 부수 정보가 강조됨
- 동일 사건이 중복 남아 있음

---

## 5.4 4단계: 핵심 뉴스 선별 및 해설 포인트 도출

### 목적
수집된 뉴스 중 블로그에서 다룰 가치가 높은 핵심 뉴스만 선별하고, 설명해야 할 포인트를 뽑는다.

### 역할
단순 수집에서 끝나지 않고 “무엇을 중심으로 글을 쓸지” 결정하는 단계이다.

### 선별 기준
- 최신성
- 영향도
- 검색어와의 관련성
- 독자 관심도
- 비교 가능성
- 실무적 의미

### 처리 내용
- 핵심 뉴스 Top N 선정
- 회사별 주요 이슈 정리
- 공통 경쟁 포인트 도출
- 블로그 핵심 메시지 정의

### 출력 예시
```json
{
  "selected_news": [
    {
      "id": "news_001",
      "reason_selected": "OpenAI의 최신 전략 변화를 보여줌",
      "key_takeaway": "기업용 AI 확장 전략이 강화되고 있음"
    }
  ],
  "comparison_points": [
    "모델 업데이트 방향",
    "제품 전략",
    "생태계 확장",
    "기업용 활용성"
  ],
  "main_message": "이번 경쟁의 핵심은 단순 모델 성능이 아니라 생태계와 제품화 속도에 있다."
}
```

### 체크포인트
- 뉴스 선별 이유가 설명 가능한가
- 비교 축이 명확한가
- 본문에 들어갈 핵심 메시지가 정의되었는가

### 실패 위험
- 뉴스는 많지만 글의 중심 메시지가 없음
- 회사 비교 기준이 불명확함
- 독자 입장에서 왜 중요한지 빠짐

---

## 5.5 5단계: 블로그 콘텐츠 생성

### 목적
선별된 뉴스와 비교 포인트를 바탕으로 블로그용 콘텐츠를 생성한다.

### 역할
실제 독자가 읽을 결과물을 만드는 핵심 단계이다.

### 입력
- 구조화된 입력 정보
- 정리된 뉴스 데이터셋
- 핵심 뉴스 선별 결과
- 비교 포인트
- 작성 톤
- 출력 형식 요구사항

### 출력 항목
1. 제목 5개
2. 메타 설명
3. 3줄 요약
4. 블로그 본문
5. 비교 표
6. HTML 강조 문장
7. 해시태그
8. 이미지 프롬프트
9. 영상 프롬프트

### 본문 생성 기본 구조
1. 도입
2. 최신 뉴스 핵심 요약
3. OpenAI 동향
4. Google 동향
5. 경쟁 구도 비교
6. 실무적 의미
7. 결론

### 체크포인트
- 제목 5개가 충분히 다변화되었는가
- 메타 설명이 검색 친화적인가
- 3줄 요약만 읽어도 흐름이 보이는가
- 본문이 단순 기사 나열이 아닌가
- 비교 표가 본문과 일관되는가
- 실무적 의미가 포함되는가

### 실패 위험
- 본문이 요약문 수준에서 끝남
- 독자 대상과 맞지 않는 난이도
- 비교표가 형식적이거나 부실함
- 이미지/영상 프롬프트가 추상적임

---

## 5.6 6단계: HTML 렌더링

### 목적
생성된 블로그 콘텐츠를 티스토리 업로드에 적합한 HTML 구조로 변환한다.

### 역할
콘텐츠를 게시 가능한 형태로 정리하는 단계이다.

### 입력
- 블로그 콘텐츠 초안
- HTML 템플릿 기준
- 스타일 가이드

### 기본 스타일 가이드
- 강조색: `#FF6B6B`
- 배경색: `#E8F5F0`
- 박스색: `#E3F2FD`
- 테두리: `#4A90E2`

### 변환 대상
- 제목 구조
- 요약 박스
- 소제목
- 문단
- 비교 표
- 강조 박스
- 마무리 섹션

### 출력 예시 구조
```html
<h1>제목</h1>
<div class="summary-box">3줄 요약</div>
<h2>최근 AI 경쟁 구도 한눈에 보기</h2>
<p>본문 단락...</p>
<table>...</table>
<div class="highlight-box">핵심 강조 문장</div>
```

### 체크포인트
- 티스토리 붙여넣기에 적합한가
- 문단 구조가 명확한가
- 강조 박스와 표가 깨지지 않는가
- 과도한 외부 의존성이 없는가

### 실패 위험
- HTML 구조가 복잡함
- 티스토리 편집기에서 깨짐
- 본문과 HTML 구조가 일치하지 않음

---

## 5.7 7단계: 검수 및 저장

### 목적
최종 결과물이 기준 문서와 요구사항을 만족하는지 확인하고 저장한다.

### 역할
품질을 고정하는 마지막 단계이다.

### 검수 항목
- 제목 5개 존재 여부
- 메타 설명 존재 여부
- 3줄 요약 존재 여부
- 본문 구조 적합성
- 비교 표 존재 여부
- HTML 강조 문장 존재 여부
- 해시태그 10개 여부
- 이미지 프롬프트 5개 여부
- 영상 프롬프트 1개 여부
- 사실성 문제 여부
- 불확실한 내용 표시 여부

### 저장 경로 예시
- `outputs/html/`
- `outputs/markdown/`
- `outputs/json/`

### 파일 예시
- `2026-07-04_openai-google-genai_blog.html`
- `2026-07-04_openai-google-genai_summary.md`
- `2026-07-04_openai-google-genai_sources.json`

### 체크포인트
- 파일명 규칙을 지켰는가
- 저장 포맷이 맞는가
- 로그에 기록할 변경 사항이 있는가

---

## 6. 단계 간 입력/출력 연결 구조

파이프라인은 아래처럼 연결된다.

```text
[사용자 입력]
   ↓
[뉴스 수집]
   ↓
[뉴스 정리 및 정규화]
   ↓
[핵심 뉴스 선별 및 해설 포인트 도출]
   ↓
[블로그 콘텐츠 생성]
   ↓
[HTML 렌더링]
   ↓
[검수 및 저장]
```

---

## 7. 중간 산출물 정의

자동화 품질을 높이기 위해 각 단계별 중간 산출물을 남긴다.

| 단계 | 중간 산출물 | 저장 권장 위치 |
|------|-------------|----------------|
| 입력 정의 | 입력 요약 JSON | `data/test_inputs/` |
| 뉴스 수집 | 뉴스 후보 목록 | `data/sources/` |
| 뉴스 정리 | 정규화 데이터 | `data/curated_news/` |
| 핵심 선별 | 핵심 뉴스 선정 결과 | `outputs/json/` |
| 콘텐츠 생성 | Markdown 초안 | `outputs/markdown/` |
| HTML 렌더링 | HTML 결과물 | `outputs/html/` |

- 검색어 입력
- 주제 초점 결정
- 최종 결과 승인

- 블로그 초안 생성
- 비교표 및 프롬프트 생성

### 8.3 Codex 역할
- 폴더/파일 생성
- 중간 데이터 저장
- 템플릿 파일 수정
- HTML/CSS 파일 관리
- 자동화 스크립트 초안 반영

## 9. 모델 비교를 위한 파이프라인 고정 규칙

GPT / Claude / Gemini를 비교할 때는 아래를 동일하게 유지한다.

1. 동일 검색어 사용
2. 동일 뉴스 후보 목록 사용
3. 동일 정규화 데이터 사용
4. 동일 출력 요구사항 사용
5. 동일 HTML 구조 요구사항 사용
6. 동일 검수 체크리스트 사용

이 규칙을 지키지 않으면 비교 공정성이 떨어진다.

## 10. 검증 루프 설계

이 프로젝트는 한 번 생성하고 끝내지 않고, 검증 루프를 포함한다.

### 10.1 1차 검증
뉴스 수집 결과 검토
- 최신성 확인
- 중복 여부 확인
- 출처 신뢰성 확인

### 10.2 2차 검증
콘텐츠 초안 검토
- 본문 구조 적합성
- 실무적 의미 포함 여부
- 비교 논리 적합성

### 10.3 3차 검증
HTML 결과 검토
- 가독성
- 티스토리 호환성
- 강조 요소 활용도

### 10.4 개선 루프
검수 결과 미흡 시 아래 단계로 되돌린다.
- 뉴스가 약하면 2단계로 복귀
- 비교 포인트가 약하면 4단계로 복귀
- 본문 품질이 낮으면 5단계 재생성
- HTML 품질이 낮으면 6단계 재작업

## 11. 실패 지점과 대응 방안

| 실패 지점 | 문제 설명 | 대응 방안 |
|-----------|-----------|-----------|
| 뉴스 수집 | 오래된 기사 포함 | 날짜 필터 강화 |

| HTML 변환 | 에디터 호환성 문제 | 단순 구조 우선 적용 |
| 최종 검수 | 사실성 오류 누락 | 체크리스트 기반 검수 고정 |

## 12. 자동화 성숙도 단계

이 프로젝트의 파이프라인은 한 번에 완전 자동화하는 것이 아니라 단계적으로 성숙시킨다.

### Level 1. 수동 보조형
- 사람이 뉴스 후보를 제공
- AI가 정리 및 블로그 생성

### Level 2. 반자동형
- 뉴스 수집 일부 자동화
- 중간 정규화 자동화
- 사람이 핵심 뉴스 선별 검토
- AI가 본문 및 HTML 생성

### Level 3. 구조화 자동화형
- 뉴스 수집
- 뉴스 정리
- 핵심 포인트 도출
- 블로그 초안 생성
- HTML 렌더링
- 저장 및 로그 기록까지 자동화
- 사람은 최종 승인만 수행

### Level 4. 에이전트형 확장
- 입력 해석
- 뉴스 탐색
- 출처 우선순위 판단
- 품질 자가 검수
- 초안 개선 루프
- 플랫폼 맞춤 출력까지 연계

현재 프로젝트는 **Level 1 ~ Level 2 사이**를 목표로 한다.

## 14. 파이프라인 운영 시 주의사항

### 14.1 최신성은 별도 검증이 필요하다
모델이 생성한 문장만으로 최신성을 보장할 수 없다.  
반드시 뉴스 수집 단계와 출처 확인 단계가 선행되어야 한다.

### 14.2 기사 요약과 해설을 혼동하지 않는다
기사 요약은 사실 전달이고, 해설은 의미 설명이다.  
본문 생성 단계에서는 이 둘을 구분해서 작성해야 한다.

### 14.3 비교는 억지로 만들지 않는다
OpenAI와 Google을 비교하더라도, 같은 기준에서 비교 가능한 내용만 비교해야 한다.  
근거 없는 우열 비교는 금지한다.

### 14.4 HTML은 단순할수록 좋다
초기에는 화려한 구조보다 티스토리에서 안정적으로 붙여넣기 가능한 단순 구조를 우선한다.

### 14.5 중간 산출물을 버리지 않는다
뉴스 후보 목록, 정규화 데이터, 초안, HTML 결과물은 모두 남겨야 한다.  
그래야 품질 문제 발생 시 어느 단계에서 문제가 생겼는지 추적할 수 있다.
