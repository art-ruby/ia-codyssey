# AI 뉴스 블로그 자동화 과제 최종 제출 본문

이 문서는 평가 기준 15개 항목이 제출 텍스트 본문 안에서 바로 확인되도록 정리한 최종 답안이다.

## 평가기준 1. 업무 과업 정의

업무 과업은 AI 기술 뉴스 기사를 입력하면 블로그 게시용 콘텐츠 패키지를 자동 생성하고, ChatGPT, Claude, Gemini 3종 모델 결과를 비교해 최종 게시 모델을 선정하는 것이다.

- 타겟 사용자: 1인 창업자, AI 콘텐츠 제작자, 기술 블로그 운영자
- 입력 규격: 기사 제목, 기사 본문, 원문 URL, 출처명, 확인일, 타겟 독자, 게시 플랫폼, 확인된 사실, 확인 필요 주장
- 출력 규격: 핵심 주제, 제목 후보, 썸네일 문구, SEO 메타 설명, 이미지 프롬프트 3개, Sora 영상 프롬프트, 해시태그 10개 이상, 마크다운 패키지, 게시 가능한 HTML, 사실 확인 필요 항목

## 평가기준 4. Few-shot 예시 및 되묻기

### Few-shot 1: 충분한 기사 입력

입력:

```text
Hermes Agent는 Nous Research가 공개한 오픈소스 AI 에이전트 프레임워크다. 대화가 쌓일수록 메모리를 유지하고 반복 작업을 재사용 가능한 스킬로 정리한다. 공식 저장소는 MIT License를 사용한다.
```

기대 출력:

```text
[기사 핵심 주제]
지속적 메모리를 가진 Hermes Agent의 운영 방식

[사실 확인 필요 항목]
- 개인 사례는 전체 제품 성능 보장으로 일반화하지 않는다.
- GitHub 스타 수와 설치 명령은 게시 직전 공식 문서로 재확인한다.
```

### Few-shot 2: 사실과 해석이 섞인 기사

입력:

```text
Hermes는 OpenClaw보다 무조건 빠르다. hermes claw migrate 명령으로 모든 설정과 API 키를 자동 이전한다. $5 VPS만 있으면 추가 비용 없이 운영된다.
```

기대 출력:

```text
[사실 확인 필요 항목]
- "무조건 빠르다"는 검증되지 않은 비교 표현이다.
- hermes claw migrate는 존재하지만 API 키 이전에는 별도 옵션과 수동 검토가 필요하다.
- $5 VPS는 실행 가능성 안내이며 전체 운영비 보장이 아니다.
```

### Few-shot 3: 모호하거나 정보가 부족한 입력과 되묻기

입력:

```text
Hermes Agent가 요즘 화제라고 합니다. OpenClaw보다 좋다고 하네요.
```

기대 출력:

```text
===INPUT_REQUIRED===
뉴스 기사 내용이 부족해 핵심 변화와 확인 가능한 사실을 파악하기 어렵습니다. 기사 본문, 제품 기능, 비교 근거와 출처 요약을 추가로 제공해 주세요.
===INPUT_REQUIRED_END===
```

모델 비교는 사실 정확성, 입력 충실도, 형식 준수, 콘텐츠 구조, 한국어 가독성, HTML 완성도, 이미지/영상 연계, 운영 편의성의 8개 축으로 구조화했다. 4개 이상의 평가 축을 사용했고, 각 모델에 점수와 근거를 부여했다.

## 평가기준 10. 환각의 정의 설명

이 과제에서 환각은 입력 기사와 공식 출처로 확인되지 않은 사실을 확정적으로 생성하는 것이다. 예를 들어 존재가 확인되지 않은 모델명, 변동 수치, 비용 보장, API 키 자동 이전 같은 주장을 사실처럼 쓰면 환각이다.

창의적 생성은 제목 후보, 썸네일 문구, 이미지 프롬프트, 문체 조정처럼 사실 주장과 분리되는 영역이다. 제품 기능, 라이선스, 설치 명령, 가격, 성능 비교는 사실 영역이므로 임의 생성하면 안 된다.

## 평가기준 11. 환각 검증 판정 기준 설명

| 판정 | 기준 |
|---|---|
| Pass | 공식 출처 또는 입력 기사와 일치하고 조건을 정확히 설명함 |
| Pass-safe | 위험 주장을 반복하지 않거나 확인 필요로 분리함 |
| Fail | 공식 확인이 불가능하거나 틀린 내용을 확정 사실처럼 생성함 |
| 확인 필요 | 현재 자료만으로 확정할 수 없어 게시 전 추가 검증이 필요함 |

## 평가기준 12. 모델 선정 이유와 과업 연결

최종 모델은 ChatGPT 5.5다. 총점 86.5점으로 1위이고, AI 뉴스 블로그 자동화 과업에서 중요한 사실성, HTML 이식성, 구조 안정성, 누적 조건 유지가 가장 균형적이었다. 위험 수치를 보수적으로 처리하고, 인라인 HTML 구조가 안정적이며, 11턴 수정 과정에서 독자층과 문체와 수치 검증 조건을 유지했다.

## 평가기준 13. 심층 인터뷰 답변: 비용 제약 시 전략

무료 또는 저비용 모델만 써야 하면 한 번에 완성본을 만들지 않고 프로세스를 나눈다.

1. 사실 검증 단계와 글쓰기 단계를 분리한다.
2. 공식 확인된 사실과 확인 필요 주장을 입력 템플릿에 미리 나눈다.
3. 긴 원문은 핵심 사실, 금지 표현, 출처 요약으로 압축한다.
4. 이미지 생성은 최종 선정 모델 결과에만 적용한다.
5. 무료 모델 결과는 환각 검증표를 통과한 뒤 게시한다.

## 평가기준 14. 심층 인터뷰 답변: 잦은 정책 변경 시 전략

업무 정책이나 제품 정보가 자주 바뀌면 다음 운영 전략을 사용한다.

1. 변동 수치는 항상 “확인일 기준”으로 표시한다.
2. 설치 명령, 가격, 지원 OS, 라이선스, 모델명은 게시 직전 공식 문서로 재확인한다.
3. 정책 변경 가능성이 큰 항목은 본문 단정문이 아니라 “확인 필요” 섹션에 분리한다.
4. 프롬프트에 “최신성 불확실 항목은 확정하지 말라”는 규칙을 넣는다.
5. 변경된 정책은 입력 템플릿의 `[사실 검증]` 블록에 먼저 반영한다.

## 평가기준 15. 심층 인터뷰 답변: 문맥 끊김 해결

10턴 이상 대화에서 문맥이 끊기는 문제는 프롬프트 구조로 해결한다.

1. 매 턴 유지해야 할 조건을 짧게 재명시한다.
2. 독자층, 문체, 금지 표현, HTML 형식, 이미지 위치를 고정 조건으로 둔다.
3. 최종 생성 전 누적 조건 체크리스트를 만들게 한다.
4. 긴 대화 후에는 전체 재생성을 요청한다.
5. 마지막 턴에서 조건별 Pass/Fail 검증을 수행한다.
6. `MARKDOWN_START`, `HTML_START` 같은 출력 구분자를 사용해 문맥과 형식이 섞이지 않게 한다.
