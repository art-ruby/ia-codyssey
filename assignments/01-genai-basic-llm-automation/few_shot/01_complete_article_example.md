# Few-shot 1 — 충분한 기사 입력

## 예시 유형

충분한 기사 입력

## 목적

뉴스 기사 원문에 제품, 개발 주체, 기능, 사례, 비교 대상, 활용법, 설치 정보와 출처가 충분히 포함되었을 때 모델이 별도 질문 없이 마크다운 콘텐츠 패키지와 완결형 HTML을 생성하는지 확인한다.

## 사용자 입력 예시

```text
[뉴스기사]

Hermes Agent는 Nous Research가 공개한 오픈소스 AI 에이전트 프레임워크다. 대화가 쌓일수록 메모리를 유지하고, 반복 작업을 재사용 가능한 스킬로 정리하는 구조를 특징으로 내세운다.

Nick Spisak의 X 아티클은 한 핀테크 창업자가 마케팅, SDR, 엔지니어링, 커뮤니티, 브리핑 에이전트 5개를 운영하다 48시간 만에 실패한 사례를 소개한다. 원문은 에이전트끼리 컨텍스트를 공유하지 못해 브랜드 보이스와 작업 방식이 서로 달라진 것을 원인으로 설명한다.

이후 다섯 역할을 Hermes Agent 하나로 통합하자 마케팅에서 쌓인 표현이 아웃리치에도 반영되고, 커뮤니티 피드백이 다음 콘텐츠에 연결됐다고 설명한다.

Hermes Agent의 주요 기능으로는 지속적 메모리, 자동 스킬 생성, 멀티플랫폼 메시징, 크론 스케줄링, MCP 서버 연동이 소개된다.

OpenClaw와 비교하면 Hermes는 반복 경험을 축적하는 단일 운영자형 에이전트, OpenClaw는 다양한 도구를 연결하는 플랫폼형 도구로 설명된다. 이는 원문 작성자가 제시한 비교 관점이다.

공식 저장소는 MIT License를 사용한다. 2026년 7월 6일 GitHub 화면 기준 스타 수는 약 21만 개다. 공식 README는 Linux, macOS, WSL2, Termux와 네이티브 Windows 설치를 안내한다.

Linux, macOS, WSL2, Termux 설치 명령:
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

원문:
- GPTERS 분석 글
- Nick Spisak X 아티클
- Hermes Agent 공식 GitHub와 문서
```

## 기대 출력 예시

```text
===MARKDOWN_START===
[기사 핵심 주제]
분리된 여러 에이전트의 컨텍스트 단절 문제와 지속적 메모리를 가진 단일 Hermes Agent의 운영 방식

[사실 확인 필요 항목]
- 5개 에이전트가 48시간 만에 실패했다는 내용은 Nick Spisak이 소개한 개인 사례다.
- OpenClaw와의 성능 비교는 양쪽 공식 문서를 기준으로 추가 확인이 필요하다.

(제목, 이미지 프롬프트 3개, Sora 프롬프트, 내레이션, 자막, SEO, 해시태그 계속)
===MARKDOWN_END===
===HTML_START===
<!DOCTYPE html>
<html lang="ko">
...
</html>
===HTML_END===
```

## 기대 동작

- 별도 확인 질문 없이 콘텐츠 패키지 생성
- 마크다운과 HTML을 지정 구분자로 분리
- 대표 이미지 프롬프트와 alt 텍스트 각각 3개
- Sora 2 프롬프트, 내레이션, 자막 포함
- 해시태그 10개 이상
- 개인 사례와 비교 평가는 출처에 귀속
- HTML은 완결형이며 인라인 CSS 사용

## Pass 기준

- 필수 결과물이 모두 생성된다.
- 공식 확인 사실과 개인 사례를 구분한다.
- 기사에 없는 기능이나 성과를 추가하지 않는다.

## Fail 기준

- 충분한 입력인데 불필요한 확인 질문만 출력한다.
- 개인 사례를 일반적인 성능 보장으로 바꾼다.
- 마크다운 또는 HTML 중 하나를 누락한다.
