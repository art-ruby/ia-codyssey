# AI Secretary — MVP PRD

- 문서 상태: 검토 가능한 초안 v0.1
- 작성일: 2026-10-01
- 작업 위치: `M1-2`
- 기준: [사용자 시나리오](ai-secretary/AI_SECRETARY_SCENARIO.md), [M1-2 과제](m1-2.md)
- 참고 화면: [단일 파일 목업](mockup/index.html)

## 1. 목적과 이번 버전의 성공 경험

사용자가 발견한 AI 자료를 저장한 이유와 함께 보관하고, 나중에 출처를 확인하며 다시 찾을 수 있는 개인용 웹 비서를 만든다.

MVP의 핵심 경험은 다음과 같다.

> 자료의 제목·본문·출처·저장 이유를 입력한다. 비서가 요약과 분류를 제안하면 내가 고쳐서 보관한다. 며칠 뒤 질문하면 저장한 자료와 내 메모를 근거로 답하고, 이전 대화도 다시 볼 수 있다.

개발 완료는 화면 표시만으로 판단하지 않는다. 실제 Firestore 저장, GPT API 답변, 자료 수정·삭제, 대화 재조회, 배포 주소 접속까지 검증한다.

## 2. 확정된 방향과 초안의 제안

### 기존 대화에서 정한 방향

- 개인 비서의 작업과 문서는 `M1-2`에서 관리한다.
- 이번 버전은 간단한 MVP이며 M1-2 과제 필수 기능을 충족한다.
- 초기 100건 이상은 검증용 표본 데이터로 준비한다.
- 화면 목업은 `mockup/index.html` 한 파일로 유지한다. 실제 서비스의 프론트엔드·백엔드 파일 구성에는 이 제약을 적용하지 않는다.
- 사용자가 최종 보관 여부를 정하고 AI의 제안을 수정할 수 있다.

### 이 초안에서 제안하는 기본값

| 결정 항목 | 제안 | 이유 |
|---|---|---|
| 사용자 | 허용된 본인 계정 1개 | 개인용 서비스에 맞추고 역할·회원 관리 범위를 줄인다. |
| 입력 | 제목, 직접 붙여 넣은 텍스트, 출처 URL, 저장 이유 | 외부 콘텐츠 접근 실패에 의존하지 않고 핵심 경험을 검증한다. |
| 시계열 수치 | 자료별 사용자 중요도 1~5점 | 과제의 `date, value, memo`를 자료 관리 경험과 연결한다. |
| 초기 데이터 | 28일에 걸친 표본 자료 100건 | 기간·기본 통계·최근 변화·검색을 재현 가능하게 검증한다. |
| 검색 | 보관일·키워드·분류·프로젝트 기준 | 작은 자료 규모에서 검색 범위와 결과를 설명하기 쉽다. |

위 기본값은 개발 범위를 구체화하기 위한 제안이다. 특히 중요도 점수는 외부 인기나 사실의 신뢰도를 측정하지 않으며, 사용자의 주관적 평가를 기록한다.

## 3. 구현 범위

### MVP 필수 기능

| ID | 기능 | 이번 버전의 동작 |
|---|---|---|
| F01 | 본인 로그인 | 허용된 계정으로 로그인하고 PC·모바일에서 같은 자료를 조회한다. |
| F02 | 자료 접수·관리 | 텍스트와 메타데이터를 입력하고 목록 조회·수정·삭제한다. |
| F03 | 요약·분류 제안 | 입력된 본문을 바탕으로 짧은 요약, 분류, 프로젝트 관련 이유를 제안한다. |
| F04 | 검토·보관 | 제안을 수정한 뒤 보관하거나 나중에 보기로 남긴다. |
| F05 | 자료 검색 | 보관일·키워드·분류·프로젝트로 보관 자료를 찾는다. |
| F06 | 자료 기반 대화 | 통계 요약과 검색한 자료를 참고해 답하고 출처를 표시한다. |
| F07 | 대화 기록 | 대화를 자동 저장하고 목록 조회·불러오기·삭제한다. |
| F08 | 데이터 요약 | 자료 수, 기간, 사용자 중요도 평균·최대·최소·최근 변화를 표시한다. |
| F09 | 프로젝트 설정 | 프로젝트 이름·설명·관심 키워드를 등록·수정한다. |
| F10 | 배포·문서 | Vercel 프론트, Render 백엔드, Swagger UI, 실행 안내와 제출 증거를 준비한다. |

### 후속 단계

Telegram 전달·승인, 외부 뉴스·SNS 자동 수집, 예약 브리핑, YouTube 자막 자동 취득, PDF·이미지 분석, 스크린샷 묶음 정리, Downloads 감시·이동·삭제, Obsidian 연동, 의미 기반 자동 연결, 사용자 취향 자동 학습은 MVP 완료 조건에 포함하지 않는다.

URL은 출처를 기록하고 사용자가 원문을 여는 용도로 사용한다. MVP 서버는 URL 본문을 자동으로 가져오지 않는다. 동일 URL의 기존 자료는 보여줄 수 있지만 중복을 이유로 자동 병합·삭제하지 않는다.

## 4. 사용자 흐름과 화면

1. 로그인 후 `표본 자료` 또는 `내 자료`를 선택한다. 두 데이터 모드를 화면 상단에 명시한다.
2. 필요한 경우 프로젝트 이름, 설명, 관심 키워드를 등록한다. 프로젝트 없이도 사용할 수 있다.
3. 받은 자료 화면에서 제목·보관일·중요도·저장 이유를 입력하고, 본문과 출처를 추가한다.
4. 접수 즉시 Inbox에 저장한다. 본문이 있으면 사용자가 `요약 제안 받기`를 누른다.
5. 요약·분류·프로젝트 제안을 확인하고 수정한 뒤 `보관` 또는 `나중에 보기`를 선택한다.
6. 지식 보관함에서 자료를 찾거나 비서에게 질문한다. 답변에서 근거 자료를 열 수 있다.
7. 새로고침 또는 재로그인 후에도 자료와 이전 대화를 다시 조회한다.

| 메뉴 | 주요 내용 | 기존 목업 정리 방향 |
|---|---|---|
| 오늘 | 선택한 데이터 모드의 통계 요약과 Inbox 건수 | 자동 뉴스 브리핑 대신 내 자료 현황을 표시한다. |
| 받은 자료 | 입력, 분석 제안, 검토, 나중에 보기 | 검토·승인 화면을 통합한다. |
| 지식 보관함 | 검색, 상세 보기, 수정·삭제 | 실제 저장 데이터와 연결한다. |
| 비서에게 묻기 | 질문, 응답 대기, 답변, 근거 자료 | 같은 화면에서 현재 통계 요약도 확인한다. |
| 대화 기록 | 목록, 불러오기, 삭제 | 실제 저장된 대화를 표시한다. |
| 프로젝트·설정 | 프로젝트 정보, 데이터 모드, 로그아웃 | 본인이 관리한다. 별도 관리자 계정은 만들지 않는다. |

왼쪽 세로 메뉴를 클릭하면 오른쪽 내용이 바뀐다. 모바일에서는 메뉴를 접어 표시한다. 현재 목업의 AI 동향·스크린샷·Downloads 메뉴는 후속 기능이므로 MVP 화면 정리 시 제외한다. 이 PRD 작성 단계에서는 목업 파일을 변경하지 않는다.

## 5. 저장할 자료와 상태

### 자료 1건

| 필드 | 의미·규칙 |
|---|---|
| `id`, `owner_id` | 고유 자료 ID와 서버가 확인한 소유자 |
| `dataset` | `sample` 또는 `personal`; 표본과 개인 자료를 분리한다. |
| `title` | 필수 제목, 1~200자 |
| `date` | 사용자가 지정한 자료 보관일, 기본값은 한국 시간 오늘, 미래 날짜 불가 |
| `value` | 사용자가 선택하는 중요도 1~5 정수; AI가 임의로 확정하지 않는다. |
| `memo` | 저장하려는 이유 또는 활용 계획, 필수 1~1,000자 |
| `content` | 직접 붙여 넣은 본문 또는 발췌, 선택 입력, 최대 12,000자 |
| `source_url`, `source_type` | 선택 입력한 HTTP(S) 출처와 자료 종류; 출처 없음도 허용 |
| `status` | `inbox`, `saved`, `later` |
| `category`, `project_id` | 최종 분류와 선택한 프로젝트; 분류 기본값은 `미분류` |
| `summary`, `suggestion` | 사용자가 확정한 요약과 별도로 보존하는 AI 제안 |
| `analysis_status`, `analysis_version` | 미분석·완료·실패·재분석 필요와 분석에 사용한 자료 버전 |
| `created_at`, `updated_at`, `version` | 실제 생성·변경 시각과 자료 변경 버전 |

중요도 기준은 1점 ‘관심 낮음’, 2점 ‘참고 가능’, 3점 ‘다시 볼 가치 있음’, 4점 ‘현재 작업에 도움’, 5점 ‘현재 작업에 우선 확인 필요’로 제시한다. 게시일은 이 MVP의 통계 날짜로 사용하지 않는다.

분류는 `개념·학습`, `도구·서비스`, `구현 사례`, `정책·운영`, `미분류` 중 하나다. 프로젝트 정보는 소유자·데이터 모드별로 이름, 설명, 키워드를 저장한다. 프로젝트 삭제는 MVP에서 제공하지 않아 연결이 끊기는 처리를 늘리지 않는다.

### 보관과 분석의 규칙

- 접수는 임시 저장이다. `보관`을 눌러 `saved`가 되어야 지식 보관함·통계·AI 자료 검색에 포함한다.
- 자료의 데이터 모드는 생성할 때 정하고 이후 변경하지 않는다. 표본을 개인 자료로 자동 전환하지 않는다.
- `inbox`와 `later`는 받은 자료 화면에서 조회한다. 자동 만료·삭제하지 않으며 언제든 수정·보관·삭제할 수 있다.
- 본문이 없으면 ‘본문 미확인’으로 표시하고 AI 본문 요약을 실행하지 않는다. 제목·출처·내 메모를 가진 북마크로 보관할 수 있다.
- 분석 실패 후에도 입력은 유지한다. 다시 분석하거나 직접 분류·요약을 작성해 보관할 수 있다.
- AI 재분석은 새 제안만 만든다. 사용자가 확정한 요약·분류·프로젝트를 덮어쓰지 않는다.
- 분석 대상 내용이 바뀌면 기존 제안을 ‘재분석 필요’로 표시한다. 이미 보관한 자료는 사용자가 요약을 다시 확인할 때까지 기존 요약을 새 질문의 근거로 사용하지 않는다.
- 자료 삭제 시 삭제 대상을 확인한다. 서비스에 저장한 해당 자료만 삭제하며, 기기의 원본 파일과 과거 대화는 별개임을 안내한다.

## 6. 표본 100건과 시계열 요약

### 표본 데이터

100건을 생성 기준일 직전 28일에 걸쳐 서로 다른 날짜·중요도·주제로 구성한다. 일부 날짜에는 여러 건을 배치하고 일부 날짜는 비워 기간 비교를 검증한다. 초기 표본은 `sample`, `saved` 상태다.

표본의 제목·본문·요약·저장 이유·프로젝트는 검증용으로 작성한다. 실재 기사나 검증된 뉴스처럼 표시하지 않으며 실제로 확인하지 않은 URL을 만들어 넣지 않는다. 표본 화면과 표본 기반 답변에는 ‘검증용 표본’을 표시한다.

데이터 준비 시 GPT API를 100번 호출하지 않는다. 표본은 미리 작성한 데이터로 주입하고, 실제 API 분석은 별도의 소수 입력으로 검증한다. 표본 주입은 서버 측 준비 명령으로 제공하고 재실행해도 같은 표본 ID를 중복 생성하지 않는다. 개인 자료는 변경하지 않는다.

### 통계 정의

선택한 소유자·데이터 모드의 `saved` 자료 전체를 대상으로 서버에서 계산한다. 목록 화면의 페이지 크기나 검색어 때문에 통계 모집단이 달라지지 않는다.

- 기간: 가장 이른 보관일과 가장 늦은 보관일.
- 개수: 보관 자료 수.
- 기본 통계: 중요도 평균·최대·최소. 평균은 표시할 때 소수점 1자리로 반올림한다.
- 최근 변화: 기준일 D를 가장 늦은 보관일로 잡고, 최근 7일 `D-6~D`와 이전 7일 `D-13~D-7`의 자료별 중요도 평균을 비교한다. 비교 기간을 함께 표시한다.
- 반올림 전 평균 차이가 0.5점 이상이면 ‘상승’, -0.5점 이하이면 ‘하락’, 그 사이면 ‘유지’다. 어느 한쪽에 자료가 없으면 ‘비교 자료 부족’이다.
- 자료가 0건이면 개수 0, 기간과 수치 지표는 `null`, 추세는 ‘자료 없음’으로 반환한다. 자료가 없는 기간의 중요도를 0점으로 계산하지 않는다.

이 추세는 최근 보관한 자료에 사용자가 높은 점수를 주었는지를 뜻한다. AI 산업의 성장, 외부 화제성, 사용자의 생산성 추세로 해석하지 않는다. 개인 중요도 평균은 편의상 요약하는 지표이며 정밀한 객관적 측정값으로 제시하지 않는다.

## 7. AI 분석·검색·대화 규칙

### 요약·분류

본문과 사용자가 등록한 프로젝트 설명을 근거로 3문장 이내 요약, 분류 1개, 관련 프로젝트 최대 1개와 이유를 제안한다. 적절한 프로젝트가 없으면 미지정을 허용한다. 확인 범위는 ‘사용자가 입력한 본문/발췌’로 표시한다.

### 검색과 답변

- 기본 검색 대상은 선택한 데이터 모드의 보관 자료다. 제목·본문·메모·분류·프로젝트 이름의 키워드와 보관일 범위를 사용한다.
- 질문은 공백을 제외하고 1~2,000자로 제한한다. 질문이나 검색 조건을 바꾸면 새로운 요청으로 처리한다.
- 첫 버전은 작은 자료 집합을 서버에서 필터링한다. 소유자·모드별 보관 자료는 최대 500건까지 지원하고 초과 보관 시 안내한다. 전체 검색 가능한 범위를 임의의 최신 일부로 축소하지 않는다.
- 자연어 질문에서 검색어와 기간을 추출할 수 있지만 서버가 허용된 조건인지 검증한다. 검색에 적용한 기간과 키워드를 답변 옆에 표시하고 사용자가 수정할 수 있게 한다.
- ‘지난달’은 한국 시간 현재 날짜를 기준으로 한 지난 달력월의 보관일이다. 통계의 기준일 D와 혼동하지 않도록 각각 표시한다.
- 질문마다 6절의 통계 요약과 관련 자료 최대 5건을 문맥으로 제공한다. 자료 본문 총량은 12,000자 이내로 제한하고 발췌·생략 여부를 표시한다. 과거 대화는 최근 6개 메시지만 문맥으로 사용한다.
- 반환하는 출처 ID는 실제 제공한 자료 목록에 포함되는지 서버에서 검사한다. 출처에는 제목·보관일·확인 범위·자료 상세 링크와 존재하는 경우 원문 URL을 표시한다.
- 제목과 메모만 있는 자료는 해당 정보까지만 답변 근거로 사용한다. 본문 내용에 관한 단정은 하지 않는다.
- 관련 자료가 없으면 검색 범위에서 찾지 못했다고 안내하고 검색 조건 변경을 제안한다. 검색 장애는 ‘검색 실패’로 구분한다.
- 통계 수치는 서버 계산값을 사용한다. 외부 최신 정보나 근거 없는 자료 내용을 보충하지 않는다.
- 사용자가 수정한 자료와 프로젝트 설정은 다음 요청에서 다시 읽는다. 자동 모델 학습이나 장기적인 취향 추론은 수행하지 않는다.

### 대화 보존

새 대화는 데이터 모드에 묶이며 모드를 바꾸면 새 대화를 시작한다. 메시지에는 역할·본문·시각·참고 자료 ID·사용한 통계 요약의 스냅샷을 저장한다. 대화 목록에는 제목과 최근 변경 시각을 표시한다.

답변은 저장 성공 후 완료 상태로 표시한다. 저장 실패 시 ‘대화 저장 실패’를 안내하며 성공처럼 처리하지 않는다. 같은 요청을 다시 보내도 질문·답변 쌍을 중복 저장하지 않도록 요청 ID를 사용한다.

자료를 삭제해도 과거 대화는 당시 기록으로 남는다. 해당 출처에는 ‘삭제된 자료’를 표시한다. 삭제된 자료를 인용한 과거 메시지는 새 답변의 문맥에서 제외한다. 대화를 삭제하면 해당 대화의 메시지도 함께 삭제한다.

## 8. 기술·운영 조건

- 프론트엔드: HTML/CSS/JavaScript, 프레임워크 없이 구현하고 Vercel에 배포한다.
- 백엔드: Python 3.10 이상, FastAPI, Pydantic 검증, Render 배포. 라우터와 데이터·분석·대화 서비스를 구분한다.
- 저장: Firestore의 `data`, `conversations`, `projects`를 기본으로 한다. 대화의 메시지는 용량 증가를 고려해 개별 문서로 저장한다. 통계는 요청 시 계산하고 대화에는 사용한 요약을 저장한다.
- 인증: Firebase Authentication의 Google 로그인과 허용 UID 1개를 사용한다. 백엔드는 프로젝트를 포함한 모든 개인 데이터 API에서 토큰과 소유자를 확인한다. 브라우저의 직접 Firestore 접근은 차단한다. 개인 가입·관리자 역할 체계는 제공하지 않는다.
- 환경 설정: `OPENAI_API_KEY`, `OPENAI_MODEL`, `FIREBASE_SERVICE_ACCOUNT_JSON`, `ALLOWED_USER_UID`, `ALLOWED_ORIGINS`, `API_BASE_URL`을 문서화한다. 공개 Firebase 웹 설정은 비밀 키와 구분한다.
- 바닐라 프론트의 `API_BASE_URL`은 Vercel 빌드 과정에서 공개 설정 파일로 주입한다. 서버 전용 키는 프론트 산출물에 포함하지 않는다.
- AI 이용: 분석·질문 버튼을 누를 때 입력한 텍스트와 관련 저장 자료가 외부 AI에 전달됨을 안내한다. 이 통상 이용에 대해 매 요청마다 별도 승인창을 띄우지 않는다.
- 기본 제한: 사용자당 AI 호출 하루 50회, 동시 1회, 응답 출력 최대 800토큰. 제한값은 서버 설정으로 관리하고 한도 초과 시 명확히 안내한다. 실제 비용은 모델·입력량에 따라 달라지므로 호출 수를 금액 상한으로 설명하지 않는다.
- 실패 처리: AI 요청 제한시간은 30초, 자동 재시도는 하지 않는다. 접수·수정은 요청 ID와 버전 확인으로 중복 처리와 오래된 화면의 덮어쓰기를 막는다. AI 재요청은 사용자가 실행한다.
- 보안 경계: 외부 자료 본문은 분석할 데이터다. 그 안의 명령문으로 파일 작업·메시지 발송·임의 API 호출을 수행하지 않는다. 입력은 화면에서 안전하게 텍스트로 표시한다.
- 초기 서버 응답 지연 시 접속 대기 안내를 제공한다. CORS 허용 주소는 배포 프론트와 지정된 개발 주소로 제한한다.

## 9. 과제 필수 API와 기능 연결

| API | 역할 |
|---|---|
| `POST /api/data` | Inbox 접수 |
| `GET /api/data` | 소유자·데이터 모드·상태·검색 조건에 맞는 자료 목록 |
| `PUT /api/data/{id}` | 자료 수정과 상태 변경·보관 승인 |
| `DELETE /api/data/{id}` | 자료 삭제 |
| `GET /api/data/summary` | 6절의 통계 요약 |
| `POST /api/data/{id}/analyze` | 사용자가 요청한 요약·분류 제안 |
| `POST /api/chat` | 통계 요약과 관련 자료를 이용한 GPT 답변·자동 대화 저장 |
| `POST /api/conversations` | 새 대화 생성·저장; 소유자의 사용자·비서 메시지를 함께 저장하는 요청도 검증해 지원 |
| `GET /api/conversations` | 대화 목록 |
| `GET /api/conversations/{id}` | 선택한 대화와 전체 메시지 조회 |
| `DELETE /api/conversations/{id}` | 대화와 메시지 삭제 |
| `GET /api/projects`, `POST /api/projects`, `PUT /api/projects/{id}` | 프로젝트 조회·등록·수정 |

`POST /api/chat`은 `/api/data/summary`와 동일한 서버 계산 로직을 사용한다. 서버 내부에서 자기 HTTP 주소를 다시 호출할 필요는 없다. 별도 저장 버튼 없이 매 대화를 자동 저장한다. Swagger UI는 `/docs`에서 확인하고, 데이터 실행에는 인증이 필요하다.

## 10. 완료 기준과 검증 사례

| ID | 검증 | 통과 조건 |
|---|---|---|
| A01 | 표본 준비 | 표본 보관 자료가 100건이며, 준비 명령 재실행 후에도 중복되지 않는다. 개인 자료에 섞이지 않는다. |
| A02 | 실제 저장 | 자료를 입력하고 새로고침·재로그인하면 같은 항목이 조회된다. |
| A03 | 분석과 승인 | 입력 본문의 요약·분류 제안을 실제 GPT API로 받고 수정·보관한다. AI 실패 시 입력은 남는다. |
| A04 | 읽기 범위 | 본문 없는 URL 자료에서 본문 분석을 실행하지 않고 ‘본문 미확인’을 표시한다. |
| A05 | CRUD와 상태 | 수정·삭제가 목록에 반영되고, 승인 전 자료는 보관함·통계·AI 검색에 포함되지 않는다. |
| A06 | 통계 정확성 | 알려진 점수·날짜 표본으로 평균·최대·최소와 0건·비교 불가·상승·하락·유지를 검증한다. |
| A07 | 근거 기반 질문 | 고정된 검증 질문 10개 중 8개 이상에서 예상 관련 자료를 근거 목록에 포함한다. 없는 자료의 출처 ID는 0건이다. |
| A08 | 근거 없는 질문 | 의도적으로 관련 자료가 없는 질문 3개에서 모두 검색 범위 내 자료 부족을 안내한다. |
| A09 | 대화 기록 | 질문·답변·출처를 새로고침 후 불러오고, 삭제한 대화가 다시 조회되지 않는다. |
| A10 | 변경·실패 | 중복 클릭, 분석 실패, 저장 실패, 오래된 수정 요청, 삭제된 출처를 각각 구분해 처리한다. |
| A11 | 접근·기기 | 미로그인·허용되지 않은 계정은 API 데이터에 접근하지 못하고, 본인은 PC·모바일에서 같은 자료를 조회한다. |
| A12 | 배포·제출 | Vercel URL, Render API와 `/docs`가 접속되며 README와 필수 화면 증거가 있다. |

검증 질문과 기대 자료는 표본과 함께 고정해 준비한다. 별도로 직접 입력한 소수 자료로 실제 AI 분석·검색을 확인한다. ‘표본의 미리 작성된 답변만 표시’하는 것으로 AI 동작 검증을 대신하지 않는다.

README에는 서비스 목적, 기술 구성, 프론트·백엔드·Swagger URL, 로컬 실행, 환경 변수, 본인 로그인 설정, 표본 준비 방법, 지원 범위와 제한을 기록한다. 제출 화면은 통계가 보이는 질문·답변, 자료 CRUD 동작, 대화 불러오기 세 가지를 포함한다.
