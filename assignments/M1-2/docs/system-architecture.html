구성 요소별 역할

요청이 지나가는 순서대로 묶었습니다. 회색 꼬리표는 실제 주소·경로·설정 이름입니다.

화면과 로그인

Vercel · 웹 화면

ia-codyssey-web.vercel.appweb/

사용자가 보는 화면 전부를 내려줍니다.

  • 프레임워크 없는 HTML·CSS·JavaScript 정적 사이트입니다.
  • 빌드 때 공개 값 4개(API 주소, Firebase 웹 설정)로 config.js를 만듭니다. 비밀값은 넣지 않습니다.
  • 보안 헤더(CSP, 프레임 차단, MIME 고정)를 붙입니다.
  • API를 부를 때 토큰, 자료 모드(X-Data-Mode), 중복 요청 키를 함께 보냅니다.

Firebase Auth · 로그인

Google 로그인OWNER_UID

누가 쓰는지 증명합니다.

  • 브라우저에서 Google 로그인을 하면 ID 토큰을 받습니다.
  • 서버는 요청마다 토큰의 서명·만료·폐기 여부를 확인합니다.
  • 토큰의 사용자가 OWNER_UID와 다르면 거부합니다(403). 한 사람만 쓰는 서비스입니다.
중심 서버와 데이터

Render · API 서버

ai-secretary-api.onrender.comserver//docs

웹과 Telegram이 모두 찾아오는 중심입니다.

  • FastAPI 서버입니다. 자료 접수·검토·분석, 숫자 기록과 요약, 채팅, 대화 기록, 휴지통, 새 소식, URL 미리보기를 처리합니다.
  • 비밀값(서비스 계정, AI 중계 토큰, Telegram 토큰)은 Render 환경변수에만 있습니다.
  • 허용한 웹 주소에서 온 요청만 받습니다(CORS). Swagger 문서는 /docs입니다.
  • /health의 ready는 설정이 들어 있다는 뜻일 뿐, Hermes 호출이 성공한다는 뜻은 아닙니다.
  • 무료 플랜이라 한동안 안 쓰면 잠들고, 첫 요청이 50초 이상 걸릴 수 있습니다.

Firestore · 데이터베이스

materialsdataconversationsnews_items

모든 기록을 보관합니다.

  • 자료, 숫자 기록, 대화, 프로젝트, 설정, 새 소식이 들어갑니다.
  • 보안 규칙으로 브라우저의 직접 읽기·쓰기를 전부 막았습니다. 서버만 관리자 SDK로 접근합니다.
  • 모든 문서에 소유자와 모드(개인·표본)가 붙어 서로 섞이지 않습니다.
  • 목록 조회에는 복합 색인이 필요하고, 색인은 Firebase CLI로 배포합니다.
AI 연결 · 이 PC

Hermes · AI 게이트웨이

127.0.0.1:8642/v1gpt-5.5openai-codex

GPT를 OpenAI API와 같은 방식으로 부를 수 있게 해 줍니다.

  • 이 PC에서 돌며, 구독 경로 openai-codex로 현재 gpt-5.5를 씁니다(처음 연결 검증은 gpt-6-luna로 했습니다).
  • 서버는 Python openai SDK로 호출합니다. 과제가 요구한 OpenAI API 형식과 같습니다.
  • 파일·터미널·MCP 도구를 꺼 두었고, 서버도 호출 전마다 도구가 꺼졌는지 확인합니다.

중계 서버 + Tailscale Funnel

127.0.0.1:8766HERMES_RELAY_TOKEN

Render가 이 PC의 Hermes에 닿도록 길을 엽니다.

  • Render는 이 PC의 127.0.0.1에 직접 닿지 못합니다. Funnel이 공개 HTTPS 주소를 열어 중계 서버로 넘깁니다.
  • 중계 서버는 전용 토큰을 확인하고 GET /v1/toolsets, POST /v1/chat/completions 두 경로만 Hermes로 전달합니다.
  • Render의 OPENAI_API_KEY에는 Hermes 키가 아니라 이 중계 토큰을 넣습니다.
다른 입구와 바깥 정보

Telegram Bot

/api/telegram/webhookTELEGRAM_ALLOWED_CHAT_ID

휴대폰 메신저에서 비서에게 묻는 입구입니다.

  • Telegram이 메시지를 Render의 웹훅으로 직접 보냅니다. 서버는 비밀 헤더(TELEGRAM_WEBHOOK_SECRET)와 허용한 chat_id를 확인합니다.
  • 답은 웹 채팅과 같은 처리로 만들고 Telegram의 sendMessage로 돌려보냅니다. 이때 Hermes까지 가는 Funnel 연결이 필요합니다.
  • 같은 메시지가 다시 와도 한 번만 처리합니다. 처음엔 /start로 내 chat_id를 확인합니다.

공식 블로그 · 커뮤니티 피드

/api/newsRSS · Atom

AI 동향의 '새 소식'을 채웁니다.

  • AI 동향을 열 때 마지막 수집이 6시간 넘었으면 서버가 OpenAI, Google AI, DeepMind, Hugging Face, GeekNews, Hacker News 피드를 읽습니다.
  • 관심 분야와 맞는 글을 먼저 보여 주고, 고른 글만 받은 자료로 저장합니다.
  • 외부 접속은 공개 주소만 허용하고 크기·시간·리다이렉트를 제한합니다. Hermes는 쓰지 않습니다.

질문 하나가 처리되는 순서

웹의 '비서에게 묻기'에서 질문을 보냈을 때입니다.

  1. 브라우저 → Render웹이 Firebase 토큰을 붙여 POST /api/chat을 보냅니다.
  2. Render → Firestore서버가 토큰과 소유자를 확인하고, 보관 승인된 자료와 숫자 요약을 찾습니다.
  3. Render찾은 자료와 요약을 "지시가 아닌 참고 데이터" 구획에 넣어 시스템 메시지를 만듭니다. 자료 안의 문장은 명령으로 따르지 않습니다.
  4. Render → Funnel → 중계 → Hermes → GPT질문이 이 PC를 거쳐 GPT로 가고, 답이 같은 길로 돌아옵니다.
  5. Render → Firestore → 브라우저서버가 답에 적힌 출처 번호를 검증하고, 대화를 저장한 뒤 화면에 보여 줍니다.

Telegram에서 물으면 1번이 웹훅으로 바뀌고 2~5번은 같습니다. 마지막에 화면 대신 Telegram 답장을 보냅니다.

  • Telegram 일반 질문에 대한 AI 답변
