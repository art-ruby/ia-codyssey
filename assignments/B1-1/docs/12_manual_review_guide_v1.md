# 12_manual_review_guide_v1.md

## 1. 문서 목적

이 문서는 **AI 테크 뉴스 블로그 자동화 프로젝트의 수동 검수 기준 문서**이다.

목적은 다음과 같다.

- 자동 생성 결과를 사람이 일관된 기준으로 검토할 수 있게 한다.
- 문장 품질, 비교 균형, 기사 기반성, HTML 안정성을 점검한다.
- 어떤 문제는 수정으로 해결하고, 어떤 문제는 재생성해야 하는지 구분한다.
- 게시 가능 수준의 결과물을 선별하는 기준을 제공한다.

---

## 2. 적용 범위

이 문서는 아래 산출물 검수에 적용한다.

- 블로그 초안 본문
- 비교형 기사 요약 글
- HTML 출력물
- 표/리스트/소제목 구조
- 제목/도입부/결론 문장
- 수동 수정 후 최종본

---

## 3. 수동 검수의 역할

이 프로젝트에서 수동 검수는 단순 오탈자 확인이 아니다.

수동 검수의 핵심 역할은 다음과 같다.

1. 자동 생성 결과가 **기사 기반 글**로 읽히는지 확인한다.
2. 비교형 글의 **구조와 균형**이 유지되는지 본다.
3. 과장, 단정, 환각 가능 표현을 제거한다.
4. HTML이 실제 게시 가능한 수준인지 확인한다.
5. 자동 생성이 놓친 미세한 어색함을 줄인다.

---

## 4. 운영 원칙

수동 검수는 감각이 아니라 기준에 따라 수행해야 한다.

### 원칙
1. “좋아 보인다”보다 “기준에 맞는다”로 판단한다.
2. 기사에 없는 내용은 함부로 보강하지 않는다.
3. 애매하면 화려한 문장보다 안전한 문장을 선택한다.
4. 수정량이 과도하면 재생성을 우선 검토한다.
5. 검수 결과는 가능하면 실행 로그에 남긴다.

---

## 5. 검수 대상의 기본 구성

비교형 AI 테크 뉴스 블로그 초안은 보통 아래 요소로 이루어진다.

- 제목
- 도입부
- 본문 비교 섹션
- 표 또는 정리 블록
- 결론
- HTML 구조

검수는 이 순서대로 진행하는 것을 권장한다.

---

## 6. 검수 전체 흐름

권장 검수 순서는 아래와 같다.

1. 전체 방향 확인
2. 제목 검수
3. 도입부 검수
4. 본문 비교 구조 검수
5. 기사 기반성 검수
6. 표현 리스크 검수
7. 결론 검수
8. HTML 구조 검수
9. 최종 게시 가능 여부 판단

---

## 7. 1차 검수: 전체 방향 확인

먼저 세부 문장보다 큰 방향이 맞는지 본다.

### 확인 질문
- 이 글이 비교형 글로 읽히는가?
- 입력 기사들의 핵심이 반영되어 있는가?
- 제목과 본문 방향이 일치하는가?
- 특정 회사/제품 쪽으로 과도하게 기울어져 있지 않은가?
- 수정으로 살릴 수 있는 수준인가, 재생성이 더 빠른가?

### 즉시 재생성 고려 신호
- 비교 구조가 거의 없음
- 입력 기사와 무관한 일반론 위주
- 특정 대상만 과도하게 길게 설명
- 사실관계가 불안정해 보이는 문장 다수
- HTML 자체가 크게 깨짐

---

## 8. 제목 검수 기준

제목은 클릭 유도보다 **정확한 방향 제시**가 우선이다.

### 좋은 제목의 조건
- 비교 대상이 분명하다
- 최근 이슈나 변화 포인트가 드러난다
- 과장되지 않는다
- 본문 내용과 맞는다

### 점검 항목
- [ ] 제목이 기사 기반 내용과 일치하는가
- [ ] “완전 정리”, “승자”, “압도”, “충격” 같은 과장 표현이 없는가
- [ ] 비교 글인데 비교 대상이 제목에 드러나는가
- [ ] 너무 추상적이지 않은가

### 수정 예시
- 수정 전: `AI 시장의 최강자는 누구일까?`
- 수정 후: `OpenAI와 Google, 최근 AI 전략 차이는 무엇이 달라졌나`

---

## 9. 도입부 검수 기준

도입부는 독자에게 글의 맥락과 비교 포인트를 알려줘야 한다.

### 좋은 도입부의 조건
- 기사 기반 문제의식이 반영된다
- 글의 비교 관점이 드러난다
- 일반론이 길지 않다
- 본문으로 자연스럽게 연결된다

### 나쁜 도입부 신호
- “AI 시장은 빠르게 변하고 있다” 같은 상투적 문장만 길다
- 기사 내용과 직접 연결되지 않는다
- 비교 관점 없이 배경 설명만 이어진다

### 점검 항목
- [ ] 도입 2~4문장 안에 비교 주제가 드러나는가
- [ ] 입력 기사 맥락이 반영되는가
- [ ] 일반론 비중이 과하지 않은가
- [ ] 본문 첫 섹션으로 자연스럽게 이어지는가

---

## 10. 본문 구조 검수 기준

본문은 비교형 글의 핵심이다.

### 좋은 본문 구조의 조건
- 비교 축이 분명하다
- 각 대상 설명 분량이 대체로 균형적이다
- 소제목이 읽기 흐름을 돕는다
- 정보 나열이 아니라 비교가 된다

### 점검 항목
- [ ] 비교 기준이 일관적인가
- [ ] 섹션 순서가 자연스러운가
- [ ] 특정 대상 설명만 과도하게 길지 않은가
- [ ] 기사 요약과 해석의 균형이 맞는가

### 자주 발생하는 문제
- A는 전략, B는 제품, C는 시장 반응처럼 비교 축이 흔들림
- 한쪽은 구체적이고 다른 쪽은 추상적임
- 소제목은 비교처럼 보이지만 실제 내용은 병렬 나열임

---

## 11. 비교 균형 검수 기준

비교형 글은 **균형감**이 중요하다.

### 확인 포인트
- 설명 분량의 균형
- 긍정/부정 표현의 균형
- 근거 밀도의 균형
- 결론이 특정 한쪽으로 기울지 않는지

### 점검 항목
- [ ] 한 대상만 과도하게 자세하지 않은가
- [ ] 평가 어조가 한쪽에 더 우호적이지 않은가
- [ ] 비교표나 정리 블록이 같은 기준으로 작성되었는가

### 수정 원칙
- 한쪽 설명이 너무 길면 다른 쪽 보강 또는 긴 부분 압축
- 비교 기준이 다르면 같은 축으로 재정렬
- 평가성 형용사는 줄이고 관찰형 문장으로 바꾸기

---

## 12. 기사 기반성 검수 기준

이 프로젝트의 핵심은 **기사 기반 자동화**이므로 가장 중요하게 봐야 한다.

### 좋은 상태
- 기사에서 확인 가능한 내용 중심
- 기사 간 공통점/차이를 정리
- 과도한 확장 해석이 없음

### 위험 신호
- 기사에 없는 추정이 많음
- 맥락 없이 업계 일반론으로 채움
- “의미한다”, “보여준다”, “증명한다” 같은 과도한 해석이 많음

### 점검 항목
- [ ] 주요 문장이 기사 기반으로 설명 가능한가
- [ ] 근거 없이 단정하는 문장이 없는가
- [ ] 입력 기사와 무관한 배경 설명이 과도하지 않은가

---

## 13. 사실성 및 환각 리스크 검수

모든 문장을 완전 검증할 수 없더라도, 위험 신호는 잡아야 한다.

### 위험 신호 예시
- 기사에 없던 수치가 등장
- 특정 발표 시점이나 기능명이 불명확
- 기업 의도나 전략을 단정적으로 해석
- 시장 반응을 과도하게 일반화

### 점검 항목
- [ ] 숫자/날짜/기능명이 입력 내용과 어긋나지 않는가
- [ ] “반드시”, “확실히”, “결국” 같은 단정 표현이 과하지 않은가
- [ ] 기사에 없는 예측을 사실처럼 쓰지 않았는가

### 대응 원칙
- 애매하면 삭제 또는 완화
- 검증이 안 되면 추정형 문장으로 낮추기
- 근거 없는 강한 해석은 제거

---

## 14. 표현 톤 검수 기준

테크 블로그 문체는 명확하되 과장되지 않아야 한다.

### 권장 톤
- 차분함
- 비교 중심
- 설명형
- 과장 억제
- 해석은 신중하게

### 피해야 할 표현
- 충격, 압도, 승자, 끝났다, 완패
- 혁명적, 게임체인저, 독주 확정
- 무조건, 반드시, 명백히

### 점검 항목
- [ ] 자극적 표현이 없는가
- [ ] 평가보다 설명 비중이 높은가
- [ ] 투자/시장 전망처럼 읽힐 위험이 없는가

---

## 15. 문장 품질 검수 기준

문장이 너무 길거나 애매하면 정보 전달력이 떨어진다.

### 좋은 문장 조건
- 한 문장에 하나의 핵심
- 주어와 서술어 관계가 분명
- 불필요한 반복이 없음
- 의미가 겹치는 수식어가 적음

### 점검 항목
- [ ] 한 문장이 지나치게 길지 않은가
- [ ] 같은 표현이 반복되지 않는가
- [ ] 번역투/기계적 문장이 심하지 않은가
- [ ] 문장 간 연결이 자연스러운가

### 자주 하는 수정
- 긴 문장 분리
- 중복 수식 삭제
- “한편”, “또한”, “즉” 남용 줄이기
- 모호한 지시어 구체화

---

## 16. 표 및 정리 블록 검수 기준

비교형 글에서는 표나 요약 블록이 자주 핵심이 된다.

### 좋은 표의 조건
- 비교 축이 명확하다
- 각 행/열의 기준이 같다
- 문구 길이가 과도하지 않다
- 표만 읽어도 핵심이 보인다

### 점검 항목
- [ ] 각 셀이 같은 관점으로 작성되었는가
- [ ] 한 셀만 지나치게 긴가
- [ ] 비교 항목명이 명확한가
- [ ] 본문과 표의 메시지가 충돌하지 않는가

### 수정 원칙
- 한 셀당 핵심만 남기기
- 문장형보다 구문형으로 압축
- 비교 축이 흔들리면 항목명부터 다시 잡기

---

## 17. 결론 검수 기준

결론은 독자가 글의 핵심을 회수하는 구간이다.

### 좋은 결론의 조건
- 비교 결과를 정리한다
- 우열 확정처럼 읽히지 않는다
- 기사 기반 범위를 넘지 않는다
- 독자가 핵심 차이를 기억할 수 있게 돕는다

### 위험한 결론 신호
- 승패처럼 정리함
- 미래를 단정함
- 본문보다 더 센 해석을 함
- 기사 근거보다 필자의 주장처럼 읽힘

### 점검 항목
- [ ] 결론이 본문 요지와 일치하는가
- [ ] 단정적 우열 판단이 없는가
- [ ] 과잉 예측이 없는가
- [ ] 비교의 핵심 차이를 차분히 정리하는가

### 수정 예시
- 수정 전: `결국 OpenAI가 이번 경쟁의 승자라고 볼 수 있다.`
- 수정 후: `이번 기사 흐름만 놓고 보면 두 회사의 접근 방식 차이가 더 선명해졌다고 볼 수 있다.`

---

## 18. HTML 검수 기준

내용이 좋아도 HTML이 불안정하면 게시 효율이 떨어진다.

### 기본 확인 항목
- [ ] HTML 외 불필요한 설명 문장이 없는가
- [ ] 태그 구조가 크게 깨지지 않았는가
- [ ] 제목/문단/리스트/표가 의도대로 구분되는가
- [ ] 복사/붙여넣기 시 구조가 유지되는가
- [ ] 불필요한 인라인 코드나 마크다운 잔재가 없는가

### 자주 발생하는 문제
- HTML 앞뒤에 설명 텍스트가 붙음
- 리스트 태그가 어색하게 중첩됨
- 표가 깨져서 한 줄 텍스트처럼 나옴
- 마크다운 문법과 HTML이 섞임

### 대응 원칙
- 경미한 구조 오류는 수동 수정
- 태그 구조가 전반적으로 무너지면 재생성 고려

---

## 19. 수정 vs 재생성 판단 기준

수동 검수에서 가장 중요한 판단 중 하나다.

### 수정으로 해결 가능한 경우
- 제목/도입/결론 표현만 다듬으면 됨
- 비교표 문구 압축 정도면 해결 가능
- HTML 경미한 오류만 있음
- 전체 구조와 기사 기반성은 살아 있음

### 재생성이 더 나은 경우
- 비교 구조 자체가 무너짐
- 기사 기반성이 약함
- 한쪽으로 과도하게 편향됨
- 잘못된 사실 가능성이 여러 군데 보임
- 수동 수정량이 지나치게 많음

---

## 20. 수정 강도 분류 기준

수동 검수 결과를 아래 수준으로 구분해 기록할 수 있다.

### 분류
- `None`: 수정 없음
- `Light`: 소폭 문장 정리
- `Moderate`: 여러 섹션 수정
- `Heavy`: 구조 수준 수정
- `Rerun Preferred`: 재생성이 더 적절

### 예시
- `Light`: 제목 완화, 결론 2문장 수정
- `Moderate`: 도입부 재작성, 표 문구 전면 정리
- `Heavy`: 본문 섹션 순서 변경, 비교축 재구성

---

## 21. 수동 검수 기록 권장 형식

검수 결과는 간단히라도 남겨두는 것이 좋다.

```md
## Manual Review Note

- Review Result: Moderate Edit
- Main Issues:
  - intro too generic
  - comparison balance slightly weak
  - conclusion too assertive
- Fixed:
  - rewrote intro opening
  - shortened table wording
  - softened conclusion
- Final Decision:
  - Approved for Posting
```

---

## 22. 검수자가 자주 빠지는 함정

수동 검수도 과도하면 오히려 기준이 흐려질 수 있다.

### 주의할 점
- 기사에 없는 내용을 검수자가 임의로 보강하지 않기
- 문체를 예쁘게 만들려다 해석을 과장하지 않기
- 한 문장을 고치며 전체 균형을 무너뜨리지 않기
- 자신의 선호를 기준처럼 착각하지 않기

---

## 23. 좋은 검수의 조건

좋은 수동 검수는 아래 특징을 가진다.

- 수정 이유가 설명 가능하다
- 글의 방향을 더 선명하게 만든다
- 과장을 줄이고 명확성을 높인다
- 기사 기반성을 유지한다
- 재현 가능한 기준으로 수행된다

---

## 24. 게시 가능 판정 기준

아래 조건을 대체로 만족하면 게시 가능으로 판단한다.

- 제목과 본문 방향이 맞다
- 비교 구조가 분명하다
- 기사 기반성이 유지된다
- 과장/환각 위험 표현이 관리 가능한 수준이다
- 결론이 차분하다
- HTML이 바로 사용할 수 있는 수준이다

---

## 25. 게시 보류 또는 재작업 기준

아래 경우는 게시 보류를 우선 검토한다.

- 핵심 내용의 신뢰도가 불안하다
- 비교라기보다 편향된 소개문처럼 읽힌다
- 본문보다 결론 해석이 더 과감하다
- HTML 수정 시간이 과도하게 든다
- 수동 수정 후에도 글의 중심이 불분명하다

## 27. 실무용 초간단 검수 체크

시간이 부족할 때는 아래 7가지 항목만 빠르게 확인해도 기본 품질을 많이 걸러낼 수 있다.

- [ ] 제목이 과장되지 않았는가
- [ ] 도입부가 기사 맥락과 연결되는가
- [ ] 비교 구조가 살아 있는가
- [ ] 특정 대상에 치우치지 않았는가
- [ ] 근거 없는 단정 표현이 없는가
- [ ] 결론이 과하지 않은가
- [ ] HTML이 바로 붙여넣기 가능한가

---

## 28. 예시: 가벼운 수정으로 끝나는 경우

```md
### Review Case A
- Problem:
  - intro slightly generic
  - conclusion wording a bit strong
- Action:
  - replace first 2 sentences in intro
  - soften final paragraph
- Edit Level:
  - Light
- Final Decision:
  - Approved for Posting
```

이 경우는 전체 구조와 기사 기반성이 살아 있으므로  
재생성보다 수동 수정이 효율적이다.

---

## 29. 예시: 재생성이 더 나은 경우

```md
### Review Case B
- Problem:
  - comparison axis inconsistent
  - one company heavily overexplained
  - several claims not clearly grounded in source articles
- Action:
  - rerun preferred
- Edit Level:
  - Rerun Preferred
- Final Decision:
  - Hold
```

이 경우는 문장 몇 개를 고치는 수준이 아니라  
**글의 중심 구조 자체가 흔들린 상태**이므로 재생성이 더 적절하다.

## 30. 검수 코멘트 작성 원칙

검수 메모는 짧아도 좋지만, 다음 사람이 봐도 이해 가능해야 한다.

### 좋은 코멘트 예
- 도입부가 기사 기반보다 일반론 비중이 높음
- 비교표는 좋지만 결론이 우열 판단처럼 읽힘
- HTML 구조는 안정적이나 리스트 계층이 어색함

### 나쁜 코멘트 예
- 뭔가 애매함
- 별로임
- 그냥 다시

### 원칙
1. 문제를 관찰 가능한 형태로 적는다.
2. 가능하면 수정 방향도 함께 적는다.
3. 감정보다 기준 중심으로 적는다.

## 31. 팀 운영 시 권장 방식

여러 사람이 검수에 참여하는 경우 기준 차이를 줄여야 한다.

### 권장 방식
- 같은 초안을 2명이 시범 검수해 기준 차이 확인
- 자주 충돌하는 판단 항목 문서화
- “수정 가능”과 “재생성 필요” 기준을 통일
- 좋은 수정 사례를 별도 축적

### 권장 운영 메모
- 초반 10건 정도는 검수 메모를 자세히 남긴다.
- 반복 패턴이 보이면 프롬프트 수정으로 되돌린다.
- 검수자 취향보다 프로젝트 기준을 우선한다.
