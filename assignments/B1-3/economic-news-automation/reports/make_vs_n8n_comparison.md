# Make vs n8n 비교 보고서

## 1. UI와 화면 구성

Make는 큰 캔버스에 모듈이 순서대로 배치되고 Router 분기가 시각적으로 명확하다. 비개발자가 업무 흐름을 설명하거나 시연하기 쉽다. n8n은 노드 기반 캔버스이지만 Code 노드와 데이터 구조가 더 개발자 친화적이다.

## 2. 초기 설정 난이도

Make는 계정 생성 후 Webhook, Google Sheets, Gmail 연결까지 빠르게 구성할 수 있다. n8n은 클라우드 또는 self-hosted 환경을 먼저 준비해야 하지만, 한 번 준비하면 워크플로우 JSON import/export와 코드 재사용이 편하다.

## 3. Webhook 생성 방식

Make는 Custom Webhook 모듈을 추가하면 URL이 즉시 생성된다. n8n은 Webhook 노드를 만들고 테스트 URL과 프로덕션 URL을 구분해 사용한다. 테스트 반복은 둘 다 가능하지만 n8n은 실행 이력에서 요청 payload를 더 구조적으로 확인할 수 있다.

## 4. 조건 분기 방식

Make는 Router와 Filter가 직관적이다. 다만 분기가 많아지면 같은 조건을 여러 모듈에 반복 입력해야 한다. n8n은 Switch, IF, Code 노드를 섞어 쓸 수 있어 복잡한 조건을 코드로 한 번에 관리하기 쉽다.

## 5. 데이터 매핑 방식

Make는 UI에서 필드를 끌어와 매핑하는 방식이 쉽다. n8n은 표현식과 JSON 경로를 사용하므로 초반에는 어렵지만, 중첩 데이터나 배열 처리에는 더 유리하다.

## 6. Google Sheets 연동

두 도구 모두 Add Row와 Lookup을 지원한다. Make는 설정 화면이 단순하고, n8n은 lookup 이후 Code 노드에서 중복/집계 로직을 더 자유롭게 처리할 수 있다.

## 7. 실행 로그 확인

Make는 모듈별 버블로 입출력을 볼 수 있어 빠른 디버깅에 좋다. n8n은 실행 이력의 JSON 구조가 명확하고, Code 노드 오류 원인을 추적하기 좋다.

## 8. 오류 처리

Make는 Error Handler route를 모듈 단위로 붙인다. n8n은 Continue on Fail, Error Trigger Workflow, 별도 오류로그 저장 노드를 조합할 수 있다.

## 9. 테스트 편의성

HTTP Webhook 테스트는 둘 다 쉽다. n8n은 import JSON으로 같은 워크플로우를 재현하기 쉬워 제출물 검증에 유리하다.

## 10. 사용자 정의 코드

Make는 노코드 중심이라 복잡한 문자열 탐색과 우선순위 계산이 길어진다. n8n은 JavaScript Code 노드로 키워드 분류와 source_count 계산을 명확하게 구현할 수 있다.

## 11. 재사용성

n8n은 Code 노드와 JSON export를 재사용하기 좋다. Make는 모듈 설정을 문서화하면 재현 가능하지만, Blueprint 유효성 보장 없이 직접 작성한 JSON은 import 실패 위험이 있다.

## 12. 확장성

핫이슈 감지처럼 집계가 필요한 자동화는 n8n이 더 적합하다. 단순 수집, 저장, 알림은 Make가 빠르다.

## 13. AI 연동 가능성

두 도구 모두 AI API 호출이 가능하다. n8n은 Code 노드와 LangChain 계열 노드를 활용할 수 있어 후속 확장성이 높다.

## 14. 초보자 적합성

Make가 더 적합하다. 화면 흐름이 설명하기 쉽고 필터 설정이 직관적이다.

## 15. 복잡한 자동화 적합성

n8n이 더 적합하다. 중복 방지, 같은 날짜/주제 집계, 다중 시트 업데이트 같은 로직은 코드와 노드 조합이 필요하기 때문이다.

## 요금 관련 주의

최신 무료 플랜 수치와 요금은 제출일 기준 공식 요금 페이지 재확인이 필요하다.
