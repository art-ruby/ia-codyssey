## 1. 미션 개요

여러 문서와 메신저에 흩어진 프롬프트를 한곳에서 관리하기 위해 Python 콘솔 기반 Prompt Manager를 제작하였다. 사용자가 메뉴 번호를 입력하면 프롬프트 목록 확인, 키워드 검색, 새 프롬프트 등록, 즐겨찾기 설정과 조회를 수행하도록 구성하였다.

이 과정에서 Python의 리스트와 딕셔너리, 함수, 조건문, 반복문, 사용자 입력을 실제 프로그램에 적용했다. 또한 Git으로 변경 이력을 기록하고 GitHub 원격 저장소에 업로드하여 코드와 문서를 함께 관리하였다.

## 2. 개발 목표와 결과물

- 터미널에서 실행되는 메뉴형 Python 프로그램 제작

- 이전 미션에서 작성한 프롬프트를 기본 데이터로 3개 이상 등록하는 요구사항을 충족했다. 현재 prompts.json에는 총 4개의 프롬프트가 저장되어 있다.

- 실제로 구현된 기능은 전체 프롬프트 조회, 제목·내용·카테고리 통합 검색, 새 프롬프트 추가, 즐겨찾기 목록 조회, 즐겨찾기 설정·해제이다. 별도의 카테고리별 조회 메뉴와 번호 입력 방식의 독립 상세 보기 메뉴는 구현하지 못했다.

## 5. Prompt Manager 프로그램 구현

### 5.1 프로그램 구조 설계

프로그램의 각 기능을 하나의 큰 코드에 몰아넣지 않고 함수로 분리하였다. main()의 while 반복문이 메뉴를 계속 보여주고, 사용자가 선택한 번호에 따라 각각의 기능 함수가 실행된 뒤 다시 메뉴로 돌아오도록 설계하였다.

- load_prompts(), save_prompts(): JSON 데이터 불러오기와 저장

- show_all_prompts(): 전체 프롬프트 출력

- search_prompts(): 제목·내용·카테고리 키워드 검색

- add_prompt(): 새 프롬프트 입력과 등록

- show_favorites(), toggle_favorite(): 즐겨찾기 조회와 상태 변경

- main(): 메뉴 출력, 선택 분기, 반복 실행과 종료

### 5.4 JSON 저장·불러오기 보너스 구현

보너스 과제인 프롬프트 영속화를 위해 JSON 저장 기능을 구현하였다. 프로그램 시작 시 prompts.json을 읽고, 프롬프트 추가나 즐겨찾기 변경 시 UTF-8 JSON으로 전체 목록을 다시 저장한다. 파일이 없거나 JSON이 손상되면 코드에 정의된 기본 프롬프트 3개로 복구한다. 따라서 데이터는 종료 시 초기화되지 않고 다음 실행에서도 유지된다.

## 7. GitHub 저장소와 과제 Git 요구사항 점검

### 7.1 실제 커밋·브랜치·원격 저장소 상태

현재 main 브랜치에 의미 있는 커밋 5개가 있으며 origin/main과 연결되어 있다. 최근 이력은 Hello 실행, README 및 ignore 파일 추가, 기본 프롬프트 등록, 메뉴 기능 추가, JSON 저장 및 즐겨찾기 완성 순서이다. 그러나 과제 기준인 최소 10개 커밋에는 부족하고, 추가 브랜치 생성·checkout·merge 기록 및 병합 커밋도 확인되지 않는다. 따라서 해당 Git 요구사항은 아직 미충족 상태이다.

```text
git add src/main.py prompts.json README.md
git commit -m "feat: 프롬프트 저장 및 즐겨찾기 기능 완성"
git push
```

## 8. 과제 요구사항 대조 및 수행 결과

[구현 완료] Python Prompt Manager는 콘솔 메뉴, 기본 프롬프트 4개, 전체 목록, 통합 검색, 프롬프트 추가, 즐겨찾기 조회·설정·해제, 잘못된 메뉴 번호 안내, 기능별 함수 분리를 구현했다. [보너스 구현] json과 pathlib을 사용하여 prompts.json을 불러오고 변경 내용을 영구 저장한다. [미충족 또는 차이] 별도의 카테고리별 조회 메뉴와 번호 기반 독립 상세 보기 메뉴가 없으며, 추가 입력값이 비어 있으면 재입력을 요청하지 않고 해당 추가 작업을 종료한다. Git 커밋은 5개로 최소 10개 기준에 부족하고, 추가 브랜치 생성·병합 기록도 없다. .gitignore 대신 .gitnore가 존재하여 제외 규칙도 적용되지 않는다. 따라서 현재 결과물은 과제의 핵심 기능을 일부 구현했지만 모든 필수 요구사항을 완전히 충족한 상태는 아니다.

현재 확인된 주요 산출물은 src/main.py, prompts.json, README.md, hello.py와 본 제출 보고서이다. GitHub 원격 저장소는 https://github.com/art-ruby/python-prompt-manager 이며 현재 브랜치는 main이다.

## 9. 배운 점과 시행착오

Python 실행 위치: Python 대화형 입력창(>>>)과 프로젝트 터미널을 구분해야 했다. 파일 실행 명령은 프로젝트 경로가 표시되는 터미널에서 입력해야 한다는 점을 익혔다.

데이터 구조: 여러 프롬프트를 리스트로 묶고, 각 프롬프트의 제목·내용·카테고리·즐겨찾기 상태를 딕셔너리로 관리하는 방식을 이해했다.

함수 분리: 기능별로 함수를 나누면 오류가 난 위치를 찾기 쉽고, 이후 기능을 추가하거나 수정하기도 편해진다는 점을 체감했다.

저장 방식: 메모리의 데이터는 프로그램 종료 시 사라지지만 JSON 파일로 저장하면 다시 불러올 수 있다는 차이를 배웠다.

Git과 GitHub: Git은 로컬 변경 이력을 기록하고, GitHub는 그 기록과 파일을 원격에서 공유·보관하는 역할을 한다는 점을 실제 커밋과 푸시를 통해 익혔다.

## 10. 미충족 요구사항과 향후 개선 계획

우선 .gitnore를 .gitignore로 바로잡고, 별도 카테고리별 조회 메뉴와 번호 기반 상세 보기 기능을 추가해야 한다. 프롬프트 추가 시 빈 입력을 받으면 기능을 끝내지 않고 다시 입력받도록 개선할 필요가 있다. Git 과제 기준을 충족하려면 기능 브랜치를 생성하여 checkout 후 작업하고 main에 merge한 기록을 남기며, 기능 단위의 의미 있는 커밋을 최소 10개 이상 확보해야 한다. 이후 선택 과제로 수정·삭제, Markdown 내보내기, 조회수 기록과 인기 프롬프트 정렬을 구현할 수 있다.
