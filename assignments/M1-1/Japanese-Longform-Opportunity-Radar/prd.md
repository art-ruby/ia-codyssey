## 1. 한 줄 정의

> **일본 YouTube 롱폼 데이터를 매일 모아, 작은 채널에서 지금 오르고 있는 영상을
> 아침 5분에 찾아내고, 그 소재를 Claude 웹에 붙여넣을 수 있는 한 장으로
> 내보내는 개인용 도구.**

## 2. 왜 만드는가

일본어 영상을 만들려면 «무엇을 만들 것인가» 를 먼저 정해야 한다.
조회수 상위를 보는 것으로는 답이 안 나온다 — 그 자리는 이미 큰 채널이
차지하고 있어 **새로 만들 소재를 알려주지 않는다.**

대신 **구독자가 적은데 크게 터진 영상**을 찾는다. 그것이 «아직 충분히 다뤄지지
않은 주제» 를 가리킨다고 본다.

여기서 찾은 소재는 `automaker`(별도 프로그램)로 영상이 된다. 다만 대본은
Claude 웹에서 대화하며 쓰므로, 이 도구의 최종 산출물은 **영상이 아니라
«Claude 에게 줄 재료 한 장»** 이다.

## 3. 사용자와 사용 방식

| 항목 | 결정 |
|---|---|
| 사용자 | **본인 1명**. 로그인·다중 사용자 없음 |
| 실행 환경 | **로컬 PC (Windows)**. 서버 배포 없음 |
| 사용 리듬 | **매일 아침 5분** |
| 저장 | CSV 파일. DB 없음 |
| 인증 | 없음. API 키는 `.env` 한 곳 |

### 하루 흐름

```
[배경 · 사람 손 안 감]
  매일 정해진 시각  →  수집 + 스냅샷 자동 실행  (약 1,625 units)

[아침 5분]
  화면 열기
   → 「지금 오르는 중」 10개 훑기
   → 「어제 새로 들어온 것」 10개 훑기
   → 마음에 드는 것 클릭 → [복사]
   → Claude 웹에 붙여넣기 → 대본 설계 시작
```

**«쌓는 주기» 와 «보는 주기» 가 다르다.** 스냅샷은 매일 쌓여야 시계열이 생기고,
사람은 그것을 아침에 본다.

## 5. 화면 명세

화면은 하나다. Streamlit. **이미 수집된 CSV 만 읽는다 — 화면 조작이 API 를
부르지 않는다.**

### 5.1 아침 화면 (기본 탭) — 신규

```
📡 오늘의 발견                          스냅샷 누적 N일 · 추적 M건

🔥 지금 오르는 중                                          [10건]
   직전 관측 대비 하루 증가 순. 스냅샷 2회 이상 쌓인 것만.
   ┌──────────────────────────────────────────────────┐
   │ +12,400/일  (1.0일 간격)   제목…        [복사] [열기] │
   │ 구독 4,140 → 493,227  Video 96.2 / Channel 17      │
   └──────────────────────────────────────────────────┘

🆕 어제 새로 들어온 것                                      [10건]
   Video Score 순. ⚠ «어제 처음 봤다» 이지 «어제 떴다» 가 아니다.
   게시일을 함께 표시한다.
```

**설계 근거** — 「지금 오르는 중」이 먼저다. 스냅샷 두 장을 비교한 값이라
착각할 여지가 없다. 「새로 들어온 것」은 검색으로 이제야 걸렸을 뿐
**한 달 전에 이미 터진 영상일 수 있다.**

첫날에는 「지금 오르는 중」이 비어 있다. 그 자리에 안내를 띄운다.

> 스냅샷이 한 번뿐이라 증가량을 계산할 수 없습니다.
> 내일 한 번 더 돌면 여기가 채워집니다.

### 5.2 나머지 탭 (기존 유지)

```
🔥 떡상영상      Video Score 상위 30 · 표본 수 함께 표시
📈 시계열        게시 주차별 조회 속도 + 4주 이동평균
🎯 Outlier 분포   구독자 대비 조회수 산점도
📊 데이터        전체 표 + CSV 내려받기
🔎 검색어 관리    ← ③ 에서 추가
```

### 5.3 검색어 관리 (③)

```
현재 검색어 (8/15)
  老後  お金  仕事  孤독  AI  人生  SNS  住宅        [각각 빼기]

새 검색어 후보 — Outlier 영상 제목에서 뽑음
  ゆっくり解説   8건에 등장   [추가] [무시]
  新NISA         5건에 등장   [추가] [무시]
```

**프로그램은 후보만 제안하고 넣을지는 사람이 정한다.** 제목에서 뽑은 단어가
주제가 아니라 **형식이거나 채널명**일 때가 많기 때문이다. 실제 데이터에서
`【ゆっくり解説】`가 여러 번 나오는데 이는 주제가 아니라 영상 형식이다.
그대로 검색어로 넣으면 그 형식의 영상만 걸린다. 사람이 보면 3초에 거른다.

「무시」한 후보는 다시 제안하지 않는다.

## 6. 기능 명세

### F-1. 아침 화면 · 지금 오르는 중 (①)

- **입력** `video_snapshots.csv`, `videos.csv`
- **처리** 영상별 직전 관측과 최신 관측을 비교
- **정렬** 하루 증가량 내림차순, 상위 10
- **조건** 스냅샷 2회 이상. `watch_status = active` 만
- **표시** 하루 증가 · 관측 간격(일) · 제목 · 채널 · 구독자 · 조회수 · Video Score

```
Daily View Gain = (오늘 views − 직전 views) ÷ (오늘 날짜 − 직전 날짜)
```

> ⚠️ **«전날» 이 아니라 «직전 관측» 이다.** 하루를 빠뜨리면 2일치가 1일치로
> 읽혀 값이 2배가 된다. 반드시 실제 경과 일수로 나눈다. 이미 구현돼 있다
> (`src/analysis.py::gains`).

### F-2. 아침 화면 · 새로 들어온 것 (①)

- **조건** `videos.csv` 의 `found_at` 이 최근 24시간
- **정렬** Video Score 내림차순, 상위 10
- **표시** 위와 같되 **게시일과 경과일을 반드시 표시** — 오래된 영상일 수 있다

### F-3. 내보내기 (②)

각 항목의 [복사] 버튼. 클립보드로 아래 한 장이 들어간다.

```
■ 소재
  {제목}  ({길이}분, {게시일} 게시)
  {URL}

■ 왜 이 영상인가
  구독자 {N} → 조회 {N}  (구독자의 {N}배)
  Video Score {N} / Channel Score {N}
  같은 나이대({버킷}) {N}건 중 상위 {N}%
  검색어 「{seed}」 — 성과 {순위}위, 공급 {이전}건 → {최근}건

■ 자막 발췌
  [앞 3분]      …
  [반복 키워드]  …
  [마지막 1분]   …

■ 주변
  같은 검색어 상위 5편 제목
  이 채널 최근 영상 5편 제목
```

**자막은 전체를 넣지 않는다.** 37분물이 약 17,000자라 붙여넣기가 부담이다.
앞 3분 + 반복 키워드 + 마지막 1분이면 약 2,500자이고, **소재를 «고르는»
단계에는 그것으로 충분하다.**

근거 — 벤치마킹한 37분물은 0:10 에 세계관, 0:40 에 길이 변호, 0:59 에 본편
진입이었다. 오프닝에 핵심 질문과 훅이 다 있다. 마지막 1분에는 결론과 다음 화
예고가 있다. 앞뒤만 보면 «무엇을 묻고 어떻게 닫았는가» 가 잡힌다.

- 자막 수집은 **`yt-dlp`** 로 한다. 무료이고 API 키가 필요 없다.
  ```
  yt-dlp <URL> --skip-download --write-auto-subs --sub-lang ja --sub-format json3
  ```
  `json3` 은 조각별 타임스탬프를 주므로 «앞 3분» 을 정확히 자를 수 있다.
- 자막이 없는 영상은 그 칸을 «자막 없음» 으로 두고 나머지는 그대로 낸다.
- **파일로 떨어뜨리지 않는다.** 어차피 채팅창에 붙여넣을 것이라 한 단계 낭비다.

### F-4. 검색어 관리 (③)

- 현재 검색어 목록 표시. 빼기 가능
- **상한 15개.** 넘으려 하면 «성과가 낮은 검색어를 빼시겠습니까» 로 안내
- Outlier 영상(구독자 대비 5배 이상) 제목에서 명사·대괄호 표현을 뽑아
  **2건 이상 등장한 것만** 후보로 제안
- 「추가」하면 `config.SEEDS` 에 반영되어 다음 수집부터 쓰인다
- 「무시」한 것은 별도 파일에 기록해 다시 제안하지 않는다

### F-5. 자동 실행 (배경)

윈도우 작업 스케줄러에 매일 1회 등록한다.

```
python -m src.collector            수집    약 1,615 units
python -m src.snapshot_collector   스냅샷  약     9 units
```

실행 결과는 `data/raw/quota_log.csv` 에 쌓인다. 실패해도 다음날 다시 돈다 —
`--skip-done` 성격이라 중복 저장은 없다.

## 8. 지표 정의

### Average Daily Views

```
ADViews = views ÷ 게시 후 경과일          (당일 영상은 0.5일로 하한)
```

실제 조회 «속도» 가 아니라 평균이다. 이름을 그렇게 쓴다.

### Age Bucket

```
0~3일 · 4~7일 · 8~14일 · 15~30일 · 31~90일
```

**분석 실행 시점의 나이로 매번 다시 정한다.** 수집 시점에 고정하지 않는다 —
영상은 매일 나이를 먹어 버킷이 바뀐다.

표본 규칙:

```
n >= 20   버킷 내부 백분위
n <  20   인접 버킷과 병합
그래도 부족  전체 분석군 중앙값 대비 비율
```

`age_bucket` · `age_bucket_n` · `age_adjusted_percentile` 을 **함께 저장한다.**
표본 수를 같이 보여줘야 점수를 믿을지 판단할 수 있다.

**«동일 Seed» 를 fallback 모집단으로 쓰지 않는다.** Seed 단위는 전체보다
표본이 적어 오히려 더 불안정하다.

### Video Score — Phase A · 영상 선별

```
Video Score = Age-adjusted ADViews Percentile × 0.6
            + Subscriber View Ratio Percentile × 0.4
```

`hidden_subscriber_count = true` 면 Subscriber View Ratio 를 계산하지 않고
Age-adjusted 만으로 낸다. 0 으로 채우면 비율이 무한이 된다.

### Channel Score — Phase B · 채널 검증

```
Channel Baseline = 대상 views ÷ median(대상보다 오래된 채널 영상들의 views)
Channel Momentum = median(최근 5개 views) ÷ median(그 앞 10개 views)

Channel Score = Baseline Percentile × 0.6 + Momentum Percentile × 0.4
```

**조회수로 비교하고, 비교 대상은 대상보다 오래된 영상으로 한다.**
자세한 이유는 §10-② 를 볼 것. 값은 과소평가이며, 그래서 나온 신호는 진짜다.

Momentum 을 못 낸 채널은 Baseline 만으로 내고 `score_basis` 에 남긴다.
둘 다로 낸 점수와 같은 자로 잰 것이 아니다.

### 두 점수를 합치지 않는다

```
Video Score    이 영상이 특이하게 강한가?
Channel Score  이 채널도 실제로 상승하고 있는가?
```

실제 데이터에서 Video Score 가 거의 같은 두 영상이 정반대로 갈렸다.
하나는 채널째 오르는 중이었고, 하나는 **그 채널 평소보다 오히려 못했다.**
합쳤다면 이 차이가 사라진다. **Final Data Score 를 만들지 않는다.**

## 9. 비기능 요구사항

### API 할당량 — 가장 중요한 제약

```
search.list   100 units · 하루 실질 상한 약 100회
videos.list     1 unit  · 50개를 묶어 1회
하루 총량    10,000 units
```

| 작업 | 비용 |
|---|---|
| 수집 (검색어 8개 × order 2종) | 약 1,615 |
| 스냅샷 (500건까지) | 약 10 |
| 채널 검증 (30채널) | 약 55 |
| **하루 합계** | **약 1,680** |

- **수집은 하루 1~2회.** 분석은 저장된 CSV 만 읽는다
- 검색어 상한 15개 (30회 검색 = 약 3,030 units)
- 할당량 소진 시 명확한 안내를 내고 종료한다. 이미 받아 둔 CSV 로 분석은 계속된다

### 성능

- 화면 첫 렌더 3초 이내. Streamlit `cache_data` 로 CSV 를 캐시
- 수집 1회 2분 이내

### 보안

## 10. 알려진 함정 — 반드시 읽을 것

이 프로젝트에서 실제로 걸린 것들이다. **셋 다 에러 없이 그럴듯한 숫자로
나왔다.** 값을 눈으로 보고 «말이 되나» 를 따지지 않으면 그대로 지나간다.

### ① ADViews 로 기간을 비교하면 안 된다

검색어별 성장률을 나이 보정 없이 계산했더니 **`+16,162%`** 가 나왔다.

`ADViews = 조회수 ÷ 경과일` 인데 조회수는 초기에 몰리고 분모는 계속 는다.
어린 영상일수록 값이 구조적으로 높다. 「최근 30일 vs 이전 30일」 비교는
사실상 **어린 영상과 늙은 영상의 비교**다.

나이를 통제해 다시 재자 **그 검색어가 8개 중 꼴찌**가 됐다.

→ 기간 비교에는 **게시 수(공급량)** 와 **같은 나이대 안에서의 성과**만 쓴다.

### ② Channel Baseline 도 같은 함정에 빠졌다

ADViews 로 계산했더니 **`2,941배`** 가 나왔다. 그 채널의 중앙 ADViews 가
`4.1/일` 이었기 때문이다 — 오래된 영상들이 `2.2 · 4.5 · 7.0` 으로 0 에
수렴해 있었다.

→ **조회수로 비교하고, 비교 대상은 «대상보다 오래된 영상»** 으로 한다.
비교 대상이 시간을 더 가졌는데도 이겼다면 그것은 진짜다. 편향이 신호를 찾는
**반대 방향**으로 작용하므로 나온 값은 과소평가다.

### ③ 그래프에 한글과 일본어를 같이 못 쓴다

윈도우에 둘 다 가진 폰트가 **없다**(실측).

```
Malgun · Gulim · Batang    한글 O · 独 X
MS Gothic · Yu Gothic      한글 X · 独 O
```

폰트를 섞으면 라벨이 축 밖으로 밀리거나 사라졌다.

→ **그래프 라벨은 한글로 쓴다**(`config.SEED_LABELS`). 일본어 원문은 CSV 와
웹화면에 그대로 둔다 — 웹은 브라우저가 그리므로 깨지지 않는다.

### ④ 이 프로그램의 실패는 조용하다

형식이 어긋나도 에러가 아니라 «0개» 로 인식된다. **에러가 없다는 것이
동작한다는 뜻이 아니다.** 숫자를 확인한다 — 몇 건 수집됐나, 몇 건 필터를
통과했나, 표본이 몇인가.

## 14. 구현하며 달라진 것

명세는 **만들기 전에 정한 것**이라 그대로 둔다. 실제로 만들면서 갈린 곳을
여기에 적는다. 다음에 이 문서를 읽는 사람이 «왜 코드가 다르지» 로 헤매지
않도록.

### ① 검색어는 `config.SEEDS` 가 아니라 `data/raw/seeds.json` 에

F-4 는 「추가하면 `config.SEEDS` 에 반영」이라 했다.
**화면에서 소스 코드를 고쳐 쓰는 것은 위험하다** — 쓰다 실패하면 프로그램이
아예 안 뜬다. 검색어는 상수가 아니라 바뀌는 값이므로 데이터로 뒀다.

`config.SEEDS` 는 파일이 없을 때의 기본값이 되었다.
「다음 수집부터 쓰인다」는 요건은 그대로다.

### ② 검색어 상한 15개와 할당량 20% 는 함께 지킬 수 없다

```
F-4    검색어 상한 15개
§12    하루 할당량 20% 이내
```

검색어 1개 = 검색 2회 = 200 units 이므로

```
 8개  1,600 units  16%
10개  2,000 units  20%   ← 여기가 선
15개  3,000 units  30%   ← §12 위반
```

프로그램은 막지 않는다. 지금 몇 %인지 화면에 늘 띄우고 20% 를 넘으면
경고한다 — 어느 쪽을 택할지는 쓰는 사람이 정할 일이다.

### ③ [복사] 와 [열기] 의 자리

§5.1 스케치는 행마다 `[복사] [열기]` 를 그렸다. 실제로는

```
[열기]   표의 «맨 앞» 칸. 맨 뒤에 두면 가로 스크롤에 가려 안 보인다
[복사]   행마다가 아니라 «한 장» 에 하나. 한 장을 만드는 데 몇 초 걸리므로
         고를 때마다 만들면 요청이 몰려 막힌다
```

### ④ 검색어 성과는 이상치 수로 줄 세운다

명세에 정렬 기준이 없었다. 중앙 점수로 매겼더니 `住宅` 을 «성과 꼴찌» 로
짚었는데, **이상치가 두 번째로 많은 검색어**였다.
찾는 것은 «평균이 높은 주제» 가 아니라 «유난히 잘 된 영상» 이다.

### ⑤ 화면에 추가한 것 — 채널 영상수

명세에 없었으나 넣었다. 구독자만으로는 «작은 채널» 을 못 가른다.

```
구독   4,190 · 영상   4편  ← 갓 시작한 채널이 바로 터짐
구독 512,000 · 영상 671편  ← 영상이 쌓여 큰 채널
```

`channels.list` 를 이미 `part=statistics` 로 부르고 있어
**할당량이 더 들지 않는다.**

### ⑥ 아직 화면이 없는 것

수집·할당량·스케줄러·번역 설정은 **명령으로만** 된다.
`mockup/index.html` 에 화면으로 만들면 어떤 모습일지 그려 두었다.
