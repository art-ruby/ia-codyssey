### 무엇을 하는 파일인가

```python
from src import subtitles
d = subtitles.digest("DD3gDj8cKGo")

d["ok"]        자막을 구했는가
d["head"]      앞 3분
d["keywords"]  [(낱말, 횟수), ...]  되풀이된 말
d["tail"]      마지막 1분
d["chars"]     자막 전체 글자수
```

### 왜 전체를 안 넣나

20분물이 7,191자, 37분물이 약 13,000자다. 채팅창에 그대로 붙이면 부담이고,
**「이 소재를 할까 말까」를 정하는 데는 필요가 없다.**

벤치마킹한 37분물은 0:10 에 세계관, 0:40 에 길이 변호, 0:59 에 본편 진입이었다.
오프닝에 핵심 질문과 훅이 다 있다. 마지막 1분에 결론과 다음 화 예고가 있다.
가운데는 되풀이되는 낱말만 봐도 무엇을 다루는지 잡힌다.

### 확인한 것 (7.5~7.9)

```bash
python -c "from src import subtitles; d=subtitles.digest('DD3gDj8cKGo'); print(d['head'][:200])"
```

1. **`_events()` 의 겹쳐쓰기 제거가 맞게 도는가.**
   유튜브 자동자막은 앞 줄을 다시 쓰며 한 낱말씩 늘려 간다.
   실측한 파일에서 `t=40ms` 는 `ねえ、魔理沙。AI`, `t=1880ms` 는
   `って結局どれも同じでしょ。` 였다. 앞 줄로 시작하는 줄은 앞 줄을 버린다.
   **이게 틀리면 같은 말이 두 배로 들어간다 — 조용히 틀린다.**

2. **앞3분+마지막1분이 2,500자 안쪽인가.** 넘으면 `HEAD_SECONDS` 를 줄인다.

3. **키워드가 말이 되는가.** 형태소 분석기 없이 한자 2자 이상 / 가타카나
   3자 이상 덩어리를 센다. 정확한 분석이 아니다 — 「무엇에 대한 영상인가」만
   알면 되므로 이 정도로 충분하고 사전을 안 깔아도 된다는 이점이 크다.
   결과가 조사 범벅이면 `STOP` 집합에 추가한다.

4. **자막 없는 영상.** 일본 롱폼에도 자막 없는 것이 흔하다.
   `ok=False` 로 돌려주고 **그 칸만 「자막 없음」으로 두고 나머지는 그대로 낸다.**
   자막이 없다고 소재가 못 쓸 것은 아니다.

### 함정

- `yt-dlp` 출력 폴더를 `$TMPDIR` 로 잡으면 안 된다. Git Bash 에서 비어 있어서
  `C:\Program Files\Git\` 에 떨어진 적이 있다. `config.DATA_RAW / "subs"` 를 쓴다.
- `--write-auto-subs` 이지 `--write-subs` 가 아니다. 사람이 단 자막은 거의 없다.
- 실패해도 **예외를 올리지 않는다.** 자막은 보조 정보다.

## 2-B. 하다가 걸린 것 — 다음에 또 걸릴 것들

### Streamlit 은 `src/` 변경을 안 읽는다

`app.py` 를 고치면 자동으로 다시 뜨지만, **`src/` 밑 모듈을 고치면 옛 코드가
그대로 돈다.** 줄 접기를 넣었는데 화면에서 안 접혀 한참 헤맸다.
`src/` 를 고쳤으면 Streamlit 을 죽였다 다시 띄운다.

```bash
powershell -Command "Get-CimInstance Win32_Process -Filter \"Name='python.exe'\" | Where-Object { $_.CommandLine -like '*streamlit*' } | Stop-Process -Force"
```

### 429 는 「자막 없음」이 아니다

빠르게 여러 편을 받으면 유튜브가 막는다. 이때 yt-dlp 가 내는 말이
`Unable to download video subtitles for 'ja': HTTP Error 429` 라서
**「자막이 없다」로 읽기 쉽다.** 자막이 있는 영상을 없다고 적어 두면
그 소재를 영영 안 보게 된다. `subtitles._why()` 가 둘을 가른다.

### Channel Score 는 비어 있을 수 있다

롱폼이 적은 채널은 비교할 과거 영상이 모자라 `score_basis = "none"` 이 되고
`channel_score` 가 빈다. **「점수가 낮다」가 아니라 「모른다」다.**
30개 채널 중 2개가 그렇다. `nan` 을 그대로 내보내면 안 된다.

### 360배가 버그가 아닐 수 있다

`ねっと` 채널의 baseline 이 360.68 이 나와 예전 2,941배 버그인 줄 알았다.
확인해 보니 진짜였다 — 평소 522회짜리 채널이 188,291회를 냈다.
게다가 비교 대상이 **시간을 더 가진** 영상들이라 이 값은 과소평가다.
**큰 값이 나오면 의심하되, 확인하고 판단한다.**

## 5. 절대 어기면 안 되는 것

### ⛔ git 에 올리지 않는다

사용자가 명시적으로 지시했다. **로컬 저장소만.**
`git remote add` · `git push` 금지. `.env` 는 `.gitignore` 에.

### 🚨 이 프로그램의 실패는 조용하다

**가장 중요한 규칙이다.** 형식이 틀리면 에러가 아니라 「0개」로 나오고,
계산이 틀리면 **그럴듯한 숫자**가 나온다.

실제로 걸린 것들:

| 무엇 | 증상 | 왜 |
|---|---|---|
| 주제 성장률 | `+16,162%` | ADViews 로 다른 기간을 비교 |
| Channel Baseline | `2,941배` | 옛 영상의 ADViews 가 0 에 수렴 |
| 그래프 라벨 | `孤独` → `孤` | 한글+일본한자 동시 폰트가 없음 |
| `.cmd` 줄바꿈 | 스케줄러가 조용히 실패 | LF 로 저장 |
| `cd /d "%~dp0"` | 로그가 안 생김 | 끝의 `\` 가 따옴표를 이스케이프 |

**돌린 뒤 숫자를 눈으로 본다.** 「돌아갔다」는 확인이 아니다.
말이 안 되게 큰 값이 나오면 성공이 아니라 **버그의 신호다.**

### 할당량

`search.list` 는 **100 units**, `videos.list` 는 50개당 **1 unit** 이다.
하루 10,000 units → 실질 검색 상한 약 100회.
검색어 9개 × order 2종 = 18회 = 1,800 units.

**스냅샷은 싸다.** 334건이면 12 units. 매일 돌려도 된다.

### 보안

- 키는 `.env` 에만. 코드·URL·로그에 절대 안 적는다.
- 읽는 곳은 `config.api_key()` 하나.
- Streamlit 은 `--server.address 127.0.0.1` 로만 띄운다.

## 9. Phase 10 — ③ 검색어 관리 (만든 것)

### 어디에 있나

`src/seeds.py` · 화면은 `app.py` 의 `tab5` (🔎 검색어 관리)

검색어는 **코드가 아니라 데이터**다. `data/raw/seeds.json` 에 넣는다.
화면에서 `config.py` 를 고쳐 쓰면 쓰다 실패했을 때 프로그램이 아예 안 뜬다.
`config.SEEDS` 는 이제 **파일이 없을 때의 기본값**이다.
읽는 곳은 `seeds.terms()` · `seeds.labels()` 두 개뿐이다.

### ⚠️ 중앙 점수로 줄 세우면 안 된다

처음에 «성과가 낮은 것» 을 중앙 점수로 골랐다. 그랬더니 「住宅」 을
빼라고 나왔다 — **이상치가 8건으로 두 번째로 많은 검색어인데도.**

```
       이상치  영상수  중앙점수
AI       10건   47건   59.7
住宅       8건   39건   41.1   ← 중앙값 꼴찌, 이상치 2위
人生       7건   35건   52.6
老後       5건   28건   43.8
孤独       4건   41건   60.4   ← 중앙값 1위, 이상치는 보통
仕事       4건   47건   46.8
お金       2건   49건   53.1
SNS       0건   18건   51.5   ← 진짜 뺄 후보
```

우리가 찾는 것은 «구독자에 비해 유난히 잘 된 영상» 이지 «평균이 높은 주제»
가 아니다. 편차가 큰 주제가 오히려 사냥터로 좋다.
그래서 `performance()` 는 **이상치 수**로 줄 세우고, `weakest()` 는
«영상 15건 이상 모았는데 이상치 0건» 인 것만 뺄 후보로 짚는다.

### ⚠️ 낱말을 `translate_titles()` 로 옮기면 안 된다

`注文住宅` 의 뜻을 물었더니 **「나만의 맞춤형 주문주택 짓기 노하우」** 가
나왔다. 그 프롬프트는 «제목» 을 시키기 때문이다. 오류는 안 나는데
읽는 사람은 그걸 낱말 뜻으로 믿는다. 그래서 `translate_terms()` 를 따로 뒀다.

```
translate_titles()   제목 → 무슨 내용인지 알 수 있는 한 줄
translate_terms()    낱말 → 12자 이내의 뜻
```

### 후보는 옥석이 섞여 나온다 — 그게 맞다

```
注文住宅 주문주택   5편   ← 진짜 주제
家づくり 집짓기     4편   ← 진짜 주제
心理学  심리학      3편   ← 진짜 주제
ユング  융         3편   ← 사람 이름. 주제일 수도
残酷   잔혹/잔인    2편   ← 수식어. 넣으면 아무거나 걸린다
```

**프로그램은 후보만 내고 사람이 고른다.** 자동으로 넣으면 안 된다.
「무시」한 것은 `seeds.json` 의 `ignored` 에 남아 다시 안 나온다.

### ⚠️ 명세 두 개가 서로 어긋난다

```
prd F-4   검색어 상한 15개
prd §12   하루 할당량 20% 이내
```

검색어 1개 = 검색 2회 = 200 units 이므로

```
 8개  1,600 units  16%
10개  2,000 units  20%   ← 여기가 선
15개  3,000 units  30%   ← §12 위반
```

**둘 다 지킬 수는 없다.** 화면에 지금 몇 %인지 늘 띄우고, 20% 를 넘으면
경고한다. 어느 쪽을 따를지는 사용자가 정할 일이라 프로그램이 막지는 않는다.

### 지금 상태

시험 삼아 **`注文住宅`(주문주택) 를 넣어 두었다.** 검색어 9개 = 1,800 units = 18%.
필요 없으면 화면에서 [빼기] 한 번이면 된다.

## 10. 채널 영상수 (2026-09-02 추가)

### 왜 넣나

구독자만으로는 «작은 채널»을 못 가른다.

```
구독   4,190 · 영상    4편  ← 갓 시작한 채널이 바로 터짐
구독   2,850 · 영상   17편  ← 마찬가지
구독 512,000 · 영상  671편  ← 영상이 쌓여 큰 채널
```

같은 «구독 대비 100배» 라도 4편짜리 채널과 671편짜리 채널은 전혀 다른 일이다.

### 어디서 오나

`channels.list` 를 이미 `part=snippet,statistics,contentDetails` 로 부르고 있고
`videoCount` 는 `statistics` 안에 함께 온다. **저장만 안 하고 버리던 값이라
할당량이 한 톨도 더 들지 않는다.**

```
video_snapshots.csv  ← channel_video_count 열 추가
```

### ⚠️ 열을 늘릴 때 조심할 것

`csv.DictWriter` 는 **파일이 새로 만들어질 때만 헤더를 쓴다.** 그래서 필드만
늘리면 헤더는 옛 8칸 그대로인데 새 행은 9칸으로 붙어 **값이 한 칸씩 밀린다.**
에러가 나지 않는다 — `watch_status` 자리에 `hidden_subscriber_count` 가 들어앉는다.

`storage._migrate_header()` 가 붙이기 전에 헤더를 비교해 다르면 파일을 새
헤더로 다시 쓴다. 옛 행의 새 칸은 **빈 값**으로 둔다 — 0 으로 채우면
«영상 0개» 라는 거짓말이 된다.

앞으로 필드를 늘릴 때도 이 함수가 알아서 맞춘다.

### 값이 채워지는 시점

09-02 10:02 이전에 받은 1,051줄은 빈 칸이고, 그 뒤로 받는 것부터 채워진다.
`analysis.load()` 는 **최신 스냅샷**을 붙이므로 화면에는 바로 나온다.

뺄 후보로 짚는다(영상 15건 이상 · 이상치 0건 기준).

### ⚠️ 할당량 날짜는 한국 날짜가 아니다

YouTube 할당량은 **태평양시 자정** 에 리셋된다 — UTC 07:00 = **KST 16:00**.
한국 날짜로 세면 두 방향으로 어긋난다.

```
KST 00:00~16:00   우리는 «새 날» 인데 YouTube 는 아직 어제 → 조용히 초과
KST 16:00 이후     YouTube 는 리셋됐는데 우리는 «오늘» → 남았는데 막는다
```

`Client.quota_day()` 가 태평양시 날짜를 준다. 옛 기록은 한국 날짜로 적혀
있어 한 번 정정했다(`quota_log.bak_*` 에 원본).

**매일 07:00 KST 자동 수집은 «전날» 할당량 날짜에 들어간다** (= 15:00 PT).
즉 저녁에 손으로 돌린 수집과 다음날 아침 자동 수집이 **같은 하루치를 나눠 쓴다.**

### ⚠️ 번역 실패가 수집을 통째로 날렸다

검색 24회(2,400 units)를 다 쓰고 번역 단계에서 `TimeoutError` 가 나
**저장도 할당량 기록도 없이 죽었다.** `translate._ask()` 가
`HTTPError`·`URLError` 는 잡는데 읽기 타임아웃은 안 잡았다.

세 겹으로 막았다.

```
translate._ask()      OSError·Exception 까지 잡는다 — 번역은 절대 안 죽인다
collector.collect()   번역을 try 로 감싼다 — 실패해도 원문으로 저장
collector.main()      실패해도 쓴 할당량을 기록한다 — 안 적으면 다음이 초과
```
