1. 미션 소개
데이터를 수집하고, 정제하고, AI로 분석하고, 리포트로 내보내는 흐름, 이게 데이터 파이프라인입니다. 각 단계를 따로따로 해본 적은 있어도, 이걸 하나의 서비스로 연결하는 건 처음일 수 있습니다. 뉴스 자동 수집부터 AI 요약·분석, 인사이트 리포트 생성까지 CLI 기반으로 완성합니다.

Python은 데이터 수집, 처리, 분석에 가장 널리 사용되는 프로그래밍 언어이며, 최근에는 AI API와 결합하여 더욱 강력한 자동화 서비스를 구축할 수 있게 되었습니다.

이 미션에서는 뉴스 데이터를 자동 수집하고 AI로 요약·분석한 뒤 인사이트 리포트를 생성하는 CLI 기반 서비스를 구현합니다. 외부 API에서 데이터를 가져와 정제하고, AI가 핵심 내용을 추출하며, 이를 시각화와 리포트로 전달하는 데이터 파이프라인 전체 흐름을 경험합니다.

2. 최종 결과물
다음 기능이 정상 동작하는 CLI 기반 Python 애플리케이션 1개를 완성한다.

뉴스 수집 및 저장
외부 뉴스 API(또는 RSS)와 크롤링으로 뉴스 데이터를 수집하고, raw/clean 분리 저장이 동작한다.
중복 뉴스는 설정에 따라 skip 또는 upsert 처리된다.
AI 기반 뉴스 요약
저장된 뉴스 본문을 AI API에 전달하여 요약문을 생성하고 저장한다.
사용자가 CLI에서 요약 대상과 옵션을 지정할 수 있다.
AI 기반 인사이트 분석
일정 기간 또는 카테고리의 뉴스를 종합 분석하여 트렌드, 핵심 키워드, 주요 이슈를 도출한다.
분석 결과가 저장되고 조회 가능하다.
시각화 및 리포트 생성
카테고리별 뉴스 분포, 일자별 수집 추이 등을 차트로 시각화한다.
품질 지표와 TOP N 집계가 포함된 리포트를 생성한다.
결과를 CSV, 엑셀 파일로 내보낼 수 있다.

raw 데이터와 clean 데이터를 분리 저장해야 하는 이유와 각 단계의 역할을 설명할 수 있다.
AI API를 호출하여 텍스트를 요약하거나 분석하는 흐름을 설명할 수 있다.
수집된 데이터를 집계하고 matplotlib으로 시각화하는 과정을 설명할 수 있다.
4. 기능 요구 사항
다음 요구사항을 모두 만족해야 한다.

CLI 설계
argparse를 사용하여 서브커맨드 기반 CLI를 구현한다.
필수 서브커맨드: fetch, clean, summarize, analyze, report, export
각 서브커맨드는 필요한 옵션(예: --limit, --category, --date, --format)을 지원한다.
뉴스 수집
다음 두 가지 방법을 모두 구현하여 뉴스 데이터를 수집한다.
방법 1: 공개 뉴스 API 또는 RSS 피드 활용
방법 2: 뉴스 사이트 크롤링 (BeautifulSoup 또는 Selenium 활용)
HTTP 요청 시 타임아웃 설정과 오류 처리를 구현한다.
수집된 원본 데이터는 수집 시각, 소스 정보, 수집 방법과 함께 raw 저장소에 저장된다.
데이터 정제
정제 규칙: 필수 필드 검증, 텍스트 정규화, 날짜 형식 통일, 결측값 처리
중복 처리 정책(skip/upsert)을 적용한다.
정제된 데이터는 clean 저장소에 별도 저장된다.
AI 요약
AI API를 호출하여 뉴스 본문을 요약한다.
요약 대상 선택 옵션(--all, --id, --unsummarized)을 제공한다.
API 실패 시 로깅 후 스킵, 이미 요약된 뉴스는 기본 스킵 처리한다.
AI 인사이트 분석
조건별(기간, 카테고리) 뉴스를 종합하여 AI 분석을 요청한다.
분석 항목(2개 이상 필수): 주요 트렌드, 핵심 키워드, 공통점/차이점, 시사점
분석 결과는 별도 저장하여 리포트에 활용한다.
시각화
matplotlib으로 최소 2종 차트 생성: 카테고리별 뉴스 수, 일자별 수집 추이
한글 폰트 적용, PNG 파일로 저장한다.
리포트 생성
품질 지표 2개 이상, TOP N 집계 1개 이상, AI 인사이트 결과를 포함한다.
콘솔 출력 및 파일(TXT/MD) 저장을 지원한다.
데이터 내보내기
지원 포맷: CSV, JSONL, Excel 중 최소 2개
필터링 옵션(--status summarized)을 제공한다.
설정 및 로깅
설정 파일(config.json)로 API 키, 뉴스 소스 URL, 중복 정책 등을 관리한다.
logging 모듈로 INFO/WARNING/ERROR 레벨 로그를 기록한다.
데이터 저장
* 반드시 영구 저장소(SQLite 또는 JSONL 파일)를 사용한다.
* 메모리(List/Dict)만으로 데이터를 관리하면 안 된다.
코드 구조
* 모든 코드를 단일 파일에 작성하면 안 된다.
* 최소 4개 이상의 모듈로 분리한다.

7. 제약 사항
