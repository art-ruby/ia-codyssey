## 5. 모델별 평가

### ChatGPT 5.5 중간 — 86.5점

강점:

- “제공된 원문 기준”처럼 정보 범위를 지속적으로 표시해 가장 보수적으로 서술했다.
- 원문 핵심을 빠짐없이 반영하면서 소제목이 4개라 긴 글의 탐색성이 가장 좋다.
- HTML이 단순한 인라인 CSS라 블로그 플랫폼 이식성이 높다.
- 실제 이미지가 본문 흐름과 직접 연결되고 불필요한 텍스트 생성이 적다.

보완 필요:

- `[사실 확인 필요 항목]`이 누락됐다.
- HTML에 SEO meta description이 없다.
- `<title>`에 `차이 and 실전 활용법`이라는 혼합 오타가 남았다.
- Sora 프롬프트에서 `modern tech editorial mood` 정확 문구가 빠졌다.

판정:

> 현재 결과 중 게시 전 수정량이 가장 적고, 기사형 블로그로서 가장 안정적이다.

### Claude Sonnet 5 무료 시험 — 84.0점

강점:

- 공통 v6의 마크다운·HTML 분리 구조와 사실 확인 항목을 정상적으로 반영했다.
- GitHub 스타, 라이선스, 비용, 시스템 요구사항을 최신 확인 대상으로 분리했다.
- SEO meta description, 결론, 출처 안내, 이미지 3개와 인라인 CSS를 모두 갖췄다.
- Sora 필수 문구를 모두 포함했다.
- 기존 이미지 3개를 실패 사례 → 누적 메모리 → 구조 비교 순서로 자연스럽게 연결했다.

보완 필요:

- 썸네일의 “전멸”, SEO 설명의 “성공 사례”는 원문보다 강한 표현이다.
- 본문에서 메시징과 크론 기능을 비교적 확정적으로 서술해 공식 확인 표시가 더 필요하다.
- OpenClaw 비교가 원문의 주장임을 더 자주 밝혀야 한다.
- 기존 이미지 1에는 읽을 수 있는 영문 UI 텍스트가 있어 text-free 방향과 완전히 일치하지 않는다.

판정:

> 공통 v6 적용 후 이전 Claude v5의 사실성·형식 문제가 크게 개선됐다. ChatGPT와 점수 차이는 작으며, 사실 귀속 표현을 조금 보완하면 게시 가능한 수준이다.

### Gemini 3.1 Pro — 75.5점

강점:

- 세 모델 중 처음부터 사실 확인 필요 항목을 명시적으로 생성했다.
- SEO meta description, 결론, 출처 안내와 해시태그 구조가 완결적이다.
- Sora 필수 문구를 모두 포함했다.
- 비교 카드와 콘텐츠 흐름이 명확하다.

보완 필요:

- “참담한 실패”, “단숨에 해결”, “거대한 단일 뇌”, “패러다임을 바꿀 핵심”처럼 과장·홍보 표현이 많다.
- GitHub 스타가 `7.2k` 오기일 가능성이라는 추정은 입력 기사에 없는 새로운 해석이다.
- HTML이 `<style>` 블록과 외부 Google Fonts를 사용해 인라인 CSS 계약을 위반했다.
- 실제 이미지에 큰 영문 제목과 UI 텍스트가 생성됐다.
- 원본 응답 파일이 없어 파싱 전 결과를 추적하기 어렵다.

판정:

> 구조와 SEO는 강하지만 사실성 문체와 HTML 이식성에 수동 수정이 가장 많이 필요하다.

## 7. 최종 결론

### 최종 1위: ChatGPT 5.5 중간

가장 높은 점수를 받은 이유는 사실을 과장하지 않는 문체, 입력 기사 충실도, 풍부한 소제목 구조, 인라인 HTML 이식성이다. 사실 확인 섹션과 SEO meta를 보완하면 운영용 기준 결과로 사용하기 적합하다.

### 최종 2위: Claude Sonnet 5 무료 시험

공통 v6 적용 결과 이전 v5보다 사실성 관리와 HTML 계약 준수가 크게 개선됐다. ChatGPT와 2점 차이로 근접했으며, 표현 강도와 출처 귀속만 손보면 충분히 게시 가능하다.

### 최종 3위: Gemini 3.1 Pro

SEO와 사실 확인 구조는 우수하지만, 과장 표현과 입력에 없는 추론, 인라인 CSS 위반이 감점의 핵심이다. 생성 후 편집을 전제로 하면 활용할 수 있으나 자동 게시에는 추가 보정이 필요하다.

## 8. 최종 보완 과제

1. ChatGPT HTML title 오타와 SEO meta를 수정한다.
2. ChatGPT 마크다운에 사실 확인 필요 항목을 추가한다.
3. Claude 썸네일의 “전멸”과 SEO의 “성공 사례”를 중립적으로 완화한다.
4. Gemini HTML을 인라인 CSS로 변환한다.
5. Gemini의 과장 표현과 `7.2k` 오기 추정을 제거한다.
6. 세 모델의 사용 채널, 생성 시간과 주요 설정을 추가 기록한다.
7. 최종 운영 모델 선정 시 품질 외에 무료 제한, 생성 속도, 반복 안정성을 추가 측정한다.
