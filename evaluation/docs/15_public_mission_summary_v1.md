# IA Codyssey 공개용 미션

## 프로젝트 한 줄 소개

동일한 AI 뉴스 원문을 ChatGPT, Gemini, Claude에 입력해 콘텐츠 패키지를 생성하고, 결과를 근거 기반으로 비교해 가장 안정적인 프롬프트와 모델 운영 방식을 찾는 프로젝트다.

## 왜 이 미션을 진행하는가

같은 자료를 AI에 제공해도 질문 방식과 출력 규칙에 따라 결과의 정확성, 구성, 가독성, HTML 완성도가 크게 달라진다. 특히 한 모델에서 잘 작동한 프롬프트가 다른 모델에서는 HTML을 누락하거나 구조를 다르게 해석할 수 있다.

이 프로젝트는 단순히 “어느 AI가 더 좋다”를 정하는 데 목적이 없다. 동일한 업무를 여러 모델에서 반복 실행하고, 품질 차이가 모델 때문인지 프롬프트 때문인지 구분하며, 실제 게시 작업에 사용할 수 있는 재현 가능한 생성 과정을 완성하는 것이 목적이다.

## 나에게 맞춘 미션

### 업무 과업

AI 및 기술 관련 원문을 바탕으로 다음 요소가 포함된 한국어 블로그 콘텐츠 패키지를 만든다.

- 기사 핵심 주제
- 제목과 썸네일 문구
- 한 줄 요약과 SEO 설명
- 대표 이미지 프롬프트 3개와 alt 텍스트
- 12초 숏츠 콘셉트, 영상 프롬프트, 내레이션, 자막
- 모바일 가독성을 고려한 완결형 HTML 본문
- 출처와 추천 해시태그

### 현재 테스트 주제

Hermes Agent와 OpenClaw의 차이, 단일 에이전트의 지속적 메모리와 자동화 방식, 실제 활용 시나리오를 설명하는 블로그 글을 생성한다.

### 형식 기준

네이버 블로그 사례에서 관찰한 다음 요소를 적용한다.

- 넓은 본문 여백과 짧은 문단
- 핵심 단어 형광펜 강조
- 핵심·주의·목록·결론 박스의 역할 분리
- 설명 흐름과 연결되는 이미지 배치
- 결론, 출처, 해시태그 순서의 마무리

### 콘텐츠 기준

GPTERS의 Hermes Agent 글에서 다음 전개 방식을 참고한다.

- 도구를 한 문장으로 정의
- 실제 실패 사례로 문제 제시
- 해결 원리 설명
- 핵심 기능을 번호로 분해
- 유사 도구와 선택 기준 비교
- 개인·개발자·팀 활용법 제시
- 설치, 비용, 주의점, FAQ 정리

원문의 문장을 복제하지 않고 콘텐츠 전개 원리만 사용한다. 수치, 모델명, 설치 명령, 라이선스 등은 게시 전에 공식 출처로 다시 확인한다.

## 검증 대상

### 모델

- ChatGPT
- Gemini
- Claude

실행 시 실제 모델명, 사용 채널, 요금제, 날짜와 주요 설정을 함께 기록한다.

### 비교 실험

두 종류의 결과를 구분한다.

1. 공정 비교: 세 모델에 동일한 공통 프롬프트와 동일 입력을 제공한다.
2. 최적화 비교: 각 모델용으로 발전시킨 ChatGPT v3, Gemini v4, Claude v5 프롬프트를 사용한다.

공정 비교는 모델 자체의 지시 이행 차이를 확인하고, 최적화 비교는 실제 운영에서 얻을 수 있는 최고 품질을 확인한다.

## 평가 기준

| 평가 항목 | 확인 내용 |
|---|---|
| 사실성 | 입력에 없는 사실을 만들지 않는가 |
| 원문 충실도 | 핵심 변화와 한계를 정확히 반영하는가 |
| 콘텐츠 구조 | 사례, 기능, 비교, 활용, 결론이 자연스럽게 이어지는가 |
| 형식 준수 | 요구된 섹션과 출력 순서를 지키는가 |
| HTML 완성도 | 게시 가능한 완결된 HTML을 생성하는가 |
| 가독성 | 한국어 문장, 문단, 박스 구성이 읽기 쉬운가 |
| 멀티포맷 연계 | 본문, 이미지, 영상, 자막이 같은 메시지를 공유하는가 |
| 운영 편의성 | 결과 분리, 저장, 파싱과 재사용이 쉬운가 |

평가는 1~5점과 실제 결과 근거를 함께 남긴다. 느낌만으로 우열을 판단하지 않는다.

## 미션 수행 흐름

1. 원문과 출처를 고정 입력으로 정리한다.
2. 형식·콘텐츠 벤치마크를 확정한다.
3. 공통 프롬프트를 세 모델에 동일하게 실행한다.
4. 모델별 최적화 프롬프트도 별도로 실행한다.
5. 원본 응답, 마크다운, HTML을 모델별 디렉터리에 저장한다.
6. 필수 항목과 HTML 구조를 자동 점검한다.
7. 사실성, 가독성, 구조, 운영성을 수동 평가한다.
8. 세 모델 비교 보고서를 작성한다.
9. 가장 적합한 모델과 프롬프트를 선정한다.
10. 선정 결과로 반복 대화와 수정 테스트를 수행한다.

## 최종 결과물

- 세 모델의 원본 응답
- 모델별 마크다운 콘텐츠 패키지
- 모델별 게시용 HTML
- 공통 프롬프트 평가표
- 모델별 최적화 프롬프트 평가표
- 사실 오류와 형식 실패 기록
- 세 모델 비교·선정 보고서
- 최종 시스템 프롬프트 설계 문서
- 반복 수정 과정이 포함된 실행 로그

## 완료 기준

다음 조건을 모두 충족하면 미션을 완료한 것으로 본다.

- 동일 입력으로 세 모델의 결과를 확보했다.
- 모델별 결과가 서로 분리되어 저장되어 있다.
- 점수마다 확인 가능한 근거가 있다.
- 사실 확인이 필요한 문장이 표시되어 있다.
- HTML이 실제 게시 가능한 구조다.
- 프롬프트 개선 전후의 차이를 설명할 수 있다.
- 최종 선택 모델과 선택 이유가 명확하다.
- 다른 기사로도 같은 과정을 반복할 수 있다.

## 공개 시 표현 원칙

이 문서는 프로젝트 목적과 수행 방법만 공개한다. 외부 미션 원문의 문장, 세부 채점 문항, 내부 제출 지시를 그대로 게시하지 않는다. 대신 실제로 해결하려는 업무 문제, 실험 방식, 결과물과 검증 기준을 프로젝트 자체의 언어로 설명한다.
