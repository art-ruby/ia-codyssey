# 공통 프롬프트 통합 전략

## 결론

공통 프롬프트는 세 프롬프트 중 하나를 그대로 복사해 만들면 안 된다. 가장 적합한 방식은 다음 세 요소를 결합해 새로운 기준 프롬프트를 만드는 것이다.

- 구조 기반: Claude v5
- HTML 계약: Gemini v4
- 품질·안전 규칙: ChatGPT v3

이 결과는 기존 버전의 후속 모델별 프롬프트가 아니라 비교 실험용 `common v1`이어야 한다.

## 왜 단일 기존 버전을 선택하면 안 되는가

### ChatGPT v3만 사용할 경우

장점:

- 사실성, 문체, 영상, 가독성 규칙이 상세하다.
- 모델이 판단해야 할 상황을 비교적 구체적으로 제시한다.

문제:

- 최신 출력 구조와 차이가 있다.
- 대표 이미지와 HTML 결과의 연결 규격이 약하다.
- 다른 모델에서 긴 규칙을 일부 누락할 가능성이 있다.

### Gemini v4만 사용할 경우

장점:

- 완결형 HTML 문서 구조가 명확하다.
- 이미지 3개와 본문 위치가 직접 연결된다.
- 요구 결과가 비교적 간결하다.

문제:

- Gemini에서 HTML 완성을 안정화하기 위해 발전한 모델 특화 성격이 있다.
- 파싱 경계와 예외 입력 처리 규칙이 부족하다.
- v3의 상세 품질 제약이 일부 축소됐다.

### Claude v5만 사용할 경우

장점:

- 마크다운과 HTML의 시작·끝 구분자가 명확하다.
- 자동화 파이프라인에서 결과를 분리하기 쉽다.
- Claude Project 지침으로 사용하기 좋은 문서 구조다.

문제:

- v4를 바탕으로 작성되어 독립적인 공통 기준이라고 보기 어렵다.
- Claude 사용 안내와 시스템 프롬프트 본문이 한 파일에 섞여 있다.
- 모델 비교용으로는 Claude 전용 표현을 제거해야 한다.

## 공통 프롬프트에 채택할 요소

### Claude v5에서 채택

- `MARKDOWN_START/END`
- `HTML_START/END`
- 기사 정보가 부족할 때의 예외 처리
- 마크다운과 HTML의 명확한 분리
- 자동 파싱 가능한 출력 계약

### Gemini v4에서 채택

- `<!DOCTYPE html>`부터 끝나는 완결형 HTML
- 이미지 1·2·3의 본문 내 고정 위치
- 인라인 CSS 박스 구조
- HTML 하단 해시태그 박스
- 이미지 프롬프트 3개와 각각의 alt 텍스트

### ChatGPT v3에서 채택

- 기사 밖의 사실을 만들지 않는 상세 규칙
- 과장 표현과 클릭베이트 제한
- 사실 요약과 의미 해설의 구분
- 문단 길이와 모바일 가독성 규칙
- 이미지·영상·본문의 핵심 메시지 일치
- 불확실성 표시와 보수적 설명

## 공통 프롬프트에서 제거할 요소

- 특정 모델명이나 제품 UI를 전제로 한 사용 안내
- Claude Project에 붙여넣으라는 설명
- ChatGPT만 잘 이해하는 중복·장문 지시
- Gemini 실패를 우회하기 위한 모델 전용 보정 문구
- 샘플 콘텐츠에 종속된 회사명·주제·이미지
- 모델별 응답 스타일을 강제하는 표현

## 권장 프롬프트 구조

```text
1. 역할과 목표
2. 입력 계약
3. 사실성 및 불확실성 규칙
4. 콘텐츠 전개 규칙
5. 형식 벤치마크 적용 규칙
6. 멀티포맷 연계 규칙
7. 마크다운 출력 스키마
8. HTML 출력 스키마
9. 자체 검수 규칙
10. 출력 시작·끝 구분자
```

## 공정한 비교를 위한 중요 원칙

공통 프롬프트는 세 모델의 최대 성능을 만드는 프롬프트가 아니라 동일한 요구를 얼마나 정확히 수행하는지 측정하는 기준이다.

따라서 다음 두 결과를 섞지 않는다.

| 실험 | 프롬프트 | 측정 대상 |
|---|---|---|
| 공정 비교 | `common v1` | 모델의 지시 이행과 생성 품질 |
| 최적화 비교 | ChatGPT v3 / Gemini v4 / Claude v5 | 실제 운영 최고 품질 |

## 공통 프롬프트 자체 검수 단계

모델에 장문의 추론을 출력하게 요구하지 않는다. 대신 최종 출력 전에 내부적으로 다음 항목을 점검하도록 지시한다.

1. 기사 밖의 사실이 추가되었는가
2. 필수 마크다운 섹션이 모두 있는가
3. HTML이 완결되었는가
4. 이미지 위치가 3개 모두 있는가
5. HTML 내부에 마크다운 문법이 섞였는가
6. 해시태그가 10개 이상인가
7. 이미지·영상·본문 메시지가 일치하는가

자체 검수 과정은 출력하지 않고 수정된 최종 결과만 출력하게 한다.

## 권장 파일명

```text
prompts/comparison/prompt_ai_news_content_package_common_v1.md
```

공통 프롬프트가 검증된 이후에도 기존 모델별 프롬프트는 삭제하지 않는다. 기존 파일은 실패와 개선 과정을 증명하는 실험 자산이기 때문이다.

## 권장 다음 단계

1. 세 모델의 공통분모만 사용해 `common v1`을 작성한다.
2. Hermes Agent 입력 한 건으로 스모크 테스트한다.
3. 세 모델에서 HTML 누락과 구분자 실패를 확인한다.
4. 공통 프롬프트 자체 결함만 수정해 `common v2`를 만든다.
5. 모델별 결과 차이는 모델별 최적화 프롬프트에서 보정한다.
