# AI Tech News Blog Automation

뉴스기사 원문 또는 요약 1개를 기반으로 AI 테크 뉴스 블로그, 이미지 프롬프트,
Sora 숏츠 구성, HTML 및 SEO 결과물을 생성하는 자동화 프로젝트입니다.

## 평가 제출 안내

평가 시스템에서 이 저장소 `ia-codyssey`의 `main` 브랜치를 선택하면 된다.
필수 평가 자료는 저장소 루트에 배치되어 있어 별도로 `evaluation/` 폴더에
진입할 필요가 없다.

- 제출 목록: `SUBMISSION_MANIFEST.md`
- 평가 설명서: `evaluator_guide.html`
- 완료 보고서: `mission_completion_report.html`
- 최종 보고서: `reports/`
- 모델별 결과: `model_outputs/`
- 평가표: `scores/`
- 공통 입력: `test_inputs/`
- v1→v2 비교: `prompt_iterations/`
- Few-shot 예시: `few_shot/`
- 11턴 대화 로그: `logs/hermes_agent_chatgpt_conversation.md`
- 프롬프트와 설계 문서: `prompts/`, `docs/`

`evaluation/`은 위 자료를 하나의 독립 패키지로 보존하고 GitHub Pages에
배포하기 위한 미러 폴더다.

## 평가용 통합 제출 본문

아래 내용은 평가 시스템이 하위 파일을 열지 않더라도 과제의 전체 수행 내용과
근거를 직접 확인할 수 있도록 작성한 통합 제출 본문이다.

### 1. 선택한 업무 과업

**업무명:** AI 뉴스 기사 기반 게시용 콘텐츠 패키지 생성 및 LLM 비교 평가

**타겟 사용자:** 혼자서 리서치·마케팅·콘텐츠 발행을 수행하는 1인 창업자와
AI 콘텐츠 제작자

**업무 목적:** 기사 원문 한 건을 입력받아 사실과 해석을 구분하고, 한국어
블로그 게시에 필요한 기획·본문·HTML·이미지·영상·SEO 결과를 한 번에 생성한다.
동일 입력을 세 모델에 적용해 어떤 모델이 이 업무에 가장 적합한지도 평가한다.

**입력 규격:**

- 기사 제목과 본문
- 원문 URL과 출처명
- 작성일 또는 확인일
- 타겟 독자
- 확인된 사실과 확인이 필요한 주장
- 원하는 출력 형식

**출력 규격:**

1. 핵심 주제 한 문장
2. 제목 후보 3개와 최종 제목
3. 썸네일 문구 3개
4. 한 줄 요약과 SEO 설명
5. Sora 2 영상 프롬프트·내레이션·자막
6. 대표 이미지 프롬프트 3개와 alt 텍스트
7. 해시태그 10개 이상
8. 마크다운 콘텐츠 패키지
9. 게시 가능한 완결형 HTML
10. 사실 확인 필요 항목

### 3. 비교 모델과 평가 방법

동일한 Hermes Agent 기사와 Common v6 Final 프롬프트를 사용했다.

- ChatGPT 5.5 중간: ChatGPT Pro, 웹 사용
- Claude Sonnet 5: 무료 시험, 웹 사용
- Gemini 3.1 Pro: Gemini Pro, 웹 사용

각 평가 축은 1~5점으로 채점한 뒤 가중치를 적용했다.

| 평가 축 | 가중치 | ChatGPT | Claude | Gemini | 핵심 근거 |
|---|---:|---:|---:|---:|---|
| 사실 정확성·환각 억제 | 25% | 4.5 | 4.0 | 3.0 | ChatGPT는 변동 수치를 확인 필요로 분리, Claude 초기본은 스타·비용 확정 표현, Gemini는 추가 검증 필요 |
| 입력 기사 충실도 | 15% | 4.5 | 4.5 | 3.5 | ChatGPT·Claude는 기사 중심, Gemini는 일부 일반화가 큼 |
| 형식 준수 | 15% | 4.5 | 4.0 | 3.5 | ChatGPT가 필수 섹션과 구분자를 가장 안정적으로 유지 |
| 콘텐츠 구조 | 15% | 4.5 | 4.5 | 4.0 | ChatGPT·Claude의 도입→비교→활용→결론 흐름이 명확 |
| 한국어 가독성 | 10% | 4.0 | 4.5 | 4.0 | Claude 문장이 가장 자연스럽고 ChatGPT도 게시 가능 수준 |
| HTML 완성도 | 10% | 4.5 | 4.0 | 3.5 | ChatGPT는 인라인 CSS와 게시 구조 준수 |
| 이미지·영상 연계 | 5% | 4.0 | 4.0 | 3.5 | ChatGPT·Claude는 본문 흐름과 이미지 역할이 연결됨 |
| 운영·파싱 편의성 | 5% | 4.5 | 3.5 | 3.0 | ChatGPT 결과가 파일·구분자 표준에 가장 근접 |

| 순위 | 모델 | 점수 | 판정 |
|---:|---|---:|---|
| 1 | ChatGPT 5.5 중간 | 86.5 | 사실성·형식·구조의 균형이 가장 안정적 |
| 2 | Claude Sonnet 5 무료 시험 | 84.0 | 가독성이 우수하나 일부 확정 표현 보완 필요 |
| 3 | Gemini 3.1 Pro | 75.5 | 활용 가능하지만 사실 검증과 표준화 수정량이 큼 |

### 4. Few-shot 예시 3개

#### 예시 1: 충분한 입력

**입력:** 기사 본문, URL, 작성일, 공식 기능, 타겟 독자, 출력 형식이 모두 제공됨.

**처리:** 별도 질문 없이 사실 추출 → 구조 설계 → 마크다운 → HTML → 자체 검수.

**출력 예:** “기사 기준으로 확인된 기능”과 “공식 문서 재확인이 필요한 수치”를
분리한 완결형 콘텐츠 패키지를 생성한다.

#### 예시 2: 사실과 의견이 섞인 입력

**입력:** “이 도구는 업계 최고의 에이전트이며 어떤 서버에서도 5분 안에
설치된다”는 기사 문장이 포함됨.

**처리:** “업계 최고”는 평가·의견, “5분 설치”는 검증이 필요한 수치로 분류한다.

**출력 예:** “기사에서는 빠른 설치를 강조하지만 실제 설치 시간은 환경에 따라
달라질 수 있으므로 공식 문서 확인이 필요하다.”

#### 예시 3: 모호한 입력 → 되묻기

**사용자 입력:** “이 AI 도구로 블로그 글 써줘.”

**Assistant 되묻기:**

```text
정확한 글을 만들려면 다음 정보가 필요합니다.
1. 기사 원문 또는 URL은 무엇인가요?
2. 주요 독자는 누구인가요?
3. 게시 플랫폼은 네이버, 티스토리, 일반 웹 중 무엇인가요?
4. 반드시 포함하거나 제외할 사실·수치가 있나요?
```

**판정:** 원문과 출처 없이 제품 기능·수치를 추측하지 않고 생성을 보류한다.

### 5. 환각의 정의

이 과제에서 환각은 **공식 출처나 입력 기사로 뒷받침되지 않는 사실을 검증된
사실처럼 생성하는 오류**로 정의한다. 창의적 생성은 제목, 비유, 문장 구성,
이미지 연출처럼 사실 주장을 바꾸지 않는 표현 작업이다.

예를 들어 “차분한 파란색의 기술 일러스트”는 창의적 생성이지만, 출처 없이
“MIT 라이선스이며 5달러 서버에서 운영된다”고 단정하는 것은 사실 오류이므로
환각이다. 둘을 구분해야 창의성을 유지하면서도 발행 후 신뢰도 위험을 줄일 수 있다.

### 6. 환각 검증 기준과 결과

**Pass A:** 공식 저장소·공식 문서로 사실을 정확히 확인하고 출처와 함께 답함.

**Pass B:** 공식 확인이 불가능하거나 정보가 변동될 수 있음을 밝히고, 단정하지
않으며 “확인 필요”로 처리함.

**Fail:** 미확인 내용을 확정하거나, 잘못된 고유명사·명령·수치를 만들거나,
기사의 주장을 공식 사실처럼 표현함.

| 검증 질문 | 기대 판정 | 결과 | 이유 |
|---|---|---|---|
| 공식 라이선스는 무엇인가? | 공식 저장소 확인 | Pass B | 기사 표현만으로 단정하지 않고 최신 저장소 확인 필요 표시 |
| 현재 GitHub 스타 수는 얼마인가? | 실시간 확인 필요 | Pass B | 72,000개를 삭제하고 변동 정보로 처리 |
| 공식 지원 운영체제는 무엇인가? | 공식 문서 기준 | Pass A | Linux, macOS, WSL2, Android 지원 정보를 출처 범위에서 확인 |
| 설치 명령은 현재도 유효한가? | 공식 문서 재검증 | Pass B | 기사 명령을 그대로 보장하지 않고 최신 문서 확인 안내 |
| OpenClaw 마이그레이션 명령이 존재하는가? | 공식 CLI 문서 확인 | Pass B | 존재를 추측하지 않고 공식 확인 대상으로 분리 |
| `Gemma 4 26B`가 정확한 모델명인가? | 공식 모델 카드 확인 | Pass A | 공식 명칭 체계와 대조해 잘못된 명칭 가능성을 식별 |
| `$5 VPS` 운영 근거가 있는가? | 공식 비용 근거 필요 | Pass B | 환경·API 사용량에 따라 달라져 확정 비용을 삭제 |

### 7. 시스템 프롬프트·유저 프롬프트·입력 템플릿 분리

#### 시스템 프롬프트

역할과 변경되지 않는 정책을 정의한다.

```text
당신은 한국어 AI 뉴스 콘텐츠 편집자이자 사실 검증자다.
입력에 없는 기능과 수치를 만들지 않는다.
사실, 기사 주장, 해석을 구분한다.
변동 가능 정보는 공식 확인 필요로 표시한다.
필수 출력 구조와 HTML 계약을 지킨다.
```

#### 유저 프롬프트

현재 작업의 목적과 수정 요청을 전달한다.

```text
아래 Hermes Agent 기사를 1인 창업자와 AI 콘텐츠 제작자용 블로그로 작성해줘.
OpenClaw 비교는 기사 범위만 사용하고, 과장 표현과 출처 없는 수치는 제거해줘.
티스토리에 붙여넣을 수 있는 인라인 CSS HTML도 생성해줘.
```

#### 입력 템플릿

기사·출처·독자·검증 정보가 들어가는 데이터 영역이며, 앞서 제시한 `[기사 정보]`,
`[작성 조건]`, `[사실 검증]`, `[출력 요청]` 형식을 사용한다.

이 세 영역을 분리하면 정책은 재사용하고 기사 데이터와 작업 요청만 교체할 수 있다.

**실제 분리 파일:**

- SYSTEM PROMPT: `prompts/comparison/system_prompt_v6.md`
- USER PROMPT: `prompts/comparison/user_prompt_v6.md`
- INPUT TEMPLATE: `prompts/comparison/input_template_v6.md`

### 8. v1→v2 개선 과정

**v1 흐름:** 기사 입력 → 블로그 마크다운 생성 → HTML 생성

문제:

- GitHub 스타 72,000개, MIT 라이선스, `$5 VPS`를 확인 없이 확정
- 사실과 기사 주장 구분 없음
- `<style>` 및 외부 폰트 사용으로 플랫폼 이식성 저하
- 자체 검수와 자동 파싱 구조 부족

**v2 흐름:** 기사 입력 → 사실·주장 구분 → 불확실성 표시 → 구조 설계 →
마크다운·HTML 분리 생성 → 이미지·영상 연계 확인 → 10개 항목 자체 검수

| 개선 항목 | v1 | v2 |
|---|---|---|
| 변동 수치 | 현재 사실처럼 사용 | 최신 공식 확인 필요로 분리 |
| 라이선스·비용 | 확정 표현 | 기사 기준·확인 필요 표시 |
| 사실 확인 섹션 | 없음 | 있음 |
| HTML | style 블록·외부 폰트 | 인라인 CSS |
| SEO meta | 없음 | 있음 |
| 이미지 흐름 | 개별 프롬프트 | 도입→비교→결론 역할 연결 |
| 운영 편의성 | 파일명·구조 불일치 | 표준 결과 구조와 메타데이터 |

v2는 사실성 2.5→4.0, 형식 준수 3.0→4.5, HTML 완성도 3.5→4.5,
운영 편의성 2.5→4.0으로 개선되어 최종 방식으로 채택했다.

### 9. 11턴 대화와 조건 변경

| Turn | 사용자 변경 요청 | 결과 반영 |
|---:|---|---|
| 1 | 최초 기사 패키지 | 마크다운·HTML·이미지·영상·SEO 생성 |
| 2 | 핵심 주제 확인 | 지속 메모리 기반 단일 에이전트 관점 명확화 |
| 3 | 독자층 변경 | 일반 관심자 → 1인 창업자·AI 콘텐츠 제작자 |
| 4 | 제목 수정 | 검색형 제목으로 변경 |
| 5 | 과장 표현 제거 | 완벽·극적·무조건·최고 제거 |
| 6 | 비교표 보완 | 기사 범위 안에서 Hermes/OpenClaw 비교 |
| 7 | 출처 없는 수치 삭제 | 스타·설치 시간·비용 삭제 또는 확인 필요 |
| 8 | HTML 형식 변경 | 티스토리용 div·인라인 CSS 적용 |
| 9 | 이미지 위치 조정 | 도입부 뒤·비교 전·결론 앞 배치 |
| 10 | 최종 패키지 재생성 | 모든 누적 조건 통합 |
| 11 | 이전 조건 유지 확인 | 독자층·문체·수치·표·HTML·이미지 8항목 Pass |

중간 조건은 단순 요청 기록에 그치지 않고 최종 결과의 문장·표·HTML 구조에
반영했으며, 마지막 턴에서 조건별 유지 여부를 검증했다.

**11턴 실제 대화 기록 요약:**

```text
Turn 1
User: Hermes Agent 기사로 마크다운·HTML·이미지·영상·SEO 패키지를 만들어줘.
Assistant: 최초 콘텐츠 패키지와 “완벽 정리” 제목을 생성함.

Turn 2
User: 이 글의 핵심 주제를 한 문장으로 다시 확인해줘.
Assistant: 분리된 여러 에이전트보다 지속 메모리를 가진 단일 에이전트가
반복 업무 자동화에 효과적일 수 있다는 주제로 정리함.

Turn 3
User: 독자층을 1인 창업자와 AI 콘텐츠 제작자로 바꿔줘.
Assistant: 마케팅·리서치·콘텐츠·브리핑을 반복하는 독자로 전체 관점을 변경함.

Turn 4
User: 검색 유입에 유리하되 클릭베이트가 아닌 제목으로 바꿔줘.
Assistant: “Hermes Agent 완벽 정리: OpenClaw 비교와 1인 창업자 활용법”을 제안함.

Turn 5
User: 완벽·극적·무조건·최고 같은 표현을 제거해줘.
Assistant: 제목에서 “완벽”을 삭제하고 보수적·조건부 표현으로 본문을 수정함.

Turn 6
User: 기사에 없는 기능은 추가하지 말고 비교표를 명확히 해줘.
Assistant: 핵심 철학·메모리·강점·적합 상황·차이·주의점으로 표를 재구성함.

Turn 7
User: 스타 72,000개, 5분 설치, 10분 세팅, $5 VPS는 출처가 불확실하면
삭제하거나 확인 필요로 표시해줘.
Assistant: 수치를 삭제하고 라이선스·비용·설치 조건을 공식 확인 대상으로 분리함.

Turn 8
User: 티스토리에 붙여넣기 좋은 HTML로 바꾸고 인라인 CSS만 유지해줘.
Assistant: 문서 바깥 태그를 제거하고 루트 div와 인라인 CSS 구조로 변환함.

Turn 9
User: 이미지를 도입부 뒤, 비교 설명 앞, 결론 앞에 배치해줘.
Assistant: 이미지 1·2·3을 각 전환 지점으로 이동하고 역할을 명시함.

Turn 10
User: 지금까지 조건을 모두 반영해 최종 마크다운과 HTML을 생성해줘.
Assistant: 독자층·문체·수치·표·HTML·이미지 조건을 통합해 최종본을 생성함.

Turn 11
User: 이전 조건이 최종 결과에 모두 유지되는지 확인해줘.
Assistant: 독자층, 제목, 문체, 수치, 비교표, HTML, 이미지, 결론 표현
8개 항목을 확인하고 모두 Pass로 판정함.
```

### 10. 최종 모델 선정 이유

이 업무는 문장 표현력만 좋은 모델보다 다음 특성이 중요하다.

1. 기사에 없는 사실을 만들지 않는 통제력
2. 많은 필수 출력 항목을 빠뜨리지 않는 형식 준수
3. 마크다운과 HTML을 안정적으로 분리하는 능력
4. 여러 차례 수정 후에도 이전 조건을 유지하는 문맥 관리
5. 사람이 수정해야 하는 양을 줄이는 운영 편의성

ChatGPT 5.5 중간은 최고점 86.5점이며, 위 다섯 조건의 균형이 가장 좋았다.
Claude는 가독성이 더 높았지만 일부 사실 표현의 보수적 처리가 필요했고,
Gemini는 사실 검증과 파일 표준화에 추가 수정이 필요했다.

### 11. 심층 인터뷰 답변

#### 무료 모델만 사용해야 한다면

- 한 번에 전체 패키지를 만들지 않고 사실 추출→구조→본문→HTML로 호출을 분리한다.
- `expected_facts`를 입력에 포함해 무료 모델의 지식 부족을 보완한다.
- 출력 길이를 줄이고 단계별 JSON 또는 고정 템플릿을 사용한다.
- 각 단계 후 규칙 기반 검사를 실행하고 실패 부분만 재생성한다.
- 중요한 수치와 명령은 사람이 공식 출처를 확인한 뒤 입력한다.
- Few-shot 예시를 늘려 문체와 판정 기준을 모델 추론에 맡기지 않는다.

이 방식은 호출 횟수는 늘지만 작은 모델의 문맥 부담과 누락을 줄여 품질을 유지한다.

#### 정책·규정·수치가 자주 바뀐다면

- 프롬프트에 값을 직접 고정하지 않고 날짜가 포함된 외부 사실 파일로 관리한다.
- 공식 출처 URL, 확인일, 유효기간, 담당자를 각 사실과 함께 저장한다.
- 발행 전에 만료된 사실을 자동으로 `확인 필요` 상태로 바꾼다.
- 검색 결과보다 공식 저장소·공식 문서를 우선하는 출처 순위를 둔다.
- 이전 값과 최신 값을 비교하는 변경 로그를 유지한다.
- 공식 확인 실패 시 수치를 삭제하고 정성 표현으로 낮춘다.

즉, 모델의 기억이 아니라 최신화 가능한 사실 레이어를 기준으로 생성한다.

#### 10턴 이상에서 문맥이 끊긴다면

- 매 턴 전체 대화를 다시 전달하지 않고 `고정 조건`, `현재 초안`,
  `이번 변경`, `검증 체크리스트` 네 블록으로 상태를 압축한다.
- 변경 불가 조건에 ID를 부여한다. 예: `A1=독자층`, `F2=미확인 수치 금지`.
- 각 응답 마지막에 조건별 Pass/Fail 상태를 출력한다.
- 일정 턴마다 승인된 상태를 체크포인트 문서로 저장한다.
- 최종 생성 전에 최신 체크포인트와 변경 요청만 입력한다.

권장 프롬프트 구조:

```text
[고정 조건]
A1 독자: 1인 창업자·AI 콘텐츠 제작자
F1 기사에 없는 기능 추가 금지
F2 미확인 수치 단정 금지
H1 티스토리용 인라인 CSS

[현재 승인본 요약]
제목, 핵심 주제, 비교표, 이미지 위치

[이번 변경]
사용자의 최신 요청 한 가지

[출력 전 검증]
A1/F1/F2/H1을 Pass/Fail로 판정하고 Fail이면 수정 후 출력
```
